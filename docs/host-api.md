# Host API guide

This guide shows how a host application embeds the editor: it creates an editor, provides it to React, reads state through hooks, sends commands, runs queries, listens to events, registers extensions and composes the UI package. It owns the order and the how-to; the type declarations linked from each section are the source of truth for every name, field and union, and this guide copies none of them. Product behavior is in [`requirements.md`](requirements.md#sdk-model), package boundaries in [`ARCHITECTURE.md`](../ARCHITECTURE.md#dependency-direction), and the M8 public surface in the [M8 contract](plans/mvp-m8-host-api-ui-contract.md).

The packages a host uses:

| Package | Use | Entry |
| --- | --- | --- |
| `@vector-studio/editor-core` | The framework-free editor: documents, commands, queries, events, extensions. Re-exports every `model` and `contracts` type of its API (M8-T1). | [`src/index.ts`](../packages/editor-core/src/index.ts) |
| `@vector-studio/react` | The React bindings: provider, hooks and `EditorCanvas`. Re-exports every type of `editor-core` and the `extensionCommand` builder (M8-T2). | [`src/index.ts`](../packages/react/src/index.ts) |
| `@vector-studio/ui` | The minimal editor UI: toolbar rows, page list, layer tree, property panel and extension panels. Re-exports everything `react` exports (M8-T2). | [`src/index.ts`](../packages/ui/src/index.ts) |

A host that uses the UI package imports `@vector-studio/ui` alone for its React code; one that builds its own UI imports `@vector-studio/react`. Both entries are `'use client'` modules (M8-H5), so a Next.js Server Component may import them and render their components, but cannot call their functions on the server; server code that needs an editor-core value imports `@vector-studio/editor-core`.

## Creating an editor

`createEditor(options)` returns an `Editor`; see `EditorOptions` in [`editor.ts`](../packages/editor-core/src/editor.ts) and the `Editor` interface in [`types.ts`](../packages/editor-core/src/types.ts). The options give the initial document, the ID source, the extensions, extra key bindings, the platform (which resolves `Mod` in key bindings), the optional text layout port (for example `createTextDom` from `@vector-studio/text-dom`), the text tool style, `returnToSelect` (default false; when true the drawing tools switch to `select` after each shape, as next-host's studio layout does) and `adoptIntoFrames` (default false; when true a shape drawn inside a frame is created in it and a move dropped on a frame moves into it, or out of its frame onto the page) and `drawStrokeColor` (optional; the stroke colour of a line or path the line and path tools create, from the document, the active page and the first point; next-host's studio layout picks white or black to read on the backdrop; without it, or when it returns null, throws or returns a non-colour, the black default stays) and `projectEffects` (default false; when true the projected scene carries node effects, drop shadows and layer blur, which needs a renderer on `effects: 'v0'`; when `'v1'` it also carries inner shadows and background blur ([V-36](plans/viz-v36-inner-shadow-background-blur-contract.md)), which needs a renderer on `effects: 'v1'` as `@vector-studio/webgpu-host`'s `editorRendererOptions` gives; under `true` those two kinds are left out of the scene, so a host on `'v0'` keeps drawing the node. next-host uses `'v1'`. The `effectKinds` query lists the kinds a panel should offer for the option, and the property panel's Effects section offers those, except background blur, which it offers once the renderer draws it (V-36 U3); it edits effects either way, so a host that shows it should turn this on, or its effects stay in the document without drawing).

Create the editor on the client, outside render: next-host does it in a client effect together with its text-dom port and disposes the port in the effect's cleanup ([`m6a-text-host.ts`](../apps/next-host/src/m6a-text-host.ts)). The document lives in the editor; renderers and WASM handles are caches that can be rebuilt (requirements, SDK model).

## The provider and the canvas

Wrap the editor UI in `EditorProvider` with the editor; every hook and UI component reads the nearest provider ([`context.tsx`](../packages/react/src/context.tsx)). `EditorCanvas` draws the editor through a renderer the host creates in `createRenderer` and forwards pointer, keyboard, clipboard and text input to the editor ([`canvas.tsx`](../packages/react/src/canvas.tsx)). The host owns the renderer choice. The editor's WebGPU renderer is `createWebGpuRendererFactory({ wasm })` from `@vector-studio/webgpu-host` ([`src/index.ts`](../packages/webgpu-host/src/index.ts), [ADR 0004](decisions/0004-packaged-webgpu-host-composition.md)): `wasm` is the geometry kernel's URL, bytes or a loader. The kernel ships in `@vector-studio/geometry-wasm` as `dist/kernel.wasm`; `import { geometryKernelUrl } from '@vector-studio/geometry-wasm/kernel'` gives its URL through `new URL(..., import.meta.url)`, which Vite 8 and Next.js 16 (webpack and Turbopack) were checked to emit as an asset, so `createWebGpuRendererFactory({ wasm: geometryKernelUrl })` needs no server route. Import it in client code (next to the factory call): a `URL` cannot pass from a Server Component as a prop, and its server-side value differs from the client's. A host whose bundler does not follow that pattern copies `@vector-studio/geometry-wasm/kernel.wasm` to its public folder and passes that URL. Call the returned factory only on the client. If WebGPU is unavailable it throws `WebGpuUnavailableError`, whose message says what to do (for example open the page over https:// or from localhost, since a plain-http network address is not a secure context); the canvas reports it through `onRendererError`. next-host adds its test and bench hooks through the factory's stages ([`webgpu-renderer.ts`](../apps/next-host/src/webgpu-renderer.ts)).

Focus leaving the canvas ends text edit mode, except for focus moving to the property panel's text run fields, which edit the text edit selection. The canvas and those fields recognize each other through a `data-text-edit-focus` attribute: an internal marker between `react` and `ui`, not an API for host controls. It is page-wide, so a page holds one editor.

## Hooks

The hooks are in [`context.tsx`](../packages/react/src/context.tsx) and [`hooks.ts`](../packages/react/src/hooks.ts):

- `useEditor` returns the editor, and `useEditorCommands` its `execute`.
- `useEditorSelector(selector, isEqual?)` reads a part of the snapshot. The selector must be pure; with `isEqual` a fresh array or object keeps its previous reference while equal (M8-H2).
- `useSelection`, `useActivePage`, `usePages`, `useTool`, `useHistory`, `useSnapping`, `useViewport`, `useScope` and `useNode(id)` read one field of the snapshot each (M8-H1).
- `useEditorQuery(query, isEqual?)` re-reads a query after each editor event, for queries whose result changes without a new snapshot (for example `textEditOverlay` after a font loads) (M8-H3).

A hook's value is stable between unrelated changes, so a component re-renders only when its part changes.

## Commands and queries

Every edit is a command sent through `execute` (or `useEditorCommands`): the `Command` union, with `DocumentCommand` (one undo step each) and `SessionCommand` (selection, tool, viewport and other session state, never in history), is in [`types.ts`](../packages/editor-core/src/types.ts). The result is a `CommandResult`: `ok` with the IDs it created or touched, or a refusal with an `EditorErrorCode` and a path. A UI shows a refusal's code and leaves the document as it was.

`query` answers read-only questions: the `Query` union and `QueryResult` in the same file list them, from `document` and `node` to `handles`, `pathOverlay`, `textEditOverlay`, `snap`, `keymap` and `extensions`. A query never changes state or raises an event.

Fills and blend modes, V-35 ([contract](plans/viz-v35-fills-blend-contract.md)): schema v8 replaces a node's `fill` with `fills`, a list of `Fill`s (paint, visible, opacity, blend mode; bottom first, at most 16), and gives every node a `blendMode` (`passThrough` by default on groups, mask groups, frames, symbols and instances, `normal` on the other types). Host code that read `node.fill` reads `node.fills` instead. Create commands and `setStyle` still take `fill` (one fill at opacity 1, or none when null) and take `fills` to replace the list; both at once is refused. `addFill`, `setFill`, `removeFill` and `moveFill` edit one fill of each listed node, and `addFill` past 16 is refused with `editor.fill-limit`. Ungrouping a group whose mode is not `passThrough` succeeds and raises an `editor.ungroup-blend` diagnostic, since the mode is dropped. The `projectBlend` option (default false) carries the modes and the expanded fills into the projected scene, which needs a renderer on `blend: 'v0'` (the contract's U4; until it lands, leave the option off); SVG and PNG export always draw them.

Images, V-32 ([contract](plans/viz-v32-image-contract.md)): a v8 document may carry an `images` table (lowercase hex SHA-256 key to `ImageAsset`, base64 `data`), and a fill slot may hold an `ImagePaint` (`image` names a table entry, `scaleMode` `fill`, `fit`, `stretch` or `tile`, `scale` in `[0.01, 100]`); a stroke may not. `insertImages` adds one rectangle per `ImageAssetInput` (the host reads the size from the file header and hashes the bytes, so commands stay synchronous; `at` defaults to the viewport centre) and selects them; `setImageFill` sets the topmost fill of each fill-capable node to an image and `setImagePaint` changes the mode or scale; the failures are `editor.image-invalid` (bad asset, a key held with other data, a dangling image key), `editor.image-too-large` (the table over 256 MiB after the command) and `editor.image-no-target`. Every command checks that the image keys of the nodes it touched name table entries and then drops the entries nothing names, so undo brings them back. A clipboard fragment carries the entries its nodes name in an optional `images` key, which a paste merges. The `projectImages` option (default false) carries image fills into the projected scene as image paints, which needs a renderer on `paints: 'image'` with an image source; without it an image fill projects as no fill and the editor raises `editor.renderer-unsupported` once per attachment and page. An image fill's opacity is the opacity of its own scene leaf. SVG export always writes images; PNG export is the contract's U4.

### Export

V-30 ([contract](plans/viz-v30-export-contract.md)): the `exportScene` query returns what an export of the active page (no `ids`) or of some of its nodes (`ids`) draws, an `ExportScene` with page-space `bounds`, or null when nothing would draw; `exportSvg` returns the same export as SVG text. `exportPng(editor, { ids, scale })` from `@vector-studio/react` ([`export-image.ts`](../packages/react/src/export-image.ts)) paints it with Canvas 2D in the page, with the fonts the text layout port registered, and resolves a PNG `Blob` (null when nothing would draw or the image would be too large). Call it on the client. A node exports as itself: its ancestors' clips and opacity do not apply, and the background is transparent.

V-33 ([contract](plans/viz-v33-svg-import-contract.md)): `paste { text }` with SVG markup outside text edit mode imports it as editable nodes centred on `pointer`, else `at`, else the viewport centre (failures `editor.invalid-svg`, `editor.empty-svg`). `svgToFragment(text, options)` from `@vector-studio/editor-core` ([`svg-import.ts`](../packages/editor-core/src/svg-import.ts)) is the pure converter (SVG to clipboard fragment text, with the list of skipped features) and `isSvgText` its detection. `importSvgFiles(editor, files, { at })` from `@vector-studio/react` ([`import-svg.ts`](../packages/react/src/import-svg.ts)) imports SVG `File`s, one undo step each; `EditorCanvas` uses it for SVG files dropped on the canvas and reads `image/svg+xml` and SVG files on a paste.

V-39 ([contract](plans/viz-v39-styles-variables-contract.md)): the built-in `eyedropper` tool (default key `I`) applies the colour under a canvas click to the selection's fills (Shift: strokes; text: the run colour) in one undo step and returns to `select`; its overlay is `{ kind: 'eyedropper', point, color }`. The `sampleColor` query gives the colour under a page point (the document's paint, not the rendered pixel), and `pickedColor` (also `EditorSnapshot.pickedColor`, session event field `pickedColor`) the last pick. The studio toolbar copies a pick made with nothing selected as `#RRGGBB`, and a `ColorWell` offers the browser's screen eyedropper where `window.EyeDropper` exists.

V-39 ([contract](plans/viz-v39-styles-variables-contract.md)): a document may carry `colorStyles` (named paints) and `variables` (`modes`, the active `mode`, and `items`, each a colour or number with a value per mode), and a node may carry `bindings` naming a style or variable for `fill`, `stroke`, `text`, `opacity`, `strokeWidth` or `cornerRadius`. A bound property keeps its concrete value, so renderers and exporters need no change. The commands `createColorStyle`, `updateColorStyle`, `removeColorStyle`, `createVariable { name, kind, value }`, `updateVariable`, `removeVariable`, `addVariableMode`, `renameVariableMode`, `removeVariableMode`, `setVariableMode` and `bindProperty { ids, key, ref }` edit them, each one undo step; a change of a style, a value or the mode rewrites every bound node on every page, and any edit that changes a bound value drops that binding. Copy and paste carry bindings only into a document that has the same style or variable with the same value.

### Rulers, guides and layout grids

V-38 ([contract](plans/viz-v38-rulers-guides-grids-contract.md)): a page's `guides` (each `{ axis, value }` in page units) change with `setGuides { page, guides }`, one undo step; a frame's or symbol's `layoutGrids` (grid, columns or rows) change through `setNodeProps`. `layoutGridLines(width, height, grid)` from `@vector-studio/editor-core` gives a grid's lines and bands in the frame's own space, for a host that draws them. The session flags `rulersVisible` (default false) and `layoutGridsVisible` (default true) change with `setRulersVisible` and `setLayoutGridsVisible`, or the `toggleRulers` (Shift+R) and `toggleLayoutGrids` (Ctrl+Shift+4) actions. Moves, resizes and draws snap to the active page's guides always, and to the layout grid lines of frames the gesture meets while grids are shown. The editor draws none of them: next-host's studio draws the rulers, guides and grids over the canvas and drags guides from the rulers ([`v38-rulers.tsx`](../apps/next-host/src/v38-rulers.tsx)).
Auto layout, V-34 ([contract](plans/viz-v34-auto-layout-contract.md)): a frame's optional `autoLayout` (direction, gap, padding, main and cross alignment) and any node's optional `layoutSizing` (`fixed`, `hug` on an auto-layout frame, `fill` on its children, per axis) are stored fields; the document keeps each child's resolved frame, so the renderer and export read it like any other. `setLayout { ids, autoLayout?, layoutSizing? }` patches them (`autoLayout: null` removes it), `addAutoLayout { ids }` gives listed frames an inferred layout or wraps other nodes in a new hug frame, and `removeAutoLayout { ids }` removes it; each is one undo step. Every command that moves or resizes a node lays the affected frames out again in the same step. The keymap binds Shift+A to `addAutoLayout` and Shift+Alt+A to `removeAutoLayout`.

## Events

`subscribe(listener)` calls the listener after each change with an `EditorEvent` (document changes with their cause, session changes, diagnostics) and returns the function that unsubscribes; `getSnapshot()` returns the immutable snapshot the hooks read ([`types.ts`](../packages/editor-core/src/types.ts)). A host logs or reacts to events; it never mutates the document outside a command.

## Extensions

An `Extension` ([`types.ts`](../packages/editor-core/src/types.ts)) is registered with `createEditor` and contributes, each under its own ID:

- **Node types**: a `CustomNodeType` with its validator, defaults and scene projection; documents store it as a `custom` node.
- **Commands**: an `ExtensionCommand` run by `runCommand` with JSON arguments, through the `ExtensionApi` it receives (public commands and queries only). `extensionCommand<Args>(id)` builds a typed `runCommand` ([`extension-command.ts`](../packages/editor-core/src/extension-command.ts)); `run` still validates its arguments.
- **Tools**: an `ExtensionTool` that `setTool` activates by ID; the UI toolbar lists it after the built-in tools.
- **Bindings**: `KeyBinding`s layered over the default keymap.

The sample is `starExtension` ([`star.ts`](../packages/editor-core/src/star.ts)): the `ext.star` node type and the `ext.star.create` command, whose arguments are `StarCreateArgs`. The `extensions` query lists every registered extension's IDs (M8-X1).

### Panels

An extension's UI half is a `UiExtension` with `PanelContribution`s ([`panel-resolve.ts`](../packages/ui/src/panel-resolve.ts)). The host passes them to `PanelProvider`, which checks each panel against the `extensions` query (its owner registered, its ID the owner's ID or under it, no duplicate), and `EditorPanels` renders the accepted panels, each inside its own error boundary ([`panels.tsx`](../packages/ui/src/panels.tsx)). A panel component takes no props and uses the hooks only; `usePanelErrors` and `onPanelError` report rejected and failed panels. A panel's open or collapsed state is React state, never document or history.

next-host's sample is the `ext.star` panel ([`m8-star-panel.tsx`](../apps/next-host/src/m8-star-panel.tsx)), which imports `@vector-studio/ui` and `react` only.

## The UI package

`@vector-studio/ui` ([`index.ts`](../packages/ui/src/index.ts)) gives the components next-host composes ([`page.tsx`](../apps/next-host/app/page.tsx), [`m8-layout.tsx`](../apps/next-host/src/m8-layout.tsx)):

- `ToolbarPrimaryRow` (tools and edit actions) and `ToolbarSecondaryRow` (zoom and symbols), each a row that takes host controls as `children` ([`toolbar.tsx`](../packages/ui/src/toolbar.tsx)).
- `PageList` and `LayerTree` ([`layers.tsx`](../packages/ui/src/layers.tsx)).
- `PropertyPanel`, which holds `AppearancePanel` and `PropertySections` ([`property-panel.tsx`](../packages/ui/src/property-panel.tsx), [`appearance-panel.tsx`](../packages/ui/src/appearance-panel.tsx)). V-38: with one frame or symbol selected, `PropertySections` shows a Layout grid section (add a grid, columns or rows; per grid visibility, type, alignment, numbers, colour, opacity and remove).
- `PanelProvider`, `EditorPanels` and `usePanelErrors` (section above).
- V-30 ([contract](plans/viz-v30-export-contract.md)): `ExportPanel`, the Export section: format (PNG, SVG), PNG scale (0.5x to 4x) and a button that exports the selection, or the page with nothing selected, as a download ([`export-panel.tsx`](../packages/ui/src/export-panel.tsx)).
- V-39 ([contract](plans/viz-v39-styles-variables-contract.md)): `StylesPanel`, the Local styles section: colour styles and variables with modes; next-host's studio shows it when nothing is selected ([`styles-panel.tsx`](../packages/ui/src/styles-panel.tsx)). The appearance panel's fill, stroke, opacity, stroke width and corner radius rows and the property panel's text colour row gain a Style or variable menu.
- V-33 ([contract](plans/viz-v33-svg-import-contract.md)): `ImportPanel`, the Import section: an `Import SVG…` button whose chosen files import at the viewport centre, with status lines from `importMessages` ([`import-panel.tsx`](../packages/ui/src/import-panel.tsx)).
- V-25 ([plan](plans/viz-v25-editor-ui-plan.md)): `EditorToolbar`, one row of icon buttons with the same tools, actions, enable rules and test IDs as the two M8 rows, each named with its shortcut from the `keymap` query, and host controls as `children`; and `ZoomMenu`, a button showing the zoom that opens zoom in, out, fit, selection and 100% ([`editor-toolbar.tsx`](../packages/ui/src/editor-toolbar.tsx)). They carry `vs-*` class names and no colours, so the host styles them. `LayerTree` takes an optional `height` (default 240 px); with `'100%'` its parent needs a definite height. next-host's full-window studio layout composes them ([`v25-studio.tsx`](../apps/next-host/src/v25-studio.tsx)). V-40 ([contract](plans/viz-v40-pencil-polygon-contract.md)): the built-in tools include `pencil` (Shift+P) and `polygon`; `EditorToolbar` shows a Sides field (`polygon-sides`) while the polygon tool is active, which runs the session command `setPolygonSides` (the snapshot's `polygonSides`, 3 to 60).
- V-34: `PropertySections` adds an "Auto layout" section for selected frames (add, remove, direction, gap, padding, alignments, "mixed" where frames differ) and a "Resizing" section (Fixed, Hug, Fill; Fill disabled for groups, rotated nodes and zero-size paths); children of an auto-layout frame show no Constraints and read-only X and Y. Each edit is one `setLayout` over the selection ([`layout-model.ts`](../packages/ui/src/layout-model.ts)). The context menu gains Add or Remove auto layout.
- V-25 slice 10: `CanvasContextMenu`, the canvas's right click menu, and `selectForContextMenu`, which first gives the press the selection a left click there would unless it lands on the selection box ([`context-menu.tsx`](../packages/ui/src/context-menu.tsx)). With a selection the menu has copy, cut, paste here, duplicate, delete, the four arrange orders, group, ungroup, use as mask, hide or show, the symbol actions and zoom to selection; on empty canvas paste here, select all, zoom to fit and 100%. Every item runs a public command and shows its shortcut from the `keymap` query (copy, cut and paste, unbound by default, fall back to the browser's chords). The host opens it from the canvas's `contextmenu` event at a position in the menu's offset parent and refocuses the canvas on `onClose(true)`; it must not call `selectForContextMenu` while a primary press is held ([`v25-context-menu.tsx`](../apps/next-host/src/v25-context-menu.tsx)).

Each control sends one public command per committed edit and shows a refusal's code; the components hold no editor internals, so a host can replace any of them with its own built on the same hooks. The package imports `@vector-studio/react` and `react` only, which `pnpm check:boundaries` enforces (M8-B3).

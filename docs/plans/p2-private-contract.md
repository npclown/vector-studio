# P2 private geometry contract v1

Status: prospective implementation contract, 2026-09-26. Authorized entry is [D6](p1-follow-on-entry-proposal.md); acceptance and task state belong to the [P2 plan](p2-geometry-kernel.md). This is a prototype-private protocol, not a new editor-facing GeometryPort or durable document schema.

## Scope and ownership

P2 computes local Float64 bounds and flattened MOVE/LINE/CLOSE paths from canonical MOVE/LINE/CUBIC/CLOSE input. It does not produce the future Float32 mesh/index example in the graphics architecture. No fill tessellation, stroke expansion, hit testing, renderer integration, GPU ownership or P3 work is included. Fill-rule and stroke-style identity are cache inputs only.

`geometry-wasm` owns Rust code, its private TypeScript adapter and reconstructible caches. `geometry-reference` is test-only and independently implements validation and numerical checking. Neither imports the other. Both may depend inward on existing contracts, but P2 needs no new public contract exports. The test/benchmark composition root joins their plain numeric data. Extend the boundary checker and compilation coverage when each package is introduced. No third-party crate, runtime dependency or code generator is needed by this contract.

## Canonical requests

Verbs are unsigned bytes: MOVE=0, LINE=1, CUBIC=2, CLOSE=3. MOVE and LINE consume two Float64 scalars; CUBIC consumes six; CLOSE consumes none. Points are interleaved x/y. `pathOffsets` indexes verbs and `pointOffsets` indexes scalar elements, not bytes. Both arrays have pathCount+1 entries, start at zero, are nondecreasing, and terminate exactly at their buffer lengths. Zero paths and empty paths are valid.

A nonempty subpath starts with MOVE. LINE/CUBIC require an open subpath. CLOSE returns to its MOVE point and closes it; subsequent drawing requires another MOVE. Consecutive MOVE and MOVE-only subpaths are valid. Repeated CLOSE is invalid. All consumed coordinates must be finite. Bounds include MOVE points, segment endpoints, interior cubic extrema and closing lines. An empty path has explicit EMPTY status and four zero bound values, not infinite sentinel bounds. An isolated MOVE has point bounds. Degenerate lines/cubics are retained deterministically; do not deduplicate their endpoints.

Each request carries an opaque u32 requestId and ordered u32 sourceEpoch/sourceRevision. The adapter retains domain/node identity outside WASM. Integers, additions, products, offsets and capacities are checked before conversion to wasm32; overflow never wraps. The result echoes all three tokens, including failures. Stale tokens cannot publish over newer work.

Malformed envelope/offsets reject the whole batch. Within a valid envelope, invalid path state, nonfinite coordinates, invalid tolerance and numerical/work-limit failures affect only that path. A failed path publishes no partial vertices, provenance or bounds. Later valid paths still execute. Error ordering within a path is input/state validation, tolerance validation, then computation. Never replace failure with coarse geometry.

## Screen error and tolerance

The architecture's 0.25-screen-pixel geometric target means **physical display pixels**. For world linear matrix W, camera zoom z and DPR d, let S = d*z*W (CSS camera translation does not enter S). z and d must be finite and positive. W must have finite coefficients. Compute its largest singular value with scaling to avoid squaring large coefficients. Nonfinite products or an unrepresentable positive tolerance return NUMERIC_RANGE.

For sigmaMax(S)>0, required local tolerance is `0.25 / sigmaMax(S)`. Quantize downward to the largest exactly representable power of two not exceeding that value; validate the comparison rather than trusting rounded log2 at a bucket boundary. No silent minimum clamp. The kernel receives that positive finite bucket tolerance. A zero linear matrix maps every point to one screen point; the adapter still validates canonical input and returns its bounds/identity, but may use a fixed local tolerance of 1 for flattening. This deliberately still performs ordinary local flattening for cache portability and may return NUMERIC_RANGE/WORK_LIMIT even though screen error is zero; test that behavior. This does not authorize renderer culling or change singular-transform interaction behavior. Rank-one matrices with nonzero norm use the ordinary rule.

Cache reuse requires the same bucket; translation or rotation preserving it does not rebuild geometry. A scale, shear, zoom or DPR change crossing a bucket recomputes only affected paths. Bounds are local. Error verification multiplies differences by S, excluding translation to avoid cancellation at huge screen origins.

## Cubic bounds and flattening

Rust computes bounds from endpoints and all real derivative roots strictly inside (0,1), separately for x and y; it does not derive bounds from the flattened polyline. Scale coefficients before solving, treat the derivative as linear only when its quadratic coefficient is exactly zero, use the stable quadratic q formulation and evaluate candidates with de Casteljau. Normalize power coefficients a,b,c by their maximum absolute value before computing D=b*b-4*a*c. Define discriminant uncertainty delta=64*epsilon*(b*b+abs(4*a*c)+1). D < -delta has no real root; D > delta uses the stable solver. In the uncertain band, set v=-b/(2*a), r=sqrt(abs(D)+delta)/(2*abs(a)). If [v-r,v+r] intersects [0,1], evaluate v clamped to [0,1] and bound coordinate uncertainty by r*scale*(abs(a)*r*r + (abs(D)+delta)/(4*abs(a))), where scale restores derivative coefficient units. Accept this candidate only if that bound is at most the coordinate guard below; otherwise return NUMERIC_RANGE. An exact zero derivative has no interior candidates. Any nonfinite intermediate or unresolvable uncertainty returns NUMERIC_RANGE. Expand computed extrema outward by the declared guard below.

Flatten with half splits, left child first. For cubic controls P0..P3 and endpoint chord L, set q1=P1-L(1/3), q2=P2-L(2/3). Emit the endpoint when `max(norm(q1),norm(q2)) + guard <= bucketTolerance`. This is a sufficient continuous bound because the difference curve has Bernstein controls 0,q1,q2,0. Endpoint distance to an infinite line alone is insufficient for loops, retracing or cusps. Midpoints use overflow-safe arithmetic; all operations remain Float64.

Compute subdivision and derivative arithmetic relative to the original P0, adding P0 back only when emitting local output/evaluating bounds. Use epsilon=2^-52 and `guard = 128*epsilon*(max(1,maxAbsOriginalControls) + (depth+1)*maxAbsRelativeControls)` in local units. The origin subtraction/output addition budget occurs once; repeated splits depend on relative control magnitudes, not repeated rounding of a large origin. The factor budgets rounding in splits, chord evaluation and norm computation; it is deliberately conservative and is part of the declared numerical policy, not an assertion of formal interval arithmetic. For bounds use depth=0. If guard is nonfinite or consumes the requested tolerance, return NUMERIC_RANGE. Do not loosen the guard based on a failing fixture. Independent verification below remains required.

Limits are maximum split depth 20, maximum emitted lines per cubic 4096, maximum visited subdivision nodes per path 1,048,576, maximum output verbs per path 65,536, counting copied MOVE/LINE/CLOSE and all emitted cubic LINEs. Test the inclusive limit and the first exceeding operation. Return WORK_LIMIT before exceeding any limit, rolling back output for that path while retaining actual attempted-work diagnostics. CLOSE is emitted as CLOSE with no point scalars; MOVE/LINE retain their input values. Each successful cubic emits one or more LINEs, including a fully degenerate cubic.

Each output verb carries three u32 provenance values: source verb ordinal relative to its path, dyadic interval end numerator, depth. A cubic line ending at t=n/2^depth covers the interval from the preceding output line's t (initially zero) to t. Reset the starting t to zero for each new source CUBIC ordinal, regardless of preceding cubic/non-cubic output. Its first interval starts at zero and its last ends at one; adjacent intervals must cover [0,1] strictly without gaps or overlaps. A leaf interval has width 1/2^depth. Non-cubic verbs use numerator=1, depth=0. Keep provenance in both correctness and performance builds; it is private derived data, not a document feature.

## ABI v1 and memory lifetime

One single-threaded WASM instance owns one arena. No imported browser objects, shared memory, callbacks or reentrant calls. Little-endian scalar fields; byte offsets are relative to the start of the relevant input/output block, except exported pointers which are absolute linear-memory byte offsets. Sections are nonoverlapping, in the listed order, padded with zero bytes to each required alignment. Reject unknown versions, nonzero reserved fields, surplus sections and total-length mismatches.

Input header is twelve u32 fields (48 bytes): magic `0x32534756`, version=1, totalBytes, pathCount, verbCount, pointScalarCount, requestsOffset, pathOffsetsOffset, pointOffsetsOffset, verbsOffset, pointsOffset, reserved=0. Arrays follow the canonical rules above. Requests are 24-byte, 8-aligned records: requestId/sourceEpoch/sourceRevision/reserved=0 (four u32), then Float64 bucketTolerance. Points are 8-aligned; u32 sections 4-aligned. Even an empty batch includes the terminal offsets.

Output header is twelve u32 fields (48 bytes): magic `0x32524756`, version=1, totalBytes, pathCount, verbCount, pointScalarCount, resultsOffset, verbsOffset, pointsOffset, provenanceOffset, reserved=0, reserved=0. Results are 64-byte, 8-aligned records: requestId/sourceEpoch/sourceRevision/status/verbStart/verbEnd/pointStart/pointEnd (eight u32), then minX/minY/maxX/maxY (four f64). Starts/ends use element units. Provenance has three u32 per output verb. Success ranges are contiguous and ordered; failed and empty paths have equal starts/ends and zero bounds. Output has only MOVE/LINE/CLOSE, no CUBIC.

Per-path statuses: OK=0, EMPTY=1, INVALID_PATH=2, INVALID_TOLERANCE=3, NUMERIC_RANGE=4, WORK_LIMIT=5. Batch statuses: OK=0, INVALID_BATCH=1, OUTPUT_CAPACITY=2, ALLOCATION_FAILED=3, DISPOSED=4, RESOURCE_LIMIT=5, INTERNAL_ERROR=6. These namespaces are distinct. Failure is structured, not a WASM trap used as ordinary control flow.

The prototype arena caps input at 64 MiB and output at 256 MiB, including headers/padding; reserve requests exceeding either return RESOURCE_LIMIT before allocation. Validate all scalar lengths against these capacities before allocating scratch. These are bounded per-call safeguards, not supported-document limits or evidence for P1's combined-memory gate. Actual allocation failure below the caps returns ALLOCATION_FAILED. Any computed output total exceeding its cap or u32 range returns RESOURCE_LIMIT with required_output_bytes=0. The adapter reports this bounded batch failure; callers may partition at path boundaries without changing path/token order. Automatic chunking is not required by P2 and no partial batch is silently accepted.

Exports are `memory`, `abi_version()`, `reserve(inputBytes, outputBytes)`, `input_ptr()`, `input_capacity()`, `output_ptr()`, `output_capacity()`, `memory_epoch()`, `process(inputLength)`, `result_len()`, `required_output_bytes()`, `dispose()`. All exported function parameters and return values are u32; reserve/process return batch status. reserve grows but never shrinks capacities and reserves processing scratch too. `process` performs no memory growth: a sizing pass precedes output publication. If output capacity is inadequate it sets exact required_output_bytes and result_len=0, returning OUTPUT_CAPACITY; the adapter may reserve once to that size and retry identical input. Keep input copied across a reserve that can relocate allocations. The sizing pass counts deterministic output, followed by an emission pass with the same decisions. No result_len/header is published until emission fully succeeds. A sizing/emission mismatch returns INTERNAL_ERROR with result_len=0. Allocation failure leaves no published result. Zero result_len means no readable output.

Every reserve/process/dispose call invalidates previous borrowed views, even without physical memory growth. memory_epoch increments on every such call; before u32 wrap fail closed and require a new instance. The adapter re-reads memory.buffer and pointers after every call, detects unexpected buffer identity changes, and never retains borrowed output across a call. Caller-retained and cache results are owned copies. dispose is idempotent and terminal, releases arena allocations and invalidates all results; WASM linear memory itself is released only when the host drops the instance. Recreate a new instance for later work. All initialization/partial-failure paths release host references.

For the already required work observations, `statistics_ptr()` exposes a fixed 48-byte, 8-aligned borrowed block: six little-endian u64 counters for logical source cubics, sizing subdivision visits, emission subdivision visits, emitted cubic lines, attempted paths and failed paths. Reset at the start of process; preserve actual work on failure, with invalid-envelope calls reporting zeros. These counters exclude reserve and are copied before any next mutating call. Logical inputs count once during sizing; a failed sizing pass has no emission visits. Host aggregation sums every process invocation, including retries, without relabeling them as unique inputs. u64 is decoded as BigInt then range-checked before JSON number conversion. This private instrumentation adds no public statistics contract.

## Cache contract

The adapter cache is per instance/session, reconstructed from canonical caller input. Key fields are domainId, nodeId, sourceEpoch, sourceRevision, strokeStyleHash, fillRule and toleranceBucket. Domain/node/style identities are opaque strings; fillRule is nonzero/evenodd. No P2 stroke or fill algorithm depends on those tags. Color/opacity are absent. A changed revision invalidates only that node's older entries. A stale completed request cannot replace the latest requested revision. Compare sourceEpoch/sourceRevision lexicographically, without modular wrap. A lower pair than the resident node revision rejects as STALE_SOURCE; a higher pair replaces that node's older variants. An epoch change invalidates all variants of that node, not other nodes. Before either u32 wraps, require a new session/domain. Equal pairs are replayable only for identical geometry. A resident node identity registry independent of tolerance/style/fill keys compares canonical verbs and Float64 coordinate bytes (excluding requestId/tolerance/style/fill); a different geometry rejects as REVISION_CONFLICT. Retain those input copies and account for them.

Calls are synchronous in P2; no deferred result may publish after a later call or disposal. Use bounded node-LRU: evict all variants and the revision/input registry of the least recently used node together. Revision/conflict checks apply while that node is resident; after eviction it is a fresh cache miss, with caller source tokens still echoed for external stale-result checks. Never claim a durable revision ledger. At most 10,000 variant entries and 10,000 resident node identities and 16 MiB of owned typed-array payload (retained input, output and provenance counted separately; shared owned storage counted once). Oversized results may return without caching. Track hits, misses, kernel path builds, evictions, retained payload bytes and live linear-memory byteLength. Failure results are not cached. Eviction drops host-owned arrays; never free another instance's memory. dispose clears cache and rejects subsequent operations. These explicit payload counters exclude JS object/string/allocator overhead and do not prove P1 A09 combined memory.

A higher source pair advances the resident registry and purges old variants before kernel execution, including when that execution fails. An oversized result does not remove an otherwise fitting registry or same-revision variants. If canonical input alone cannot fit, treat the node as immediately nonresident (whole-node eviction semantics); do not keep an unaccounted revision ledger. Test failed-new-revision followed by an older request and oversized-result admission separately.

## Independent reference and numerical acceptance

The test-only TypeScript reference uses direct Bernstein evaluation and derivative-root bracketing/bisection, not Rust's quadratic solver or subdivision implementation. For each coordinate, independently evaluate the quadratic derivative in Bernstein form; partition [0,1] at its vertex when interior and bracket each monotone interval. Include a vertex candidate for a zero-touch/double root, which sign-change-only bisection would miss. Use up to 64 bisections and stop at interval width <=2^-48; retain both bracket endpoints as candidates. Nonconvergence/nonfinite evaluations fail verification. Share only declarative verb/status values and fixture data through test composition; no production helper imports or copied flattening algorithm. Compare bounds and geometric error, never exact vertex counts or identical subdivision choices.

For bounds compare each component to the independent extremum with tolerance `1e-9 + 256*epsilon*max(1,maxAbsControls)`. Assert containment within that numerical allowance and tightness within twice it. Include explicit analytic extrema fixtures and affine/translation metamorphic tests. Uncertain oracle convergence is a verification failure, not automatic agreement.

For flattening, check output structure/provenance and evaluate endpoints independently. Each returned knot must match canonical B(t) within the declared local numerical guard, including for rank-one or zero screen matrices; a hidden screen-space displacement cannot be accepted as correct reusable local geometry. For each emitted cubic line's dyadic source interval, verify continuous physical error: E(t)=S*(B(t)-returnedLine(t)). On any verification subinterval of width h, a conservative bound is `max(norm(E(left)),norm(E(right))) + M*h*h/8`, where M bounds norm(S*B''(t)) from the two endpoints (B'' is affine). Add the physical form of the declared numerical guard. Bisect verification intervals independently until the upper bound is <=0.25; an evaluated error >0.25 fails immediately. Cap verification at depth 24 and 1,048,576 cells per cubic; unresolved verification fails. This is a mathematical interpolation bound evaluated with a conservative Float64 guard, not a formal IEEE interval proof. Dense samples alone cannot pass acceptance.

Positive controls deliberately perturb an endpoint, remove/duplicate an interval, corrupt provenance and understate bounds; the oracle must reject each. Degenerate, line-equivalent, cusp, retracing, closed-loop and inflection cases are mandatory. Subdivision, reversal, translation and uniform-scale metamorphic fixtures supplement seeded differential inputs.

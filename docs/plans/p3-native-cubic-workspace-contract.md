# P3.2h private native cubic-fill workspace

Status: FROZEN after Primary/independent contract review, 2026-10-02. This slice follows [P3.2g](p3-native-cubic-topology-contract.md) and moves its tested composition into a crate-private Rust workspace. The [active plan](p3-fill-stroke-meshes.md) owns execution; the [private mesh contract](p3-private-contract.md) retains full C03-C05. No public API, WASM operation/export, mesh ABI, dependency, P2 behavior, renderer or product rejection policy is introduced. User-deferred stroke refinement stays deferred.

The two temporary returning/open and nonreturning/CLOSE restrictions below are superseded by the separately frozen [P3.2i closure contract](p3-cubic-closure-contract.md). The remaining LINE-only restriction is superseded by the [P3.2j mixed-source contract](p3-canonical-mixed-contract.md), which preserves all numeric caps while counting LINE/CUBIC together as source segments. All other ownership and precedence remain in force; historical P3.2h evidence is unchanged.

## Ownership and input

The separately frozen [P3.2k LINE identity contract](p3-line-identity-contract.md) composes all-LINE contours with at least three normalized edges directly into rounded topology after exact source/provenance validation. Mixed/curved and shorter contours keep the original certificate route; skipped-helper diagnostics retain their meaning. Numeric caps and all remaining preparation restrictions are unchanged.

Add `cubic_fill.rs` inside the existing Rust kernel. Reuse `codec::PathInput`, its bit-preserving `point()` accessor and `geometry::run_path`; do not duplicate or alter P2 validation/flattening. Accept the existing private fill-rule enum and a separate local rounded-topology tolerance. The PathInput request's tolerance is the flattening tolerance. No hidden zoom/DPR multiplier, screen-budget derivation or operation identity is selected here.

The workspace must derive source controls from the actual packed canonical input, not a test fixture's duplicate contour model. A CUBIC stores only p1/p2/p3: its p0 is the exact-bit current point from MOVE or the preceding cubic endpoint. Source ordinal is its global verb index, including MOVE/CLOSE. Copy source controls into fixed workspace storage; retain no input borrow after a call. Do not import any cfg(test) type into runtime code.

This restricted workspace supports one to four nonempty contours of `MOVE CUBIC+ [CLOSE]`, at most 16 total cubics. For this migration checkpoint, an explicit CLOSE is supported only when its last cubic endpoint equals its MOVE point mathematically; a contour without CLOSE is supported only when those points differ, using the existing implicit closing edge. LINE, empty/MOVE-only contours, consecutive MOVE with no intervening cubic, nonreturning explicit CLOSE and returning open contours are `UnsupportedSource`. These private preparation limits are not final product support rules. Full canonical LINE and general closure/degenerate support remain later work; no public caller can reach this helper.

## Bounded processing and error precedence

Every attempt first clears publication, all logical source/output lengths and operation diagnostics, including attempts rejected by cheap caps. Cheap input caps are 24 verbs and 104 Float64 scalars, inclusive, checked before sizing. Exceeding either is `SourceLimit` with zero operation statistics, output None and no run_path or dependency invocation. These bounds follow 16 cubics*6 scalars plus four MOVE*2 scalars, and 16 cubics plus four MOVE plus four CLOSE. Therefore P2's error precedence is inherited only inside this private bounded envelope; P2 itself is unchanged. PathInput values come from the existing validated envelope or its cfg(test) constructor, not a new byte decoder.

Within the caps:

1. Clear publication, all source/output lengths and attempt statistics. Call existing `run_path` sizing with the supplied request. Preserve every non-OK sizing status and plan/bounds diagnostics exactly as the existing bridge does, return without emission or dependent topology/rounded work, and publish no mesh. Malformed source precedes invalid flatten tolerance, which precedes empty input through existing P2 validation.
2. Decode the restricted source grammar using checked scalar offsets and fixed arrays in one left-to-right traversal. Fail `UnsupportedSource` for a valid but unsupported form; report `SourceLimit` for more than four contours/16 cubics. The first encountered restricted error wins. A MOVE first finalizes any preceding open contour, then checks the new contour count; a CUBIC checks the next cubic count before appending it. CLOSE/end finalize the current contour. Thus an earlier LINE wins over a later fifth MOVE, while a fifth MOVE after four supported contours wins over a later LINE. Do not turn a successful sizing result into a product success if source decoding fails.
3. Emit into the same 72-command fixed array and check the existing plan/bounds identity. Effective command capacity is exactly min(requested,72), preserving the bridge rule; smaller capacities may exercise `CommandLimit` and larger requests are clamped. Retain original statuses on upstream failures and distinguish internal command/provenance/ownership failures.
4. Collect contours and owners, validate complete per-cubic provenance partitions and run the existing native topology certificate on actual emitted knots and decoded original controls. Require the owned polygon/ranges to match the collected rounded inputs geometrically.
5. Only after certificate success call rounded fill with the separately supplied tolerance, validate contributor/edge ownership and publish the complete result. Invalid rounded tolerance stays a rounded-stage error after topology, as in the existing guard. Never allocate or retry during an attempt.

Retain the existing bridge's error distinctions with an additional SourceLimit/UnsupportedSource. Constructor errors include actual combined-byte overflow/limit and the existing nested topology/rounded constructor failures. Internal dependent counters may retain an earlier call if that stage was skipped; the public-to-crate operation output must remain None after every failure, and its latest attempt diagnostics must distinguish skipped stages. No stale internal certificate or mesh is exposed through a failed operation.

## Storage, output and migration

Use the existing 4-contour/16-cubic/64-edge topology ceilings, 72 commands, 68 collected points, 64 owners, and the unchanged rounded limits from [P3.2f](p3-native-cubic-bridge-contract.md). A bounded SourceVerb/contour/control inventory is inline. Topology and rounded vectors remain the only retained heap allocations; constructor checked actual combined capacity stays <=16 MiB, inline workspace <64 KiB. Preserve the G04 conservative storage proof and stable allocated_bytes measurement; no new arena or independent unaccounted cache.

The private API may use `CubicFillWorkspace::new(rounded_limits)`, `attempt(input,rule,topology_tolerance,command_capacity)`, `output()` and `allocated_bytes()`, with concrete crate-private command/range/owner/diagnostic types migrated from the bridge. Output contains borrowed workspace-owned commands, polygon ranges/points, provenance owners, rounded mesh/ledger and rounded statistics. Include a borrowed view of decoded original cubic controls/source ordinals on successful output so tests can compare actual packed-source identity. Mutation invalidates all borrowed views through Rust lifetimes; copied caller data and separate workspaces remain isolated.

Replace the cfg(test) bridge algorithm with a thin adapter that prepares the same canonical PathInput from the existing 94 rows and calls this workspace. Test-only JSON serialization, fixture parsing and expected-status metadata remain in the test module. Preserve the complete 94-row protocol, source order, values, 92 successful meshes/two sizing failures and independent TS expectations. Existing source_bits continue to identify the original fixture input; add native assertions against decoded controls and canonical input, rather than changing the frame or trusting a copied fixture echo. Signed-zero source bits are retained; geometric comparisons permit +/-0 equivalence. Do not require reconstructed leaf endpoint zero signs to equal input p3 signs, because existing relative-origin restoration may differ.

Do not retain a second independent test-only implementation of the composition. The existing TS position/topology/rounded/mesh oracles stay independent and unchanged. No geometry, codec, engine, allocator or export refactor is authorized by this migration.

## 1. Scope

In scope: a paint (solid colour or one linear or radial gradient) on every fill and stroke the document has; one stroke type with paint, width, cap, join, miter limit and an optional dash pattern and phase on every stroked node; isolated opacity on groups, frames, mask groups, symbols and instances (MVP-Q9 (a)); independent rectangle corner radii in the panel (the field exists since M1); a schema bump with a migration; the projection of all of it to the E23, E24 and E25 scene surface; a multi-node `setStyle` command; the isolation-depth bound; clipboard and persistence round trips; a property panel in next-host; a headed spec with pixel probes against the E23, E24 and E25 oracles.

Out of scope (deferred by requirements or by this contract): multiple fills, shadows, blur and blend modes (requirements); conic, mesh or focal gradients, per-stop opacity apart from the stop colour, gradient dithering (E23 section 1); stroke alignment (inside, outside), non-scaling or screen-unit dashes, "adjust dashes to fit" (E24 section 1); on-canvas gradient handles (M4-Q9); paint on text, which belongs to the M6a contract; the UI package and its panels (M8: the M4 panel lives in next-host). M4 makes no performance claim (section 11).

## 2. Schema

The bump is from vN to vN+1, vN being the latest `schemaVersion` on main when M4-U1 starts: 3 today, 4 if M6a bumps first (MVP-Q2 (a)). **Note (M7-U7, 2026-10-29):** M6a-U1 took v4 and M7-U7 takes v5 for the instance text overrides ([M6a contract, section 9](mvp-m6a-text-model-contract.md#9-m7-addendum-text-in-symbols), M7-T3), so if M7-U7 merges first M4-U1 rebases to v6: vN is 5, its migration chains after `migrateV4toV5` (`v4 -> v5 -> v6`) and the unsupported-version fixtures move from 6 to 7 ([M7 contract, section 16](mvp-m7-symbols-contract.md#16-progress), M7-U7 notes). **Fixed at M4-U1 (2026-10-29):** M7-U7 merged first, so vN is 5 and vN+1 is 6 (main at bc463c2); the rest of this contract writes v5, v6 and v7 for vN, vN+1 and vN+2.

```ts
type GradientStop = { offset: number; color: Color };
type Gradient = { kind: 'linear' | 'radial'; transform: [a, b, c, d, e, f]; stops: GradientStop[]; spread: 'pad' | 'reflect' | 'repeat' };
type Paint = Color | Gradient;
type Dash = { pattern: number[]; phase: number };
type Stroke = { color: Paint; width: number; cap: StrokeCap; join: StrokeJoin; miterLimit: number; dash: Dash | null };
// fill: Paint | null on rectangle, ellipse, path, custom, frame, symbol; stroke: Stroke | null on those and on line.
```

- **M4-S1 paint.** A paint with exactly the keys `r, g, b, a` is a `Color`, read as today; one with exactly `kind, transform, stops, spread` is a `Gradient`; anything else is `document.invalid-field` at the paint's path. The key `color` keeps its name and holds a paint (M4-Q12 (a), as E23-Q5 (a)).
- **M4-S2 gradient.** Mirrors E23-S2 in the unit box of the node's frame (M4-Q2 (a)): `transform` is six finite numbers, `x' = a·x + c·y + e`, `y' = b·x + d·y + f`, mapping gradient space to the unit box `[0, 1]²`; its binary64 determinant is finite and non-zero and its binary64 inverse finite. `stops` holds 1 to `MAX_GRADIENT_STOPS` = 16 entries `{ offset, color }`, offsets finite in `[0, 1]` and non-decreasing. `kind` and `spread` are the names above. Any violation, 17 stops included, is `document.invalid-field` at the first failing field (`/nodes/<id>/fill/stops/3/offset`, `/nodes/<id>/fill/stops` for the count).
- **M4-S3 stroke.** `width` finite and at least 0, `cap` and `join` as today, `miterLimit` finite and at least 1, `dash` `null` or a `Dash` (M4-S4). Every stroked node has this one type (M4-Q1 (a)).
- **M4-S4 dash.** Mirrors E24-S1: `pattern` holds 1 to `MAX_DASH_ENTRIES` = 16 entries, each finite and at least 0, at least one greater than 0, with a finite binary64 period (summed left to right over the pattern, doubled when its length is odd); `phase` finite, any sign or size. Dash lengths are page units, the units of `width`.
- **M4-S5 opacity.** Every node's `opacity` is finite in `[0, 1]`, containers and instances included from M4-U3 (M4-L1).
- The model mirrors the scene constants (it imports nothing); a unit test asserts `MAX_GRADIENT_STOPS === SCENE_MAX_GRADIENT_STOPS` and `MAX_DASH_ENTRIES === SCENE_MAX_DASH_ENTRIES`. Check order is the M7 section 2 order; the new field rules are field rules and run where the existing field rules run, in key order. `serializeDocument` writes a gradient as `kind, transform, stops, spread`, a stop as `offset, color`, a stroke as `color, width, cap, join, miterLimit, dash`, a dash as `pattern, phase`.

### 2.1 Migration and versions

- **M4-M1 migration** `migrate(v5 -> v6)`: every `{ color, width }` stroke of a rectangle, ellipse, frame or symbol becomes `{ color, width, cap: 'butt', join: 'round', miterLimit: 4, dash: null }`, and every line, path and custom stroke gains `dash: null`; fills, all other fields and the node map are unchanged. `join: 'round'` is what the primitive draws today (section 1.1), so a migrated document projects to the same scene (M4-A04). Every committed well-formed v5 fixture (the `malformed/` directories excluded, whose rules M4-A01 and the earlier milestones' tests keep) migrates byte for byte to its committed v6 text; the `malformed/unsupported-version.json` fixtures move to v7. The M5 envelope fixtures keep their embedded older documents as restore inputs, and M4-U1 adds one v6 envelope fixture written by `serializeEnvelope`.
- **M4-L1 where the lift lands.** M4-U1 keeps `readNode`'s check (`packages/model/src/parse.ts`, the "Container opacity other than 1" comment; *U1 review amendment (2026-10-30):* formerly cited as `readNodeV3`, `parse.ts:599-603`) for every version, so a v6 container or instance at opacity other than 1 still fails in U1 and U2; M4-U3 restricts the check to inputs at v5 or earlier, together with the command lift.
- **M4-M2 older inputs.** From M4-U3, a document read at version v5 or earlier still fails with `document.invalid-field` when a container or instance has opacity other than 1, since no build could write one (M4-Q10 (a)); migration never adds a value.
- **M6a.** The [M6 text plan](mvp-m6-text-plan.md) (M6-T5) also writes "vN+1". Whichever of M4-U1 and the M6a model unit merges first takes main's next version; the other rebases to the one after, chains its migration after the first (`v3 -> v4 -> v5`), and moves the unsupported-version fixtures once more. M4 adds no paint to text: under either order text run colours stay `Color` (M6 text plan, `TextRun.color`), and the M6 text node has no node-level fill, so no paint key applies to it under the `PROPS` rule of section 4.2. If M6a adds a node-level fill mapped to run colours, the M6a contract owns its `setStyle` rule.
- **M7.** M7-U1 took v3 (main). Symbols and instances need nothing from the migration but the stroke rewrite of `symbol` nodes; instances carry no paint (M7-S2).
- **M5 envelope** is unchanged: `parseEnvelope` reads its document through `validateAnyDocument`, so a stored older document migrates on restore and is written back at v6 by the next autosave; an older build then fails that entry with `document.unsupported-version` and keeps it (M5-Q11 (a)).

## 3. Projection

- **M4-P1 paints.** A `Color` passes through unchanged. A `Gradient` of a node with frame size `w × h` becomes the `SceneGradient` with the same `kind`, `stops` (copied) and `spread`, and `transform` = `diag(w*, h*) · T`, i.e. `[w*·a, h*·b, w*·c, h*·d, w*·e, h*·f]`, with `w* = w` if `w > 0` else 1 and likewise `h*` (E23 section 2, gradient space). The box is the node's own frame for leaves, the frame's for a frame's background and border, and the instance's frame for an instance's background and border. A composed transform that fails E23-S2 (a frame large enough to overflow the determinant) makes the renderer reject the node as `invalid-value`, isolated as any rejected node (`editor.scene-rejected`), disclosed. Likewise a box small enough to underflow it (for example `1e-170 × 1e-170`, whose composed determinant rounds to 0) is rejected as `invalid-value` (*M4-U2 review amendment, 2026-10-30*).
- **M4-P2 strokes (lands in M4-U1).** A primitive stroke is narrowed to `{ color, width }` (the renderer's `copyStroke` rejects any other key); a path stroke carries color, width, cap, join and miter limit, and `dash` only when it is not null (the key is omitted for `null`, M4-Q14 (a), so solid-stroke snapshots stay byte-identical to pre-M4 ones, E24-S2). M4-U1 makes this narrowing in the projector with the type change, so main renders unchanged between U1 and U2; U2 adds the rest of this section.
- **M4-P3 primitive or path.** A rectangle, a frame or symbol border and an instance border project as primitives (as today) when the stroke is null, or its join is `round` and its dash null; an ellipse when its stroke is null or its dash null. Otherwise the node (or the border leaf, same scene ID) projects as a `path` whose geometry is the outline of M4-P4, with fill rule `nonzero`, the node's fill (none for a border) and the full stroke. A rectangle, ellipse, frame or symbol border or instance border with width or height 0 always projects as a primitive, whatever its join or dash, which draws nothing (P1 degenerate rule, `packages/renderer-core/src/primitive-scene-source.ts:1938-1949`); as a path it would draw a visible line. **Disclosed:** a rounded rectangle with all four radii above 0 still goes to a path under a `miter` or `bevel` join, although its join never shows (an optional later optimisation), and the four-cubic ellipse of M4-P4 deviates from the true ellipse by about 0.027% of the radius, so a dashed ellipse is not the primitive's exact outline.
- **M4-P4 outlines (SVG's start points, a stated rule).** In local units with `[tl, tr, br, bl] = clampedRadii(...)` and `k = 0.5522847498307936` (`4(√2 − 1)/3`): a rectangle is `M tl 0`, `L w−tr 0`, the top-right quarter as one cubic with handles `k·tr` along the tangents, `L w h−br`, bottom-right cubic, `L bl h`, bottom-left cubic, then, when `tl > 0`, `L 0 tl` and the top-left cubic, then `Z` (with `tl = 0` the closing line draws the left edge); a zero radius gives no cubic, and a line of zero length is omitted. An ellipse is `M w h/2` and four cubics through `(w/2, h)`, `(0, h/2)`, `(w/2, 0)` back to the start, handles `k·w/2` and `k·h/2`, then `Z`. Both run clockwise on screen. A sharp rectangle `200 × 120` is therefore exactly E24's D3 path.
- **M4-P5 dashed lines (M4-Q6 (a)).** A line with a null dash projects as today. A dashed line with no arrowhead projects in stroke mode with the dash. A dashed line with an arrowhead projects in fill mode: the shaft's dashes are computed in `editor-core` by E24-K1, K2, K3 and K5 on the open segment `P0 → P1` (arc length from `P0`, phase `φ = phase % P` made non-negative), then clipped to the shaft (from the base `B` of a triangle head to the other end or base); each dash is a bar of width `w`, extended by `w/2` at an end for a `square` cap and closed by the existing 16-segment half disc for `round`, except at an end cut by a triangle base, which takes no cap; a zero-length dash is a round disc, a local-axis-aligned `w × w` square (the E24-K5 departure) or nothing for `butt`. The heads are drawn solid as in fill mode today (triangles, and bars for `line` heads), and everything is one outline filled with the stroke paint. More than 4,096 dashes (E24-K8) projects the line in stroke mode with the dash and no heads, so the renderer reports `dash-limit` and draws nothing (E11-U4 O1). The editor counts dashes on the full `P0 → P1` segment before clipping to the shaft, with binary64 arithmetic like E24-U2's; **disclosed:** at exactly 4,096 or 4,097 dashes rounding can make the two counts disagree, so a fill-mode line may draw one count the renderer would refuse, or the reverse.
- **M4-P6 opacity.** Container snapshots carry the node's opacity as today; an instance unit's outer container carries the instance's opacity times its source's (M4-Q15 (a), a projector change made in M4-U3 with the lift; under (b) the instance's alone, as `projector.ts:557-567` does now); the renderer isolates every container with `0 < opacity < 1` (E25-K1), including a frame unit's and an instance unit's outer container, and draws nothing of one at opacity 0 (E25-K3). A mask source's paint and opacity still do not affect its mask (E23-K5, P4-S2).
- **M4-P7 host renderer.** next-host constructs its service with `paints: 'gradient'` and `groups: 'isolated'` beside `clips: 'all'`. A host whose renderer lacks either receives `editor.renderer-unsupported` for the nodes concerned (existing isolation).

## 4. Commands

### 4.1 Widened commands and defaults

- `setNodeProps` and the creating commands take `fill?: Paint | null` and `stroke?: Stroke | null`, validated by the model as now; from M4-U3 (M4-L1), `opacity` on a container or instance accepts `[0, 1]`. An old `{ color, width }` stroke is `document.invalid-field` (a public API change; M4-U1 updates every call site).
- `DEFAULT_PATH_STROKE` gains `dash: null`; a new `DEFAULT_SHAPE_STROKE = { color: black, width: 1, cap: 'butt', join: 'round', miterLimit: 4, dash: null }` is the stroke a rectangle, ellipse, frame or symbol gets when the panel adds one (M4-Q4 (a)). Creating commands keep their fill and null-stroke defaults.

### 4.2 `setStyle`

`setStyle { ids, style }` sets appearance on several nodes in one transaction (M4-Q7 (a)). `style` is a non-empty object with any of `fill` (a paint or `null`), `stroke` (a stroke patch or `null`), `opacity` and `cornerRadii`. A **stroke patch** is an object holding any subset of the six stroke keys; for each node it is merged over the node's stroke, or over `DEFAULT_PATH_STROKE` (line, path, custom) or `DEFAULT_SHAPE_STROKE` (other types) when the node has none; `null` removes the stroke. A key applies to a node when the node's type has that prop in `PROPS` (an instance and a group take only `opacity`, a symbol a frame's props); a node without it is left unchanged. A text node (once M6a adds it) has no `fill` or `stroke` prop, so those keys skip it like any other node without them. Checks, in order: `ids` a non-empty list of distinct strings (`editor.invalid-command` at `/ids`); every ID a node of the active page at any depth (`editor.unknown-node`); `style` an object with at least one key (`/style`); each key one of the four (`/style/<key>`); each key applies to at least one listed node (`/style/<key>`); a stroke patch an object with known keys (`/style/stroke/<key>`); each merged node in `ids` order through `validateNode` and its extension check (the model code at `/nodes/<id>/...`); the isolation depth (section 4.3); the M7 expansion validity and caps. The selection is unchanged and the command returns empty `ids`. A `setStyle` that changes no value returns the base document, so it records no step and no event (`packages/editor-core/src/editor.ts:761`).

### 4.3 Isolation depth (M4-Q8 (a))

The **isolation count** of a node is the number of its proper ancestors that are containers or instances with opacity below 1, counted through expansions as M7-S5 counts clip levels (the instance by its effective opacity of M4-P6, then the expanded containers between the source and the node). It counts hidden ancestors and opacity 0 as well, so it never falls below E25-S2's isolation depth and does not change with visibility. A frame unit puts its content container, background and border one scene level below the frame (`projector.ts:320-360`), so, as M1 section 4.3 and M7-S5 bound clip depth for a frame, a `frame`, `symbol` or `instance` whose own (effective) opacity is below 1 also fails at a count of 32 or more, even when empty (32 nested groups at 0.5 holding an empty frame at 0.5 fail). A command whose document has a node with a count of 33 or more, or such a frame unit at 32 or more, fails with `editor.isolation-depth` (new) at `/nodes/<node>/parent`, or at `/nodes/<instance>/parent` through an expansion, at the first such node in `pages` order then page-tree pre-order. Commands check it when they create, reparent or retype nodes (as M7 section 5.3) or lower a container's or instance's opacity below 1, visiting those subtrees and every instance of each changed source; `loadDocument` checks it after `editor.clip-depth`.

### 4.4 Failure codes

| Code | When |
| --- | --- |
| `document.invalid-field` | Any M4-S rule, on load and in commands; a container or instance opacity other than 1 in a v5 or older input |
| `editor.invalid-command` | `setStyle` shape (section 4.2) |
| `editor.isolation-depth` | Section 4.3 |

`editor.isolation-depth` joins `EditorErrorCode` and the codes an extension command may return. Precedence: the M1 section 4.3.1 order with the M7 section 5.5 additions; `editor.isolation-depth` comes right after `editor.clip-depth`, in commands and on load, and before `editor.invalid-expansion`, `editor.expansion-limit` and `editor.duplicate-id`.

## 5. Symbols and instances (M7)

- **Expansion** maps nodes as a group resize does (M7-X1); paints, joins, caps and dashes are copied unchanged, like stroke widths, and a gradient follows its node's mapped frame because it lives in the unit box (M4-Q11 (a)). A source's fill and stroke change propagates to every instance (M7-X5); the instance's background and border compose the source's gradients in the instance's box (M4-P1).
- **Instance opacity** lifts with containers in M4-U3 (M7-S4 ends): `setNodeProps` and `setStyle` set it, and the instance unit is isolated (M4-P6). The check that an instance's opacity is 1 is restricted to v5 and older inputs (M4-L1).
- **Source opacity (M4-Q15, user decision).** Today a source's own opacity affects only the source as drawn on its page; the instance unit uses the instance's opacity alone (`projector.ts:557-567`), and M7-X1 lists opacity among the source fields that do not affect the expansion. Under (a), recommended for Figma parity, an instance's effective opacity is instance × source, so a translucent source makes every instance an isolated layer, counted in section 4.3; this amends M7-X1 for opacity only. Under (b) the current behavior stays.
- **Detach** and the deletion rule's detach copy paints and dashes with the expansion (M7 section 5.2) and, under M4-Q15 (a), give the frame the effective opacity, instance × source (M4-U3).
- **Disclosed:** each instance at opacity below 1 is one offscreen layer; a page of many translucent full-screen instances can exceed E25's 96 MiB layer budget and report `render.layer-resource-limit` instead of drawing (E25-Q3).

## 6. Hit testing

Unchanged (M4-Q11 (a)): a stroke is hit within `max(w/2, 4/zoom)` of its outline whatever its dash, join or cap, so dash gaps are hit and miter tips and square caps beyond `w/2` are not; paint alpha and opacity 0 do not affect hits; `visible: false` stays not hittable.

## 7. Clipboard and persistence

- Fragments are written at v6 with the fragment version current at M4-U1 (1 today, 2 after M7-U5; M4 adds no fragment version). `parseFragment` accepts each fragment version at every schema version it accepted before and at v6 (*U1 review amendment (2026-10-30):* exactly fragment version 1 at schema 2, and fragment version 2 at schemas 3 to 6; fragment version 1 gains no schema); nodes of an older schema version are migrated by M4-M1 before validation, so a copy from an older build still pastes, and M4-M2 holds for them.
- `parse(serialize(d))` is byte-identical for every v6 fixture with every paint, stroke, dash and opacity variant; the same holds through `serializeEnvelope` and `parseEnvelope`, and the headed spec reloads such a document with `?persist=1`.

## 8. Property panel (next-host)

## 11. Risks

- **Path projection cost and defects.** A rectangle with a miter or bevel join or a dash, and every dashed ellipse and frame border, becomes a path mesh: P3's disclosed defects (A01 cracks, A04) and the fringe cap (E24-Q6: region-only with a notice) apply, and 10,000 such nodes cost more than primitives (M4-A13 is the early look; M9 measures).
- **E27.** A dashed stroke over a region-only fill at `0 < opacity < 1` can take O3 and not draw (E24 D6); M4 surfaces it on dashed filled rectangles and paths and does not work around it.
- **Layers.** Each translucent container or instance is a layer re-rendered every frame (E25-Q5 (a)) within 96 MiB (E25-Q3); at 4x a layer edge shared with content under or over it blends per pixel (E25 U3 finding). If the layer pipeline fails to build, isolated content is not drawn and no diagnostic is raised (E25 U3 departure).
- **Box-relative gradients** stretch when a path edit or resize changes the frame (M4-Q2 (a)), as in Figma.
- **API change.** Old stroke shapes stop being command input; hosts and extensions passing `{ color, width }` must update. From M4-U1 also (for the exit record): `serializeDocument` writes v6 documents only (a pre-v6 stroke has no `dash` and is not serialized), and `migrateV4toV5` returns `ParseResultV5` (a `DocumentV5`) instead of `ParseResult`.
- **Schema ordering** with M6a (section 2.1) and with M7-U5's fragment version.

M4-U2 notes (2026-10-30, implementer decisions for the review):

1. **Paints (M4-P1).** `composePaint` in `projector.ts` returns a colour as the same object and a gradient as a new `{ kind, transform, stops, spread }` with `transform = [w*·a, h*·b, w*·c, h*·d, w*·e, h*·f]` (negative zero removed) and the stops copied. The box is the node's own frame for rectangles, ellipses, paths, custom nodes and lines (a line's frame of height 0 folds to 1), the frame's or symbol's for its background and border, and the instance's frame for an instance's background and border; an expanded node composes in its mapped frame, so a source gradient follows the instance scale while stroke widths and dashes stay page units (M4-A10 projection part, scales 1 and 2). The fill-mode line copies the composed stroke paint into the fill (U1 note 12 (a)), in both its solid and its dashed form. **U1 note 12 (b):** a model-valid rectangle of 1e150 × 1e150 with the identity gradient is accepted by a `RetainedSceneMirror` with every feature on; at 1e160 the composed determinant overflows binary64, the mirror rejects the page as `invalid-value` and the editor isolates the node with `editor.scene-rejected` (pinned, as M4-P1 discloses).
2. **Primitive or path (M4-P3).** A rectangle and a frame, symbol or instance border stay primitives when the stroke is null, or its join is `round` and its dash null, or the box has width or height 0; an ellipse when the stroke or its dash is null or the box is empty. Otherwise the node (or the border leaf, same scene ID, parent the outer container, identity transform) is a `path` with the M4-P4 outline, fill rule `nonzero`, the node's composed fill (none for a border) and the full path stroke (`dash` only when set, M4-Q14 (a)). A primitive's stroke stays the two-key M4-P2 stroke with its composed paint. A switch of join or dash through `setNodeProps` sends one change set that updates exactly the one snapshot, with its new kind, and back (pinned for a rectangle, a frame border and an ellipse); the projection memo and `keepEqual` need no change, since the snapshot depends only on the node (and, for an instance, on the source object, which the memo already compares).
3. **Outlines (M4-P4).** As written: the rectangle from `(tl, 0)` with handles `k·r` along the tangents, `k = 0.5522847498307936` (exported as `QUARTER_ARC_HANDLE`), a zero radius without a cubic and a line omitted when its end equals the current point exactly; the ellipse from `(w, h/2)` as four cubics. 4. **Dashed lines (M4-P5).** `lineDashes` mirrors renderer-core's `expandDash` on one open segment (the same pattern doubling, phase reduction, period walk from `m = −1`, merging of touching and zero-gap intervals, and the work bound), since `editor-core` may not import `renderer-core`; on nine segments (diagonal, odd patterns, dots, a phase of 2^40, negative phases, a 1e-9 gap, a solid pattern) the intervals equal `expandDash`'s within `2^-40 · L`. Stroke mode keeps a dashed line with no head (`none` at both ends); fill mode takes every dashed line with an arrowhead, `line` heads included (reading of "with an arrowhead"; M4-Q6 (b) names dashed `line` heads as the stroke-mode drawback). Each dash is clipped to the shaft `[4w, L − 4w]` at triangle ends; an end at a triangle base takes no cap, whether the dash was cut there or ends there exactly (reading), and a zero-length dash at a base is dropped; elsewhere a zero-length dash is a disc of 32 chords (the end cap's 16-chord half disc and its continuation, axis points exact), a node-local `w × w` square or nothing (`butt`). Dash ends on the shaft use the triangle base points exactly, so a pattern with every gap 0 gives the solid fill-mode outline bit for bit on an axis-aligned line (pinned); on a diagonal line the dashed bar takes the line's direction `d` where the solid shaft recomputes it from its end points, so cap and bar points can differ by rounding (up to about 4e-15 in the review's case; the test pins agreement within 1e-12). Every piece winds as the solid shaft does, so the one `nonzero` outline covers overlaps (caps meeting across a short gap, a cap under a head) once and a translucent paint does not blend twice. More than 4,096 dashes on the full segment (`[1, 1]` on 8,192 units: 4,097, the last zero-length at `L`) projects the line in stroke mode with the dash and no heads; 8,191 units keeps fill mode, and `expandDash` agrees at both lengths.

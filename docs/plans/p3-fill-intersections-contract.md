# P3.2b private certified segment intersections

Status: prospective implementation contract, 2026-09-29. This isolated successor to [P3.2a](p3-fill-predicates-contract.md) stays within existing Rust/Float64 geometry ownership. The [active plan](p3-fill-stroke-meshes.md) owns entry and evidence. No public API, WASM export, P2 v1 caller, dependency, mesh arena or renderer change. Deferred stroke refinement remains deferred.

## Private surface and validation

Add `fill_intersections.rs`, reusing `geometry::{Point, Bounds}` and exact `fill_predicates`. Freeze this crate-private surface:

```rust
enum IntersectionError { NonFinite, InvalidTolerance, Unresolved }
struct CertifiedPoint { point: Point, enclosure: Bounds, error_bound: f64 }
enum SegmentIntersection {
    Disjoint,
    Point(CertifiedPoint),
    Overlap { start: Point, end: Point },
}
fn segment_intersection(a: Point, b: Point, c: Point, d: Point, tolerance: f64)
    -> Result<SegmentIntersection, IntersectionError>;
```

All listed types, fields and function are `pub(crate)`; use Copy/Debug/PartialEq as appropriate. Validate every coordinate first, returning NonFinite for any NaN/infinity, then require finite positive tolerance, returning InvalidTolerance even for disjoint/exact endpoint results. No output accompanies an error. Normalize signed-zero coordinates to +0, lexicographically sort each segment's endpoints by x then y, then sort the two endpoint tuples. All eight endpoint/order permutations must give bit-identical results, including failures and bounds.

Classify using the exact P3.2a predicate. Disjoint returns Disjoint. Touch/CollinearPoint returns an existing endpoint contained in both segments, chosen in canonical order, a singleton enclosure and zero error. CollinearOverlap returns the two extreme lexicographically ordered existing endpoints contained in both segments. Do not average endpoints or approximate overlaps. These branches remain exact at subnormal/max-finite coordinates and need no interval arithmetic.

## Bounded outward Float64 construction

Only ProperCrossing needs generated coordinates. Use a small module-private closed-interval helper, not a new reusable arithmetic framework. Singleton finite input intervals represent the exact stored binary64 values. Basic add/subtract use extremal endpoints; multiply/divide enumerate four endpoint combinations. For each basic operation, widen its ordinary IEEE rounded result by next-down/next-up. For four finite candidates, min/max followed by widening is equivalent to widening each candidate before min/max because the directed successor/predecessor functions are monotone. Reject NaN/infinity or an infinite widened endpoint as Unresolved. Division rejects any denominator interval containing zero. Use Rust f64 next-up/down (or equivalent reviewed bit operations), retaining subnormals; no approximate epsilon, fused multiply-add, fast-math reassociation or unproved exactness shortcut. Exact singleton subtraction of identical values and multiplication by a singleton zero may return exact zero; other operations need no exactness detector.

Let `r=B-A`, `s=D-C`, `q=C-A`, all outward intervals. Compute `den=cross(r,s)`, `t=cross(q,s)/den`, `u=cross(q,r)/den`; require den strictly excludes zero. Intersect t and u with [0,1], justified by exact ProperCrossing. Construct `A+t*r`, `B-(1-t)*r`, `C+u*s`, `D-(1-u)*s`; intersect their coordinate boxes and the common closed source AABB. Every box contains the same exact intersection, so an empty intersection is Unresolved (no fallback). Each arithmetic dependency uses a checked result. Direct intermediate overflow/underflow uncertainty may be Unresolved even if the exact intersection is finite; this slice has no scaling retry.

For each resulting finite coordinate interval [lo,hi], choose a midpoint: `(lo+hi)*0.5` when it straddles zero, otherwise `lo*0.5+hi*0.5`; clamp the finite result to [lo,hi], normalizing zero. Bound coordinate error by the maximum of outward-up `(point-lo)` and `(hi-point)`, preserving exact zero for equal endpoints. Outward-add those two nonnegative errors (exact zero identities allowed) to obtain error_bound. Require it finite and <= tolerance. This L1 bound also bounds Euclidean distance. Every successful Point carries a finite ordered enclosure, a point inside it and a nonnegative finite error_bound. Endpoint cases have exact zero error. Tolerance affects certification only, never classification, interval inflation or point identity.

One segment pair has fixed stack storage and fixed arithmetic work, no allocation, retry, retained state or unsafe code. Existing fixed-size exact predicates provide relation classification. This does not select production path/intersection limits. Future callers must derive a conservative local tolerance within the existing 0.0625 physical-pixel topology/arc share and account for other error contributors; this local helper does not allocate that entire share independently to every downstream operation.

A small positional certificate does not prove connectivity. Preserve original segment/event identity. Overlapping boxes must never be epsilon-merged or ordered by their representative coordinates; equality/order is separate future work. This checkpoint does not select an arrangement algorithm, triangulation, global topology error, coverage, ABI or full ordinary-corpus acceptance.

## Independent fixtures frozen before execution

Add `tooling/generate-p3-fill-intersection-fixtures.mjs` and `tests/fixtures/p3-fill-intersections-v1.txt`. Independently decode inputs to BigInt integers in units of 2^-1074. Compute the exact rational crossing with determinant ratios, not Float64 interval operations or Rust imports. For each exact coordinate, obtain its closest enclosing binary64 floor/ceil by integer comparison and binary search over finite nonnegative IEEE encodings, reflecting bounds for negatives. Exact zero is +0. Verify the two returned neighbours bracket the rational and are adjacent unless equal. Do not obtain expected coordinates by Number division.

Literal generated cases: diagonals (0,0)-(4,4) with (0,4)-(4,0) -> (2,2); horizontal (0,0)-(4,0) with (1,-1)-(1,3) -> (1,0); diagonals (0,0)-(1,1) with (0,1)-(1,-1) -> (1/3,1/3); translated negative third (-2,-2)-(-1,-1) with (-2,-1)-(-1,-3) -> (-5/3,-5/3). Check those exact rational identities independently before emitting.

Append 256 ordinary crossings with xorshift32 seed `0x50333242` (updates <<13, >>>17, <<5, unsigned after each). Consume five words per row: `tx=(w1%256)-128`, `ty=(w2%256)-128`, `w=1+w3%64`, `h=1+w4%64`, `k=1+w5%64`. Points are `(tx,ty),(tx+w,ty+h),(tx,ty+h),(tx+w,ty-k)`. The analytic crossing is `(tx+w*h/(2*h+k), ty+h*h/(2*h+k))`; verify agreement with the separate determinant formula. All 260 rows must resolve at tolerance 1e-8. Output eight coordinate bit fields and four directed-bound bit fields, 16 lowercase hexadecimal digits each; fixed version/seed/count headers, UTF-8 LF. Default/--check demands exact byte regeneration; --write writes only the owned fixture; reject unknown options. Primary wires --check into the existing geometry runner before native tests.

An ignored native `fill_intersections_tests::emit_certified_intersections` test is explicitly invoked by the root runner with --ignored --exact --nocapture after normal native tests. It emits one frame `P3_INTERSECTIONS_BEGIN` / `P3_INTERSECTIONS_END` containing 260 ordered rows: decimal row index, then seven hexadecimal fields (point x/y, bounds min_x/min_y/max_x/max_y, error_bound). The runner captures output, checks process success and supplies it on stdin to generator `--verify-native`. Require exactly one complete frame, exact row count/order/field shape and finite values; no skipped results. The independent BigInt verifier checks the actual representative's exact rational L1 error <= the reported bound, exact intersection enclosure, point containment and 0 <= bound <= the exact represented 1e-8 tolerance. It also rejects a copy with a wrong box and a copy with a zero certificate for the non-dyadic third case. These controls must fail for geometric reasons, not framing. This closes the gap between enclosure correctness and an understated error certificate without introducing test arithmetic into the kernel.

Native literal tests additionally cover exact endpoints/T-junctions, all degenerate relations, partial/full/contained/vertical overlap, signed zeros, subnormal and max-finite exact endpoint branches; all eight permutations; exactly representable scale/translation/reflection with independently transformed expected coordinates. Required rejecting controls: opposite max-finite diagonal crossing causes direct subtraction overflow; min-subnormal diagonal crossing cannot establish a nonzero interval determinant; near-parallel crossing `(0,0)-(1,1)` with `(0,2^-52)-(1,1-2^-52)` has uncertain denominator. These remain exact ProperCrossing but must return Unresolved. Ordinary successful crossing at its returned positive error_bound must pass; next-down error_bound must reject (InvalidTolerance if zero, otherwise Unresolved). Nonfinite coordinates in all eight positions precede invalid tolerance; NaN/infinity/zero/negative tolerance rejects every relation class.

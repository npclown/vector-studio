# V-33 SVG import contract: open, drop and paste SVG

Status: IMPLEMENTING 2026-11-12 (contract review r2 READY WITH FOLLOW-UPS, applied), Full tier. Visualization-track item [V-33](d9-visualization-track.md#status-index). Requested by the user on 2026-11-12 (item 3 of the Figma gap list, "1~10번까지 다 진행해줘"). It moves SVG import out of the deferred list in [requirements](../requirements.md#extension-direction); other import formats stay deferred. Questions V33-Q1 to V33-Q6 (section 7) are adopted as recommended under the user's standing instruction of 2026-10-24 (추천안 자동 채택, recommended option auto-adopted).

It changes `editor-core` (one function, one paste rule, two error codes), `react` (the canvas `paste` reads SVG data and files; the canvas takes dropped SVG files) and `ui` (one panel). It changes no scene contract, renderer, document schema or command shape.

## 1. What a user can do

- Paste SVG markup (copied from a text editor, a browser's "view source", an icon site or a design tool's "Copy as SVG") on the canvas with Ctrl+V or the context menu's Paste here.
- Paste an `.svg` file copied in the system file manager.
- Drag one or more `.svg` files from the desktop onto the canvas.
- Choose a file with the Import section's **Import SVG…** button.

Each import becomes editable nodes (paths, rectangles, ellipses, groups, mask groups, text) in the paste target, centred on the pointer (paste, drop) or the viewport centre (button), selected, as one undo step per file. An SVG that V-30 exported imports back to the same page-space geometry, paints, strokes and clip regions, and single-run unrotated text to the same content, size, colour and baseline (section 5, V33-A04).

## 2. Converter (`editor-core`)

**V33-C1 function.** `svgToFragment(text, options?)` returns `{ ok: true; fragment: string; skipped: readonly string[] }` or a failure. `fragment` is clipboard fragment text (version 2, schema 7, no carried sources, M2 section 6 and M7 section 6) whose roots are the imported content in page space: 1 page unit is 1 CSS px of the root SVG viewport (M2), so `width="24mm"` is about 90.7 page units. `skipped` lists, once each in first-seen order, the element names and features that were dropped (for example `image`, `filter`, `mask`, `marker`). `options.layout(runs)` lays out an `autoWidth` text node with those runs (line height 1.2, align left) and returns `{ width, height, baseline }` (the first line's baseline); the converter writes that width and height as the text frame (a fragment paste does not lay text out, and an auto-sized frame keeps its stored size until `refitText`, M6a amendment). Without it the estimate is width `0.6 × size` per UTF-16 unit of the longest line, height `1.2 × size` per line, baseline `0.8 × size`. `options.name` names the wrapping group (M8); `options.defaultFamily` is the family for text with no or only generic families (the editor passes its text style family).

**V33-C2 failures.** `editor.invalid-svg`: text over 8,388,608 UTF-16 code units, not well-formed XML within the subset of V33-C3, a document element other than `svg`, a `<!DOCTYPE>` internal subset holding anything but internal general entities (parameter or external entities, other declarations), entity expansion over 16,777,216 code units in total, element nesting deeper than 256, more than 20,000 elements, more than 10,000 converted nodes (counted while converting, so `<use>` expansion stops as soon as it passes), more than 200,000 element visits while converting (so `<use>` fan-out of hidden or empty content stops too; each `<clipPath>` child counts once per reference), more than 1,000,000 path points emitted in total (clip outlines included, counted as they are built, so a heavy path or clip referenced many times fails instead of freezing the editor), or a converted tree deeper than 200 levels (the model's 256 includes the paste target and mask wrappers). `editor.empty-svg`: well-formed, but nothing is drawn after section 3 (every element unsupported, hidden or empty).

**V33-C3 XML.** A hand-written parser (no DOM, so `editor-core` keeps running without one): elements, attributes in either quote, character data, CDATA, comments, processing instructions and a `<!DOCTYPE>`, whose internal subset may declare internal general entities (`<!ENTITY name "value">`, as Illustrator writes); a reference to one expands its value once (a reference inside a value is not expanded again, which also stops the billion-laughs blow-up); the five predefined entities and decimal and hex character references; namespaces by prefix (`svg:`-prefixed elements and `xlink:href` are read, other prefixes' elements are skipped with their content).

**V33-C4 detection.** `isSvgText(text)` is true when, after an optional BOM, whitespace, an XML declaration, comments and a `<!DOCTYPE>`, the text's first element is `svg` or `svg:svg`.

## 3. Mapping

**V33-M1 styles.** Each element's computed style is, in priority order: its `style` attribute declarations, then the `<style>` sheet rules that match it (selectors: type, `.class`, `#id`, `*`, compound forms of those, and comma lists; later and more specific rules win; other selectors are skipped and reported once as `css-selector`), then its presentation attributes, then the inherited value for inherited properties (`fill`, `fill-opacity`, `fill-rule`, `stroke*`, `clip-rule`, `visibility`, `font-family`, `font-size`, `text-anchor`, `color`; the `xml:space` attribute inherits too), then the SVG initial value (fill black, stroke none, width 1, butt, miter, limit 4). `!important` is ignored. `font-size` is computed to user units (`px`, `pt`, `pc`, `mm`, `cm`, `in`, `em` and `%` of the parent's size, `ex` as half an em); `opacity`, `fill-opacity`, `stroke-opacity` and `stop-opacity` take a number or a percentage clamped to [0, 1]. `display="none"` drops the element and its subtree; `visibility="hidden"` drops the element's own drawing (its visible children still draw).

**V33-M2 transforms.** The current transform matrix (CTM) composes the root viewport mapping (`viewBox` with `preserveAspectRatio`, default `xMidYMid meet`, into `width` × `height`; without `viewBox` the identity; width and height in `px`, `pt`, `pc`, `mm`, `cm`, `in` or unitless, `em` and `ex` against 16 px, a percentage or no value taking the `viewBox` size, else 100), each ancestor's and the element's own `transform` (`matrix`, `translate`, `scale`, `rotate` with or without a centre, `skewX`, `skewY`), and `x`/`y` of `<use>`. A nested `<svg>` maps its own viewport the same way and clips to it; the root `<svg>` is not clipped to its viewport (content outside it imports).

**V33-M3 shapes.** All coordinates in user units (`px` units converted as M2; a percentage resolves against the nearest viewport: its width for `x`, `cx`, `width`, `rx` and the like, its height for `y`, `cy`, `height`, `ry`, and `√((w² + h²) / 2)` for `r` and stroke widths). A path whose points span no area and that has no stroke is dropped.
- `<path>`: the full SVG 1.1 path grammar (absolute and relative `M L H V C S Q T A Z`, implicit commands, exponent numbers, `1.5.5` style number runs, arc flags without separators). Quadratics are elevated to cubics; each arc becomes at most 4 cubics per 360° (the standard endpoint-to-centre conversion; a zero radius is a line, radii scaled up when too small). Parsing stops at the first error and keeps what came before (SVG's error rule).
- `<rect>` (`rx`/`ry` with SVG's auto and clamping rules), `<circle>`, `<ellipse>`, `<line>`, `<polyline>`, `<polygon>`.
- A `<rect>` whose CTM is a translation with a positive scale per axis or a rotation with uniform positive scale becomes a `rectangle` node (with `rotation`; a reflection is dropped, the shape being symmetric); with non-zero radii it must also have `rx = ry` after scaling (uniform scale), else it becomes a path; a `<circle>` or `<ellipse>` under such a CTM becomes an `ellipse`. Everything else becomes a `path` node: its points mapped through the CTM, its frame their bounding box (rotation 0, `fitPoints`), its fill rule from `fill-rule`. A shape that draws nothing (zero size, no fill and no stroke) is dropped.
- Stroke width scales by `√|det CTM|`; dash lengths and offset too. A non-uniform CTM therefore gives a uniform stroke (disclosed). A width of 0 or less is no stroke. `stroke-miterlimit` below 1 is in error and takes 4. `stroke-dasharray`: an odd-length list is repeated once (SVG); a negative entry, an all-zero list or `none` is no dash; more than 16 entries after that is no dash (disclosed).

**V33-M4 paint.** Colours: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`/`rgba()` in numbers or percentages (comma or space syntax, `/ alpha`), `hsl()`/`hsla()`, the 148 CSS named colours, `transparent`, `currentColor` (the `color` property, default black) and `none`. `fill-opacity` and `stroke-opacity` multiply into the colour's alpha. `url(#id)` naming a `<linearGradient>` or `<radialGradient>` becomes a model gradient: `gradientUnits` (`objectBoundingBox` default, against the element's geometry bounding box, or `userSpaceOnUse`), `gradientTransform`, `spreadMethod`, `x1 y1 x2 y2` or `cx cy r` (`fx fy` are ignored: the model has no focal point), stops with `offset` (number or %), `stop-color` and `stop-opacity` (style or attribute), and `href`/`xlink:href` inheritance of attributes and stops. More than 16 stops keep 16 evenly picked ones including both ends; a gradient with no stop is `none`, with one stop its solid colour. A `url()` that names nothing uses its fallback colour, else `none`. `fill-opacity` and `stroke-opacity` multiply into every stop's alpha. Offsets are clamped to [0, 1] and each raised to at least the one before (SVG). Gradient geometry: gradient space (linear: `(0,0)` to `(1,0)`, the second axis the perpendicular of the same length; radial: centre `(0,0)`, radius 1) maps to `(x1,y1)`–`(x2,y2)` or `(cx,cy)`, `r`, then through `gradientTransform`, the bounding-box map for `objectBoundingBox`, the CTM, and the inverse of the node's unit-box map (M4-S2). A degenerate gradient (zero length or radius), a zero-size bounding box under `objectBoundingBox`, or a node whose frame has zero width or height (a horizontal `<line>`; no unit-box inverse) paints its last stop's colour.

**V33-M5 opacity, groups, clips.** `<g>`, `<a>`, `<svg>` (nested) and `<switch>` (all children, no test attributes) become `group` nodes named by `id` or `inkscape:label`, else by element; an empty group is dropped and a group with one child and no opacity or clip is replaced by that child. Group and `maskGroup` frames are the bounds of their children's frame corners (rotation 0), as `groupNodes` and the group refit set them; children are stored relative to them. `opacity` on a group or a shape becomes the node's `opacity`. `clip-path="url(#id)"` on any element makes a `maskGroup` whose first child is a mask `path` (fill black, no stroke) holding the union of the `<clipPath>`'s shapes (paths and basic shapes, each with its own `transform`; `<use>`, `<text>` and a `clip-path` on the `<clipPath>` or its children skipped), in the referencing element's user space including its own `transform` (`userSpaceOnUse`) or its bounding box (`objectBoundingBox`), then the `<clipPath>`'s `transform`; a single shape's `clip-rule` is the mask's fill rule, several shapes are concatenated as one `nonzero` path (overlapping shapes with opposite winding can then cancel: disclosed). A `<clipPath>` with no usable shape, or a reference to nothing, drops the element (SVG: clips everything). Nested clips deeper than 32 import but do not draw (P4 clip depth; disclosed).

**V33-M6 text.** `<text>` with character data and `<tspan>` children becomes one `text` node (`autoWidth`, align from `text-anchor` start/middle/end as left/center/right, letter spacing 0, line height 1.2): its runs are the character data in document order with each piece's `font-family` (first family of the list, CSS quotes removed; a generic family or none gives C1's default family; at most 128 units), `font-size` (user units, times the CTM scale `√|det CTM|`, clamped to at most 4096; a piece of size 0 is dropped) and solid fill colour (a gradient fill takes its first stop; `none` is transparent); a `<tspan>` with an absolute `y` that differs from the previous piece starts a new line (`LF`). The text is normalized as M6b section 9.1 does and cut to `MAX_TEXT_LENGTH`; adjacent pieces of the same style merge into one run (canonical runs); an empty text is dropped. The anchor `(x, y)` is the first absolute `x` and `y` (the `<text>`'s, else the first `<tspan>`'s); with C1's width `w`, height `h` and baseline `b` and `k` = 0, ½ or 1 for `text-anchor` start, middle or end, the node-local anchor is `(k·w, b)`, and the frame `(w × h)` is placed so the CTM maps the anchor there: under a similarity CTM (rotation and uniform scale) with its rotation, under any other CTM at the mapped anchor without rotation or skew (disclosed). `font-weight`, `font-style`, text `stroke` and `text-decoration` are reported in `skipped`. Whitespace follows the inherited `xml:space` (default: LF removed, tabs and runs of spaces as one space, ends trimmed; `preserve`: LF and tab as spaces, kept). `textPath`, `dx`/`dy` lists and per-glyph `x` lists after the first are ignored (first value used). V-30's one-`tspan`-per-cluster text imports as one node per `<text>`.

**V33-M7 `<use>` and `<symbol>`.** `<use href="#id">` draws a copy of the referenced element (a `<symbol>` maps its `viewBox` into the use's `width`/`height` as a nested viewport), translated by `x`/`y`, with the `<use>`'s computed style as the referenced element's parent style, at most 32 deep; a reference cycle is cut. `<defs>`, `<symbol>`, `<clipPath>`, gradients, `<style>`, `<title>`, `<desc>` and `<metadata>` draw nothing themselves.

**V33-M8 skipped.** `image`, `foreignObject`, `pattern` paint (as `none`), `mask`, `filter`, `marker` properties, `textPath`, animation elements, CSS other than M1 (`css-selector`), and every other element are dropped; `skipped` lists their element or property names (never ids). `<a>` is kept as a group.

**V33-M8a names.** A node is named by its element's `id` when it has one, else its element name (`rect`, `path`, …); the wrapping group (M9) by the root's `<title>`, else `options.name`, else `SVG`. The editor's paste does not pass `options.name`, so a file import without a `<title>` is named `SVG`, not the file name (disclosed).

**V33-M9 the imported roots.** The root `<svg>`'s converted children are wrapped in one `group` (named by M8a) when there are two or more; a single child becomes the only root.

## 4. Paste and the host

**V33-P1 paste rule.** Outside text edit mode, `paste { text }` (and `paste {}` whose in-memory text is unmarked, plain text from an edit-mode copy included) whose text `isSvgText` imports it, at the point where unmarked text would create a text node: `svgToFragment` with the text layout port as `layout` (an SVG with text and no port fails with `editor.no-text-layout`), then the fragment paste of M2 section 6 with `at = pointer ?? at ?? viewport centre` (`editor.no-viewport-size` without one), which centres the roots' joint content box there, in the paste target, one step, the roots selected. Its failures are V33-C2's codes; the fragment paste's own codes pass through. A `paste` sent through the public gesture `update` or `replace` still fails unmarked text, SVG included, with `editor.unsupported-clipboard` (M6b-U8). In text edit mode SVG text is plain text (M6b section 9.2, unchanged). This amends M6b sections 9.3 and 9.4 (noted there): unmarked text that is SVG no longer creates a text node.

**V33-P2 canvas paste.** `EditorCanvas`'s DOM `paste` (M2-I4, M6b section 9.3) outside text edit mode reads, in order: `text/plain` when it is fragment text; `image/svg+xml` data; the first `File` in `clipboardData.files` whose type is `image/svg+xml` or whose name ends in `.svg` (read asynchronously, then pasted at the pointer recorded at the event, unless the editor is in text edit mode by then, when it is dropped); else `text/plain` as before. In text edit mode only `text/plain` is read (M6b section 9.1, unchanged). The event is always prevented.

**V33-P3 canvas drop.** A `dragover` carrying files is prevented with `dropEffect = 'copy'`. A `drop` reads its SVG files (by type or name, other files ignored), in order, and pastes each at the drop point (page space by the camera at drop time), the second and later ones offset by 16 page units down and right per file, one undo step per file. Before each later file the host restores the selection found before the first, so every file goes to the same paste target; the last successful import stays selected. A failed file is skipped and the rest continue. A drop with no SVG file does nothing; a drop while in text edit mode exits it first (`exitTextEdit`).

**V33-U1 Import panel.** `ImportPanel` is a fieldset titled Import with an **Import SVG…** button opening a file chooser (`accept=".svg,image/svg+xml"`, several files allowed). The chosen files import as P3 does, centred on the viewport centre. The panel shows `Imported <name>` (one file) or `Imported <n> files`, then `Skipped: <list>` when V33-C1 skipped something, and `Failed: <name> (<code>)` for each failed file (`Import failed: <code>` when the only file fails). next-host's studio layout mounts it above the Export section.

## 6. Known limits (disclosed)

- No raster content (`<image>`), patterns, masks, filters or markers; they are listed in `skipped` and the panel shows them.
- Non-uniform or skewed transforms turn rectangles and ellipses into paths and give a stroke of uniform width (`√|det|`); text under them keeps only its position.
- A radial gradient's focal point is ignored; several clip shapes merge as one nonzero path.
- Text position uses the layout port's baseline for the first line; lines after it follow the editor's line height (1.2), not the SVG's `y` values, and a `dx`, `dy` or per-glyph `x` list is reduced to its first value. Bold and italic are lost (the model has no weight or style). A multi-run text node that V-30 exported (one `<text>` per run) imports as several text nodes.
- The root viewport does not clip. A dash list over 16 entries is dropped. Nested clips deeper than 32 do not draw.
- CSS support is the M1 subset; `@media`, attribute selectors, combinators and pseudo-classes are skipped.
- A file import without a `<title>` is named `SVG`, not after the file. `<animate>` and other animation elements are skipped and reported; the static value imports.
- Font weight, style and decoration are reported when declared on the text or an ancestor in the source tree; a `<use>` copy is checked against its referenced element's ancestors, not the `<use>`'s.
- Large files (thousands of paths) import as many nodes; the 10,000-node limit fails them rather than freezing the editor.

## 7. Questions (adopted as recommended, 2026-11-12)

- **V33-Q1 what an import becomes.** (a) A group of editable nodes (Illustrator, and Figma's content). (b) A frame sized to the SVG viewport (Figma's wrapper). (c) One image node. Recommended (a): no artboard appears for every pasted icon, and (c) needs image nodes (item 2).
- **V33-Q2 where the code lives.** (a) `editor-core`, a pure converter feeding the existing fragment paste. (b) `react` with the browser's `DOMParser` and `getCTM`. Recommended (a): testable without a DOM, one validation path (the fragment rules), and paste/undo/IDs come for free.
- **V33-Q3 paste detection.** (a) Unmarked text that is SVG imports outside edit mode. (b) Only an explicit import command. Recommended (a): Figma and Illustrator paste SVG markup as shapes.
- **V33-Q4 transforms the model cannot hold.** (a) Bake into path points (shapes become paths). (b) Wrap in a group with the transform. Recommended (a): the model's groups carry no transform of their own.
- **V33-Q5 coordinates.** (a) User units as page units, centred on the pointer. (b) Keep the SVG's own coordinates. Recommended (a), matching paste.
- **V33-Q6 text.** (a) Live text nodes. (b) Outlines. (c) Drop text. Recommended (a): round trip with V-30's live text.

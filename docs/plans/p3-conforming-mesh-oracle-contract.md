## Source-level motivation

P3.2z's existing rounded mesh contains a hanging node: triangle[1,3,5] has edge3->5 at x1 from q1 to1/16; neighboring triangle[3,8,4] uses node4=(1,-1), strictly inside that edge. The native and independent rounded triangulators use cell corners, so shared node indices do not establish a conforming triangle complex. The existing exact region/rounded mesh evidence remains valid; it never established Float32 projection conformity.

Even shear[1,0,1/4,1,31,0] can break the contact under ordered Float32 arithmetic: stored q1 is y3=-14046549*2^-21; x3=f32((1+y3/4)+31)=32+y3/4+5*2^-23, whereas node4 and node5 map exactly to(31.75,-1) and(32.015625,1/16). The pre-projection determinant is nonzero. This is an analytic arithmetic witness, not a measured GPU/raster result.

Independent precision review also found that P1's separately stored local coordinates/affine do not universally satisfy P3's tighter1/16 Euclidean physical-pixel share. For a=b=c=2+2^-23,d=1+2^-24,t=0,p=(2048,2048), camera=(8192+2^-11,6144+3*2^-13), snapped origin=(8192,6144), zoom64,DPR2, ties-to-even packs a,b,c to2 and d to1. Ordered pre-NDC displacement is(-1/16,-3/64), norm5/64. This does not prove CPU pretransform is necessary; mesh-local origin and split representations remain later technical comparisons. No representation change is chosen here.

Before projection certification, establish a coordinate-preserving conforming refinement. Existing W/Y/Z input meshes remain immutable source evidence. The refinement creates no coordinates, moves no vertices, changes no winding/region/ledger and does not repair overlapping or invalid inputs.

## Input, output and deterministic algorithm

Test-only input: finite Float64 vertices and triangle index triples from a plain mesh. Preserve the input vertex array bit-for-bit in the result (including unused vertices); arithmetic treats signed zeros as one geometric point. Reject duplicate geometric vertex coordinates prospectively to avoid inventing welding/ownership rules; frozen source carriers must be checked against this requirement before final freeze. Index count must be a multiple of3, every index in range, every triangle strictly positive in exact binary64-coordinate orientation, and triangle interiors pairwise disjoint. Boundary-only contacts and existing T-junctions are allowed at input. No automatic orientation repair or triangle deletion.

Limits are independent test-work ceilings, not runtime increases: at most256 input vertices and256 input triangles, at most512 output triangles and2,000,000 counted refinement operations. Count every candidate vertex-on-edge examination and every ear candidate examination before execution; attempting operation limit+1 returns WORK_LIMIT with no partial success. Output triangles are checked against the requested limit before append/publication. A valid planar mesh with256 unique vertices has at most507 conforming positive triangles;512 is a conservative ceiling, not a promised reachable default-limit positive. Requested output limit4 success/3 failure on the hanging-node fixture supplies the actual boundary check. Empty indices are valid and may retain finite unique unused vertices.

Freeze test API refineConformingMesh(mesh, limits=DEFAULT_LIMITS). Limits contain maxVertices,maxInputTriangles,maxOutputTriangles,maxWork and must be positive integers at or below the stated ceilings. Result is CERTIFIED with mesh{vertices,indices,parentTriangle} and stats{edgeVertexChecks,earChecks,emittedTriangles,work}, or INVALID_INPUT/WORK_LIMIT/UNRESOLVED with reason and stats but no mesh. Work=edgeVertexChecks+earChecks, counters never exceed the requested budget; preflight is separately bounded by input ceilings. Validation order: limit configuration; index length divisible by3; input vertex/triangle caps; finite unique coordinates; index integer/range; exact positive triangles; pairwise interior nonoverlap; refinement. Cap exhaustion is WORK_LIMIT with explicit input/output/work reason; malformed input is INVALID_INPUT; an impossible convexity/ear invariant is UNRESOLVED. Before each counted operation, check budget; after an eligible ear, check output capacity before append. Failed publication is all-or-nothing. Returned vertices are owned copies preserving source bits, not aliases.

For each original triangle in input order, scan every original vertex against each of its three directed boundary edges using exact integer orientation and strict on-segment tests. Include edge endpoints once, insert all strict interior vertices in exact directed order (axis comparison on a nonzero edge component suffices), and form a simple convex polygon with collinear boundary subdivisions. No epsilon, candidate output or runtime geometry helper participates in incidence classification.

Triangulate that polygon with deterministic ear removal. At each removal restart cyclic inspection at the lowest remaining original vertex index; select the first strictly positive ear whose removal leaves strictly positive remaining polygon area whenever more than3 vertices remain. Do not clip an ear consuming the entire remaining area and strand collinear vertices. Record the emitted triangle's original parent index. Emit the final strictly positive triple cyclically rotated to its lowest index. Preserve all boundary subdivisions; no new vertex or midpoint. A failed convexity/ear invariant is UNRESOLVED, not a fallback. Every successful original polygon emits exactly boundaryVertexCount-2 positive triangles; output concatenates parents in original order. Determinism is defined for fixed input order, not permutation-invariant index ordering.

Use existing exact binary64-to-integer/rational test arithmetic. Coordinates are integers in2^-1074 units; orientation/area use2^-2148 units. Do not import native runtime geometry, production renderer packing or a new dependency.

## Independent verification

Keep candidate refinement separate from a verifier that receives original mesh and proposed result. The verifier must not reuse candidate ear selection or its collected boundary list as expected data. It independently checks bit-identical vertices, index validity, positive triangles, parent range/ordering, every refined triangle contained in its original parent, exact per-parent area equality and pairwise interior nonoverlap. Together these establish unchanged full region, including holes/winding selection inherited from the original mesh; area alone is insufficient.

For each parent, independently compare the multiset of refined boundary subsegments (cancel internal oppositely directed edges) against the original triangle edges split at ALL original collinear vertices. Check no skipped hanging node. Across the whole result, distinct triangle intersections must be empty, one common indexed vertex, or one entire common indexed edge; reject partial overlaps, T contacts, nonincident touches/crossings or coincident duplicate triangles. Internal refinement edges are not added to the existing fill boundary ledger. Preserve original carrier metadata unchanged and associate each refined triangle through parentTriangle; this is test-side attribution, not a new runtime carrier field.

Verifier API verifyConformingRefinement(source, proposed) receives the proposed mesh, not the candidate result wrapper; it returns normally only on proof success, otherwise throws a stage-specific reason. Candidate and verifier accept unknown inputs for malformed-array controls. Reject malformed/sparse point/index arrays before unsafe access; finite unique unused vertices and signed-zero bits remain in detached results. Provided limit configuration must contain exactly the four named fields; omitted limits select defaults. It independently validates bounded source and proposed mesh sizes before quadratic checks. Verifier arithmetic can reuse scalar exact point decoding/predicates, but its containment, edge multiset and intersection loops must be structurally independent of candidate ear clipping. It cannot trust proposed counters, expected boundary lists or parent areas as proof. Existing mesh inspection can supplement, never replace, exact conformity and parent-region proofs.

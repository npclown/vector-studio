## 1. Terms

- **Path, contour, edge.** One corpus path. Its S1 prefix (section 2.2) produces, per contour c, a cyclic sequence of n_c Float64 polygon vertices (`contour_points` within one `ContourRange`) and one owner per polygon edge e = [p_start(e), p_end(e)] (`edge_owners`, an `EdgeOwner`: `CubicLeaf { source_verb, end_numerator, depth }`, `Line`, `ExplicitClose` or `ImplicitClosure`), together with the decoded sources (`DecodedSource`).
- **Consecutive edges.** Two edges of the same contour that share a polygon vertex in the cyclic order. Every other pair of edges, in the same contour or in different contours, is **non-consecutive**. "Adjacent leaves" in B0D-Q3 means consecutive edges.
- **δ.** P2's flattening bound for the request: the bucket tolerance `Request::tolerance` passed to P2 flattening (section 3.2). In every B0 cell δ = `FLATTEN_TOLERANCE` = 0.125 = 2^-3, so 2δ = 0.25 and (2δ)² = 2^-4 exactly.
- **τ.** The exact rung's topology tolerance `TOPOLOGY_TOLERANCE` = 0.0625. The fast rung does not use it.
- **Proved.** A sign or comparison decided either by an exact predicate (`fill_predicates::orient2d`, `fill_predicates::segment_relation`) or by interval evaluation with `fill_filter::Interval` and `compare_enclosures` under B0R's [arithmetic facts R1-R3](p3-b0r-kernel-performance-contract.md#32-arithmetic-facts-used-by-every-filter). An interval never decides a true zero, so a value exactly at a threshold is never proved strictly past it. **Not proved** covers both "false" and "undecided"; either sends the path to the exact rung.

## 2. The ladder

### 2.1 Shape

For each path the ladder runs rung 0, the **fast rung**. If rung 0 publishes a mesh, that mesh is the path's output. Otherwise rung 0 returns one **fallback reason** (section 2.6), and the ladder runs rung 1, the **exact rung**, on the same input; its result, mesh or failure, is the path's output. There is one output per path. The ladder is deterministic: rung 0's checks are pure functions of the input in a fixed order, so equal requests take the same rung for the same reason (V1 rule 6).

### 2.2 Shared S1 prefix

The fast rung starts from the exact rung's own decode, flatten and leaf validation. A `#[cfg(test)] pub(crate)` method on `CubicFillWorkspace` in `cubic_fill.rs`, `prepare_for_spike`, runs exactly the statements of `attempt_body` up to the B0 stop point S1, in the same order: `begin_attempt`, the `MAX_SOURCE_VERBS`/`MAX_SOURCE_SCALARS` check, `run_path` in `Pass::Sizing`, `decode_sources`, `emit`, `collect_contours` (with the same `all_line_eligible` argument) and `validate_leaf_partitions`. It publishes nothing and returns borrowed views of `commands`, `contour_ranges`, `contour_points`, `edge_owners` and `sources`, or the prefix failure. It adds no field and changes no non-test statement. A unit test asserts, on every corpus path whose exact `attempt` publishes an output, that the accessor's points, ranges and owners equal bit for bit those of the published `CubicFillOutput`. `output()` is `None` unless the attempt published (`cubic_fill.rs`, `output`), so paths that fail after S1, such as the O1 `KnotMismatch` paths and series X, are outside the equality test; on them the test asserts only that the accessor succeeds.

Any prefix failure, including a sizing status other than `PATH_OK`, is fallback reason `PREFIX`: the exact rung then runs and reproduces it. This keeps every non-admitted outcome identical to the exact rung's by construction.

### 2.3 Fast rung algorithm

The fast rung is a new test-only module `p3_b0_spike.rs`. It copies the S1 view into fixed inline arrays, then runs these stages in order; the first unproved check returns its fallback reason.

**Contracted contours.** For a contour with a degenerate-source close edge, FR2 computes the deviation of the merged edge e′ against its chord [p, m] (section 3.6), and FR4 and FR5 run on the contracted polygon P′. FR6 to FR8 run on the actual polygon P, which keeps the vertex k.

**No Steiner points.** FR7 adds only diagonals between existing polygon vertices. Every mesh vertex is an S1 polygon vertex, bit for bit, so the mesh region is exactly the flattened polygon's region under the fill rule (checked per path by SL-O2). Contours that are not boundary contours (both sides filled, or both empty) contribute no vertex; their topology is still certified by SL-T1.

**FR7 details fixed now.** Vertex classification (start, end, split, merge, regular) uses the two neighbours' lexicographic order and the `orient2d` sign at the vertex. The left-right order of active edges at a sweep vertex is decided by `orient2d` of endpoints, which is valid because SL-T1 makes all edges pairwise disjoint except at shared vertices. A triangle whose exact `orient2d` is not positive, which collinear chains can produce, is fallback `TRIANGLE`; it is never emitted or skipped. The sorts are deterministic and allocation-free (a bottom-up merge sort on stack index arrays, ties broken by edge or vertex index); the active-edge structure is a small stack array searched linearly, which is O(n) per query in the worst case but holds about two edges per convex B0 ring. FR7's correctness is the textbook algorithm's; this contract does not re-prove it, and SL-O2 checks its output exactly on every admitted path (SL-OB4).

**Fill rule.** FR6 computes, for each contour a, its orientation o_a ∈ {+1, −1}, its outside winding w_out(a) = Σ o_b over the contours b that contain a, and w_in(a) = w_out(a) + o_a. Filled means w ≠ 0 for nonzero and w odd for evenodd. Contour a is a boundary contour exactly when filled(w_out(a)) ≠ filled(w_in(a)); FR7 traverses it counterclockwise if filled(w_in(a)) and clockwise otherwise. All contours are classified together (BC4); nothing is triangulated per contour.

### 2.4 Exact rung

The exact rung is the cell's B0 entry, unchanged: `CubicFillWorkspace::attempt` for the decision and O1 cells (Legacy topology), `attempt_transverse` for series X, with the same `LineFillRule::Nonzero`, `TOPOLOGY_TOLERANCE` and `MAX_FLAT_COMMANDS` as `p3_b0_bench.rs`. It re-runs its own prefix. It is also an oracle input (SL-O3, SL-O4).

### 2.5 Limits and storage

The fast rung runs inside the caps the S1 prefix already enforces (64 edge owners, 68 contour points, 4 contours, 16 sources). Its storage is inline and fixed: polygon and owner copies, per-edge enclosures (four control enclosures of two intervals per edge), sweep index and mark arrays (`[u8; 64]`, `[u64; 64]`), the active-edge array, a diagonal array and at most 128 triangles (a polygonal region with n vertices, k outer components and h holes has n + 2h − 2k triangles). With holes the diagonal count can exceed 64; both arrays have fixed capacities, and any overflow is fallback `TRIANGLE`, so a capacity limit costs admission only, never correctness. Nothing allocates inside a ladder call; the exact rung allocates nothing inside `attempt` either (B0R O7).

**Accounting.** For every path in every admission pre-check, oracle run and diagnostic run, the record keeps the rung taken, the reason, and on fallback the exact rung's result and topology selection (`rounded_topology_selected`, `transverse_topology_selected`). Per cell it reports the fast-rung count, the fallback count by reason and the fallback rate. Timed batches include fallback cost (section 5.3), and the rung of every timed path enters its checksum.

## 3. The topology sufficient condition and its proof

### 3.1 What is proved

The obligation is the [private contract](p3-private-contract.md#numeric-compatibility-decision)'s 0.0625 row for the fast rung, "Region preservation plus a bound on generated boundary displacement; polygon interior triangulation must not introduce new boundaries", under the connectivity clause at its line 51, "A connectivity change cannot be excused by a small positional bound". Line 55 adds that P3.2e's line-fill certificates do not certify "the topology of a preceding cubic flattening stage"; that stage is exactly what this section certifies.

**Claim.** If a path passes SL-C0 to SL-C3, and SL-C4 for each degenerate-source close edge, then:

1. **(SL-T1)** The flattened polygon P and the source contours Γ are connected by a continuous family of embeddings of the disjoint union of circles: every intermediate set of contours is simple and pairwise disjoint.
2. **(SL-T2)** Therefore P and Γ have the same contour orientations and the same nesting, hence the same nonzero and evenodd winding structure, and the same fill classification at every point outside the swept band W ⊂ ∪ N̄_δ(e) (closed δ-neighbourhoods of the polygon edges). The curves themselves are simple and pairwise disjoint.
3. **(construction plus SL-O2)** The fast mesh's region equals the polygon region R(P) exactly. The mesh adds no vertex and no boundary, so its generated boundary displacement relative to P is zero, and every triangulation diagonal is interior.

This is the statement of the [P3.1e certificate](p3-simple-cubic-topology-contract.md) ("a continuous family of embeddings … preserves component orientation and nesting, hence both nonzero and evenodd winding structure"), reached by a different sufficient condition. Like P3.1e, it does not assert that the curved region equals the polygonal region; the positional difference, at most δ by SL-C1, belongs to the 0.125 curve share, which SL-C1 certifies per edge as a by-product (section 3.2). So the fast rung consumes none of the 0.0625 topology share. The Float32 storage share is outside this native spike.

### 3.2 Which flattening bound, and what it bounds

P2's flattening rule ([P2 private contract, cubic bounds and flattening](p2-private-contract.md#cubic-bounds-and-flattening)) emits a leaf when `max(norm(q1), norm(q2)) + guard <= bucketTolerance`, with q1 and q2 the leaf's interior controls minus the chord's one-third and two-thirds points, "because the difference curve has Bernstein controls 0,q1,q2,0". That is a **parametric** bound: |B(t) − L(t)| ≤ max(|q1|, |q2|) at every common parameter t, with L the linearly parametrized chord. A parametric bound implies the two-sided Hausdorff bound between the leaf curve and its chord (and the Fréchet bound), since B(t) and L(t) each cover their whole set as t runs over [0,1].

P2's bound is not used as a certificate here, for three reasons:

- It is computed in Float64 on rounded subdivided controls, with a guard P2 itself calls "deliberately conservative … not an assertion of formal interval arithmetic".
- It bounds the rounded sub-cubic against its own rounded endpoints, not the exact source curve against the emitted knots. Emitted knots are `original_origin + leaf.endpoint` (`geometry.rs`, `emit_leaf`), which can differ from the exact curve point; this is what makes almost every generic-coordinate path fail `KnotMismatch` today (O1).
- P3.1d's exact verification of the curve share is a test-only oracle, not a per-path runtime check.

So the fast rung **re-certifies the bound per edge** (SL-C1): it proves δ̄(e) < δ for the exact restricted source curve against the actual emitted edge, with the knot errors included. δ keeps its value, the P2 bucket tolerance, as B0D-Q3 (a) requires; only its certification is new.

### 3.3 Construction: deviation and the straight-line family

For an edge e with polygon parametrization λ_e(u) = p_start(e) + u (p_end(e) − p_start(e)), u ∈ [0,1], define its **source piece** γ_e:

- `CubicLeaf` of source cubic B with dyadic interval [t_a, t_b] = [(n − 1)/2^d, n/2^d]: γ_e(u) = B(t_a + u (t_b − t_a)), a cubic with exact restricted Bernstein controls R0, R1, R2, R3.
- `Line` with source segment [a, b]: γ_e(u) = a + u (b − a).
- `ExplicitClose` or `ImplicitClosure`: the source closing segment from the contour's last source endpoint z to its MOVE point m, γ_e(u) = z + u (m − z). It is **degenerate** when z = m exactly (section 3.6).

The **deviation** D_e = γ_e − λ_e is a polynomial of degree at most 3 with Bernstein controls

- for a cubic leaf: d_0 = R0 − p_start, d_1 = R1 − (2 p_start + p_end)/3, d_2 = R2 − (p_start + 2 p_end)/3, d_3 = R3 − p_end;
- for a segment: d_0 = γ_e(0) − p_start, d_1 = γ_e(1) − p_end.

Let δ(e) = max_m |d_m| (Euclidean norm). Bernstein weights are nonnegative and sum to one, so |D_e(u)| ≤ δ(e) for every u ∈ [0,1]. d_0 and d_3 are the knot errors: zero when the emitted knot equals the curve point, as on the snapped decision corpus, and nonzero on generic coordinates.

**Consistency at vertices.** If f follows e in a contour, then γ_e(1) = γ_f(0): within one source cubic both are B at the same dyadic parameter; across sources the canonical encoding stores each segment's start as the previous segment's end, so they are the same source point; for the closing edge both are the source point z or m. Since also λ_e(1) = λ_f(0) = p_end(e), D_e(1) = D_f(0).

**The family.** On the cyclic parameter domain of each contour (edges concatenated in order), define H(s, x) = λ(x) + s D(x) for s ∈ [0,1]. By consistency H is continuous in (s, x). H(0, ·) parametrizes the polygon P; H(1, ·) parametrizes the source contour Γ (a degenerate close edge is first removed by SL-L5).

### 3.4 Conditions

For a path with request tolerance δ:

- **SL-C0, structure.** After the contractions of SL-C4, every contour has at least three edges. (Every edge already has distinct endpoints, which S1 enforces with `ZeroLengthLeaf`.)
- **SL-C1, deviation.** For every edge e, δ(e) < δ is proved: FR2 encloses each d_m in intervals and proves the upper bound of |d_m|² = d_m,x² + d_m,y² to be below δ².
- **SL-C2, consecutive pairs (the monotone argument).** For every consecutive pair (e, f), with f following e, let w = p_end(f) − p_start(e), u_e = p_end(e) − p_start(e) and u_f likewise. Proved: ⟨u_e, w⟩ > 0 and ⟨u_f, w⟩ > 0; and for each of e and f, ⟨R_{m+1} − R_m, w⟩ > 0 for m = 0, 1, 2 if it is a cubic leaf, or ⟨γ(1) − γ(0), w⟩ > 0 if it is a segment.
- **SL-C3, non-consecutive pairs (the clearance argument).** For every non-consecutive pair (e, f), in the same contour or not, dist(e, f) > 2δ is proved (section 3.9).
- **SL-C4, micro-closure.** For each degenerate-source close edge, conditions SL-M1 to SL-M4 of section 3.6.

SL-C2 is stricter than P3.1e's monotone projection, which allows zero control projections with a positive total: an exactly stationary end tangent cannot be proved positive by an interval, so it falls back (`MONOTONE`). This loses admission only, never soundness. P3.1f's rounded-knot condition uses the same choice of direction, span from the previous leaf's start to the next leaf's end, on exact source controls; SL-C2 uses the actual polygon span.

### 3.5 Lemmas and theorem

**SL-L1 (tube).** For x on edge e and s ∈ [0,1], |H(s, x) − λ_e(x)| = s |D_e(x)| ≤ δ(e) < δ. So H(s, x) ∈ N̄_δ(e) for every s.

**SL-L2 (monotone pair).** Under SL-C2 for (e, f), for every s ∈ [0,1] the map x ↦ H(s, x) is injective on the arc e ∪ f. _Proof._ Let φ(x) = ⟨H(s, x), w⟩. On e, dφ/du = (1 − s) ⟨u_e, w⟩ + s ⟨γ_e′(u), w⟩. For a cubic leaf γ_e′(u) = 3 Σ_m b²_m(u) (R_{m+1} − R_m) with quadratic Bernstein weights b²_m(u) ≥ 0 summing to 1, so ⟨γ_e′(u), w⟩ ≥ 3 min_m ⟨R_{m+1} − R_m, w⟩ > 0 on all of [0,1]; for a segment it is the positive constant ⟨γ(1) − γ(0), w⟩. With ⟨u_e, w⟩ > 0, dφ/du > 0 on [0,1] for every s. The same holds on f. φ is continuous at the shared vertex, so it is strictly increasing along e ∪ f, and H(s, ·) is injective there. ∎ Every edge lies in a consecutive pair (SL-C0 gives n_c ≥ 3, so e ∪ f is a proper arc of the contour), so SL-L2 also gives injectivity within each edge.

**SL-L3 (clearance).** Under SL-C1 and SL-C3 for non-consecutive (e, f), H(s, e) ∩ H(s′, f) = ∅ for all s, s′ ∈ [0,1]. _Proof._ By SL-L1 the two sets lie in N̄_δ(e) and N̄_δ(f). A common point y would give dist(e, f) ≤ dist(e, y) + dist(y, f) ≤ 2δ, contradicting SL-C3. ∎ Strictness matters here: at dist(e, f) = 2δ the closed tubes touch, and the argument fails, so a pair exactly at 2δ falls back. This is the reason B0D-Q3 (a) says strictly greater.

**SL-T1.** Under SL-C0 to SL-C3 (after the contractions of SL-L5), H(s, ·) is injective on the disjoint union of all contour circles for every s ∈ [0,1]. _Proof._ Take parameters x ≠ x′. If they lie on one edge or on two consecutive edges, SL-L2 separates them. Otherwise their edges are non-consecutive, in one contour or in two, and SL-L3 separates them. ∎ At s = 0 this says the polygon is simple and its contours are pairwise disjoint; at s = 1 that the source contours are.

**SL-T2 (what is preserved).** Under SL-T1:

1. **Orientation.** For each contour, the signed area A(s) = ½ ∮ (x dy − y dx) of H(s, ·) is continuous in s (H is piecewise polynomial in (s, x)), and it is nonzero for every s, because a piecewise-C¹ Jordan curve's signed area is ±(area of its bounded complementary component) by Green's theorem, and that component is a nonempty open set (Jordan curve theorem). So sign A(0) = sign A(1).
2. **Nesting.** For contours a ≠ b and a fixed parameter x_a on a, the point H(s, x_a) never lies on H(s, b) (SL-T1), so the winding number of H(s, b) around it is a continuous integer function of s, hence constant. For a Jordan curve it is ±1 inside and 0 outside, so "a lies inside b" is the same for P and Γ.
3. **Fill classification off the band.** For a point q outside W = ∪_s H(s, ·), which lies in ∪_e N̄_δ(e) by SL-L1, the winding number of every contour around q is constant in s. So nonzero and evenodd classify q the same way for P and Γ.
4. **Region structure.** The complementary components of a disjoint union of Jordan curves, their adjacency and their winding values are determined by the containment forest and the orientations (items 1 and 2). So the filled regions of P and Γ have corresponding components, holes and boundary contours.

Items 1-4 are what "region preservation" means here, and they come from an exact certificate, not from a positional bound (line 51).

### 3.6 Closure and the knot and endpoint joins

- **Internal knots and cubic joins.** An inexact emitted knot k shared by edges e and f moves along k + s (γ(t_k) − k) in both edges' parametrizations (consistency, section 3.3), so the family stays continuous. Its error enters δ(e) and δ(f) through d_3 of e and d_0 of f.
- **First vertex.** The MOVE point is emitted unchanged (`collect_contours` checks its bits), so d_0 of the first edge is the source start minus itself, zero for a cubic or line source.
- **Exactly closed contours.** When the last emitted knot equals the MOVE point, `finish_closed_contour` and `finish_open_contour` drop it, so the last edge ends at the MOVE point and needs no close edge. Its d_3 is B(1) − m = z − m = 0 when the source closes exactly.
- **Non-degenerate close.** When the source does not return to its MOVE point (z ≠ m), the close edge [k_end, m] has the source segment [z, m]; it is an ordinary segment edge.
- **Closed polygon, open source.** If z ≠ m but the last emitted knot equals m exactly, S1 drops that knot and pushes no close edge, so no polygon edge carries the source segment [z, m] and the consistency of section 3.3 fails at m. FR1 returns `STRUCTURE` for such a contour. It cannot occur on the B0 corpus, whose sources close exactly.
- **Degenerate-source close (micro-closure).** When z = m but the emitted last knot k = k_end differs from m (common on generic coordinates, where `original_origin + leaf.endpoint` rounds), S1 pushes an `ExplicitClose` (or `ImplicitClosure`) edge g = [k, m] whose source piece is the single point m. The straight-line family would collapse g at s = 1, and g's direction is a rounding artefact, so SL-C2 cannot use it; worse, the edge e = [p, k] before g and the edge f = [m, q] after it are non-consecutive and about one ulp apart, so SL-C3 must fail. SL-L5 removes g by a first, separate isotopy.

**SL-L5 (micro-closure contraction).** Let P′ be the polygon with vertex k deleted, so that e′ = [p, m] replaces e and g, with source piece γ_e′ = γ_e (its deviation is computed against the chord [p, m]). Let h be the edge ending at p, with other endpoint r, and let T = conv(p, k, m). Conditions:

- **SL-M1.** The contour of P′ still has at least three edges (SL-C0 on P′).
- **SL-M2.** |k − m| < δ is proved.
- **SL-M3.** σ = sign orient2d(p, k, m) ≠ 0, or σ = 0 and ⟨k − p, m − k⟩ > 0 (k lies strictly between p and m on one line).
- **SL-M4.** f ∩ T = {m} and h ∩ T = {p}, decided exactly. For σ ≠ 0 the closed cone of T at m is bounded by the triangle edges k → m and m → p, so q lies in it exactly when σ·orient2d(k, m, q) ≥ 0 and σ·orient2d(m, p, q) ≥ 0; the condition is that this fails. At p the cone is bounded by m → p and p → k, and the condition is that σ·orient2d(m, p, r) ≥ 0 and σ·orient2d(p, k, r) ≥ 0 fails. For σ = 0, T is the segment [p, m], and the condition is that neither orient2d(p, m, q) = 0 with ⟨q − m, p − m⟩ > 0 nor orient2d(p, m, r) = 0 with ⟨r − p, m − p⟩ > 0 holds.
- **SL-C1 to SL-C3 hold on P′**, with e′ consecutive to h and to f.

_Proof that P and P′ are connected by embeddings._ For σ′ ∈ [0,1] let P_σ′ be P with k replaced by k_σ′ = k + σ′ (m − k); P_0 = P, and P_1 is P′ with g collapsed to the point m. The two moving edges [p, k_σ′] and [k_σ′, m] lie in T and, by SL-M3, meet only at k_σ′ for σ′ < 1. Every point of T is within |k − m| of e′ (write it as α p + β k + γ m = (α p + (β + γ) m) + β (k − m)), so for an edge j non-consecutive to e′ in P′, dist(j, T) ≥ dist(j, e′) − |k − m| > 2δ − δ > 0 by SL-C3 on P′ and SL-M2. The edges f and h meet T only at m and p (SL-M4), which are vertices they share with the moving edges, and the moving edges contain m or p only as their fixed endpoints for σ′ < 1. So each P_σ′ is simple and disjoint from the other contours. SL-T1 on P′ then continues the family to Γ. Each member is a Jordan curve (a parametrization that is constant on the collapsed edge at the junction is a reparametrization of P′), so SL-T2's arguments apply to the concatenated family. ∎ The mesh still triangulates P, not P′: the vertex k stays in the mesh, and SL-L5 is used only in the proof.

SL-L5 goes beyond the literal text of B0D-Q3 (a), so including it is decision SL-Q1. It matters only for generic coordinates (O1): on the snapped decision corpus every closure is bit-exact, so no micro-closure occurs.

### 3.7 Why exact polygon simplicity plus δ alone is insufficient

Exact simplicity of P together with |D_e| ≤ δ on every edge does not fix the curves' topology, in either direction. Both examples below use δ = 1/8, dyadic coordinates and cubics that satisfy P2's flattening criterion as single leaves:

- **Disjoint chords, crossing curves.** Edge e is the cubic (0, 0), (1, 3/32), (2, 3/32), (3, 0), with x(t) = 3t and apex (3/2, 9/128). A non-consecutive edge f is the cubic (3, 1/8), (2, 1/32), (1, 1/32), (0, 1/8), with x(t) = 3 − 3t and lowest point (3/2, 7/128). Both have control offsets 3/32 from their chords, so both satisfy P2. The chords y = 0 and y = 1/8 are disjoint, so a polygon containing them can be simple. But at x = 0 curve e is below curve f, and at x = 3/2 it is above (9/128 > 7/128), so the curves cross. SL-C3 rejects the pair: dist(e, f) = 1/8 ≤ 2δ.
- **Disjoint curves, crossing chords.** Keep e. Let f be a `Line` from (1, 1/32) to (3/2, −1/32), so δ(f) = 0. On x ∈ [1, 3/2] curve e has y ≥ 1/16 > 1/32, so the curves are disjoint, while f crosses e's chord at (5/4, 0). The polygon is not simple although the curves are. FR5 rejects it as `CROSSING`.

So the polygon's connectivity and the curves' connectivity can differ while every positional bound holds. That is the private contract's line 51 ("A connectivity change cannot be excused by a small positional bound") and line 55, and the proposal's ruling out of B0D-Q3 (b). SL-C3's clearance is what ties them together.

### 3.8 Curves that touch or nearly touch

- **Touching curves are never admitted.** If γ_e(u) = γ_f(v) for non-consecutive e, f, then dist(e, f) ≤ |λ_e(u) − λ_f(v)| ≤ δ(e) + δ(f) < 2δ, so SL-C3 fails. If consecutive pieces meet anywhere but their shared knot, SL-L2's conclusion would be contradicted, so SL-C2 cannot hold. Touching or coincident contours therefore take the exact rung (B0D-Q6 (a)).
- **Nearly touching curves** are admitted only with a proof: chord clearance above 2δ gives curve distance above dist(e, f) − 2δ > 0. Curves closer than that fall back even if they are disjoint; the condition is sufficient, not necessary.
- **Short edges.** If e, f and g are consecutive in that order in a contour of four or more edges, then e and g are non-consecutive and dist(e, g) ≤ |p_end(e) − p_start(g)| = |f|. So SL-C3 requires every edge of such a contour to be longer than 2δ. Shorter edges fall back (`CLEARANCE`); this limits admission only. On the B0 rings the shortest leaves are about one unit long, and SL-L5 removes the one-ulp closing edges of generic coordinates before SL-C3 runs.
- **Scale.** δ is a local tolerance proportional to 1/zoom, so a feature thinner than about 2δ at the current bucket falls back, and admits after zooming in. B0 measures zoom 1 only.

### 3.9 Computing the clearance exactly and cheaply

For a non-consecutive pair e = [a, b], f = [c, d], FR5 proves dist(e, f) > 2δ as follows, with r = 2δ:

1. **Box gap.** Edge boxes are exact Float64 minima and maxima. If xlo(f) − xhi(e) > r, or one of the three symmetric gaps, is proved (R1 outward rounding, then R3), the pair is clear: Euclidean distance is at least each axis gap.
2. **Disjointness.** Otherwise `segment_relation(a, b, c, d)` must be `Disjoint` (exact, with B0R's F0.3 and F1 filters); any other relation is `CROSSING`.
3. **Endpoint distances.** Each of the four point-segment pairs (a, f), (b, f), (c, e), (d, e) must be proved farther than r. For a point p and segment [s, t] with v = t − s and w = p − s, it is proved when any one of these is proved: (i) cross(v, w)² > r² |v|² (distance to the line exceeds r, and the segment is part of the line); (ii) ⟨w, v⟩ < 0 and |w|² > r² (the nearest segment point is s); (iii) ⟨p − t, v⟩ > 0 and |p − t|² > r² (the nearest point is t). Otherwise `CLEARANCE`.

**SL-L4 (disjoint segments).** For disjoint closed segments, dist(e, f) is the minimum of the four point-segment distances. _Proof._ g(u, v) = |λ_e(u) − λ_f(v)| is convex on [0,1]². If its minimum is attained only in the open square, the gradient of |λ_e − λ_f|² vanishes there, so the connecting vector, which is nonzero because the segments are disjoint, is perpendicular to both directions; in the plane the segments are then parallel, the distance is constant along their common perpendicular span, and it is also attained with u or v at 0 or 1. On the boundary of the square one parameter is an endpoint, which is a point-segment distance. ∎

Every quantity is a polynomial of degree at most 4 in Float64 coordinates, evaluated in `Interval` arithmetic; r² = 2^-4 is exact. A value exactly at r is never proved strictly greater (R3), so the strict inequality is exact in effect: equality and undecided cases fall back. No exact multi-limb routine is added, because a fallback costs only time. Inputs above 2^500 in magnitude, or any overflow, leave the interval undecided (R3), so they fall back.

**Sweep.** FR5 sorts the edge indices of all contours by `xlo` (ties by index) and, for each edge a in that order, scans the following edges b while `xlo(b) ≤ next_up(fl(xhi(a) + r))`, with fl the rounded binary64 sum. A pair not scanned has xlo(b) above an upper bound of xhi(a) + r (R1), so a proved x gap above r. The `next_up` is conservative and, under round-to-nearest, redundant: a binary64 value greater than fl(x) is already greater than x. It is kept for uniformity with R1; no test can distinguish it, so its removal is not a seeded defect. Consecutive pairs are skipped (SL-C2 handles them); scanned pairs run steps 1-3. The cost is O(n log n + K) for K x-overlapping pairs, with a `[u64; 64]` mark bitset as in [B0R section 4.3](p3-b0r-kernel-performance-contract.md#43-sweep). Correctness never depends on K.

## 4. Oracles

All oracles are test-only and independent of the fast rung's code. They run on every admitted path of the oracle run (section 5.9): paths 0-9 of every decision cell, paths 0-99 of P4/s=16, paths 0-29 of every O1 cell and every X path. A failure of SL-O1, SL-O2, SL-O3 or SL-O4 **invalidates the run**, as a checksum mismatch does in B0: the run has no verdict, it is retained, and the defect is fixed before a new run.

### 4.1 SL-O1: exact certificate re-verification

A TypeScript verifier under `tests/geometry/p3-b0-spike/`, using BigInt rationals and no Rust code, recomputes from the dumped source bits, provenance and polygon bits:

- the structure, independently of FR1: the source piece of every edge from its owner, the decoded sources and the provenance; the closure class of every contour (exact close, non-degenerate close, degenerate-source close, closed polygon over an open source); and SL-C0 after its own contractions;
- the exact restricted controls by rational de Casteljau, the exact d_m and max_m |d_m|² against δ²;
- SL-C2's exact dot signs;
- SL-C3's exact `segment_relation` equivalent and exact squared distances against (2δ)², over every non-consecutive pair (all pairs, without the sweep);
- SL-M1 to SL-M4 exactly.

Every fast-admitted path must satisfy every condition exactly. A path where the Rust rung fell back but every exact condition holds is a **conservative fallback**, reported per cell, not a defect.

### 4.2 SL-O2: exact region and mesh validity

For every fast-admitted path, a BigInt verifier checks:

1. every triangle's exact orientation is strictly positive (no degenerate or reversed triangle);
2. every mesh vertex is an S1 polygon vertex of a boundary contour, bit for bit, and every vertex of a boundary contour is used;
3. no directed edge occurs twice among the triangles, and the directed-edge chain of all triangles, after cancelling each edge against its reverse, equals exactly the directed boundary of R(P): the boundary contours' edges, each oriented with the filled side on its left. The verifier derives the boundary contours itself, from exact shoelace orientations and exact ray-crossing nesting;
4. the exact total triangle area equals the exact signed area sum of the oriented boundary contours.

_Why 1 and 3 suffice._ For a point x on no edge, the multiplicity m(x) = Σ_T [x ∈ T] of positive triangles equals the winding number of their boundary chain around x, and cancelled pairs do not change it. By 3 that chain is ∂R(P), whose winding number around x is 1 inside R(P) and 0 outside: it is 0 far away and, like the indicator of R(P), it rises by exactly 1 across each boundary edge from its right to its left. So m = 1 on R(P) and 0 elsewhere, off a null set: the triangles have disjoint interiors and cover R(P) exactly. Item 3 also excludes T-junctions, since a split edge would not cancel. The mesh is therefore conforming, consistently oriented and nondegenerate, and its region is exactly R(P). Item 4 is a redundant control.

The existing test-only `inspectTriangleMesh` of `packages/geometry-reference` (P3.1b) also runs on each fast mesh; every B0 mesh is within its 256-vertex and 256-triangle cap. `inspectLineFillMesh` (P3.1c) is not used, because its 32-element cap is below these paths' sizes.

### 4.3 SL-O3: agreement with the exact rung

On every path that both rungs admit (the oracle run executes the exact rung on every path, untimed):

- **Same input polygon.** The exact rung's published `points`, `ranges` and `owners` equal the fast rung's S1 view bit for bit.
- **Area band.** The exact rung embeds sections within τ (P3.2e, half-budget windows), so its region differs from R(P) only near the boundary. The check is |A(exact mesh) − A(R(P))| ≤ Σ_e (2τ (|Δx_e| + |Δy_e|) + 4τ²) over the boundary-contour edges, computed exactly; the right side bounds the area of the τ-neighbourhood of ∂R(P), since π < 4 and the L1 length bounds the Euclidean one.
- **Reported, not gated:** both meshes' V and T, and whether the exact mesh also passes SL-O2 item 3 (it can, when it places no section node off a polygon vertex).

This is a necessary condition of agreement up to the exact rung's certified displacement, not a proof; the proofs are SL-T1 and SL-O2.

## 5. The measurement

### 5.1 Scenario identity and relationship to B0

Scenario `p3-b0-spike-ladder` version 1, runner `p3-b0-spike-runner/1`.

The scenario reuses B0 v1's corpus bytes, cells, sampling, fits, prediction bound, curvature guard, checks, k and budgets, under a new identity and configuration hash. It does not supersede, rerun or reinterpret `p3-b0-feasibility` v1; both B0 records stay as committed.

### 5.2 Corpus and cells

- **Bytes.** The framed corpus of B0's generator `p3-b0-ring/v1`, unchanged, with SHA-256 `206cf6e9971d5f38f11cbef801692555843b1602ee937c5e1b60ed7dbd329796` (`206cf6e9…9796`), as both B0 records pin it. The runner regenerates the bytes with `encodeCorpus` and refuses to run if the hash differs.
- **Cells.** As [B0 section 2](p3-b0-feasibility-benchmark-contract.md#2-corpus-and-sweep): the 34 decision cells (primary series P2, P4 and P8, fitted and binding; contour series K2 and K4, observational), the 26 O1 cells and the 6 X cells. ### 5.4 Admission pre-check

As B0: in every repetition process, before timing, paths 0-9 of each decision cell and paths 0-99 of P4/s=16 run once untimed through the ladder. A path is OK if the ladder publishes a nonempty mesh; a cell is ADMITTED only if all its paths are OK, otherwise CAP-BOUND or NOT-ADMITTED from its first failure, with B0's code list applied to the exact rung's error. Per path the record keeps the rung, the fallback reason, the flat command count and, on fallback, the exact rung's topology selection.

### 5.5 Sampling

Unchanged from [B0 section 3](p3-b0-feasibility-benchmark-contract.md#3-builds-sampling-and-checks): five fresh processes with a 45-minute timeout each; the Fisher-Yates cell order from xorshift32 seeded 0x9e3779b9 + r; per cell one untimed workspace construction, three warm-up and 20 timed batches of the first 10 paths, each path also timed individually into a preallocated array; the clock quantum and the 100-quanta UNVERIFIED rule; linearity in N on P4/s=16 with 10- and 100-path batches and the 1.25 limit; retention of every sample. The batch checksum is B0's FNV-1a 64-bit fold, with the constant status word replaced by the rung (0 fast, 1 exact) as a u32, then V, T, vertex bits and indices of the ladder mesh.

### 5.6 Fits, estimates and checks

Unchanged from [B0 section 5](p3-b0-feasibility-benchmark-contract.md#5-extrapolation-and-the-feasibility-decision): per repetition and primary series, OLS of ln t on ln L over admitted cells; the upper prediction bound U with the hard-coded one-sided Student-t table; the curvature guard G; t̂ = exp(max(U, G)) at L\* = 32λ; the same for the p95 edit proxy; T̂ = 1,000 · t̂ · k, t̂_edit = t̂_p95 · k and M̂ = 1,000 · m̂ at L\*, maximized over repetitions and primary series, with k = 2 (B0-Q2). The validity checks are B0's eight. Check 5 compares, across repetitions, the checksums and the **ladder mix**: per path the rung, the fallback reason and, on fallback, the exact rung's topology selection, which is the ladder's counterpart of B0's topology mix. The spike analysis imports B0's exported `summarize`, `nearestRank`, `classify`, `leaves`, `fitSeries`, `canonicalJson` and `configHash` unchanged, so the formulas are the same code.

### 5.7 Fallback-rate reporting

Per decision cell and repetition: fast-rung and fallback counts by reason, from the admission pre-check (they must agree across repetitions by check 5), and the fallback rate. Per primary series: the fallback rate at the largest cell. The record states, next to the verdict, which share of the timed decision paths took the fast rung. No expected fast-rung admission is fixed in advance; a high fallback rate is a result, not a check failure.

### 5.8 Diagnostic run

One separate process, using the decision build (no `p3_b0_diag` flag is needed, because stage stops are parameters of test code). Over the P2, P4 and P8 cells, with three warm-up and ten timed batches per stage, it records the medians of four nested stops of the fast rung alone: SL-D1, the S1 prefix; SL-D2, through FR5 (the certificate); SL-D3, through FR6 (classification); SL-D4, through FR8 (the full fast rung). Stage costs are differences of medians. It also times the exact rung alone on the same cells, as a same-process baseline, and records per path the number of sweep candidates, of clearance tests reaching steps 2 and 3, and the `fill_filter` decided and fallback counters for F1. The diagnostic run is outside the decision; B0's H1 is not evaluated, because the fast rung's exact arithmetic is limited to `orient2d` and `segment_relation`.

### 5.9 Oracle run

One separate, untimed process after the repetitions. It runs both rungs on every path of section 4's list and writes a dump (per path: source and polygon bits, owners, provenance, both meshes, the rung, the reason, the certified δ̄ values and the exact rung's outcome). The runner then runs SL-O1 to SL-O7 in TypeScript and stores their results in the record. An oracle-gate failure invalidates the run (section 4).

### 5.10 Builds

The decision build is B0's: an ignored `cargo test --release --lib` test with pinned Rust 1.94.1, release profile (opt-level 3, LTO, one codegen unit, unwinding in the test harness), the crate's `cfg(test)` tracking allocator compiled in, and the B0 decision target directory. The `cfg(test)` filter counters (`fill_filter::record`) are compiled in, as in both B0 records. These facts are recorded as known overhead. The harness allocates nothing inside a timed batch. The spike harness `p3_b0_spike_bench.rs` reuses `p3_b0_bench.rs`'s corpus reader, clock-quantum probe, shuffle and FNV helpers, made `pub(crate)` (see the scope list above).

### 5.11 Environment and provenance

Every record carries [B0 section 7](p3-b0-feasibility-benchmark-contract.md#7-environment-memory-categories-and-result-records)'s metadata: commit or dirty-tree marker with source manifest, UTC time and timezone, OS, CPU, logical cores and RAM, power and background-load observations from `--environment-json`, build mode, toolchain, target, profile and rustflags, known overhead, schema version, scenario ID and version, the full configuration and its hash, the corpus SHA-256 and seeds, warm-up, sample and repetition counts, source and runner provenance, commands and runner version. Browser, GPU, viewport and DPR fields are not applicable, with that reason. Provenance follows the 2026-10-12 protocol, as the [B0R remeasure](p3-b0r-kernel-performance-contract.md#8-remeasure-plan) did: a power observation before the run, the operator's background-load statement, a process listing shortly before the start, and **no CPU-load sampling**, per the user's standing instruction. A record missing required metadata is exploratory and carries no verdict.

- **Raw output** goes to an exclusive new directory `artifacts/p3-b0-spike/<run-id>/` under the ignored artifacts tree; the run ID is `YYYYMMDDTHHMMSSZ` plus eight random hex digits; nothing is overwritten.

### 5.13 Command and profiles

`pnpm benchmark:p3-b0-spike --profile functional|reference --environment-json <observations.json>`, a new root script for `node tooling/run-p3-b0-spike-benchmark.mjs`. The reference profile requires `--environment-json` and a clean worktree. The functional profile runs one repetition with two timed batches per cell and the oracle run, without the diagnostic run, and has no verdict. A functional run validates the runner; it is never performance evidence.

## 8. Risks and open obligations

**Open obligations.** Each is gated by the independent review of this contract; any one the reviewer does not accept disables the conditions it supports (they fall back) until a revision resolves it.

- **SL-OB1.** SL-T2 relies on the Jordan curve theorem and Green's theorem for piecewise-C¹ Jordan curves, and its step 4 on the standard correspondence between the containment forest and the complementary components. Standard, cited rather than re-proved. Accepted by the round-1 review.
- **SL-OB2.** SL-L5 (micro-closure) is new: the cone tests of SL-M4 and the concatenation of the two families need the reviewer's specific check; accepted by the round-1 review. Its inclusion is still decision SL-Q1.
- **SL-OB3.** Interval soundness of the restricted-control enclosures and of every SL-C1 to SL-C3 decision rests on B0R R1-R3 and the existing `fill_filter::Interval`; SL-O1 checks the outcomes exactly on every admitted path.
- **SL-OB4.** FR7's triangulation is the textbook algorithm and is not re-proved here; SL-O2 verifies its output exactly per path. A production contract needs either a proof or an always-on output check.
- **SL-OB5.** The certificate covers the represented Float64 source; it says nothing about stroke, coverage, Float32 storage or the combined 0.25 px target (A04, B4).
- **SL-OB6.** The condition is sufficient, not necessary. Its admission on input other than the B0 ring family is unknown.

**Risks.**

- **The spike may miss the budgets.** DF1's target is about 1.95 µs per leaf at L\* = 256 against 37.3 µs per leaf today. No committed record measures any alternative tessellator. If it misses, the user decides again with a measured number.
- **Fallback rate.** If the fast rung falls back on many decision paths, the ladder costs more than the exact rung alone (a failed fast attempt plus a full exact attempt). The record reports it; the rule is not adjusted.
- **Certificate cost.** FR2's interval de Casteljau is O(depth) per leaf and FR5 is O(n log n + K); the B0 rings have small K, but the record's diagnostic split is the evidence.
- **Slivers.** A Steiner-free monotone triangulation of thin rings may make slivers; SL-O5 reports them. They bear on R0 and on the coverage fringe, not on the spike's verdict.
- **Worst-case FR7 cost.** The active-edge array is searched linearly. On the convex B0 rings this is constant; on other inputs it is O(n) per query. A production contract revisits it.
- **Generic coordinates.** Without SL-L5 (SL-Q1 (b)), almost every O1 path would fall back as `CLEARANCE` at its micro-closure, and the O1 observation would measure a rounding artefact rather than the condition.
- **Interval conservatism.** Undecided signs fall back; SL-O1's conservative-fallback count measures how much admission this costs.
- **Extrapolation, WASM factor, zoom range, edit proxy, outside-kernel costs.** As in [proposal section 7](p3-b0-direction-proposal.md#7-risks-and-unknowns): L\* is four times the largest measured L, k = 2 is provisional until B0-W, zoom 1 only, E3 is a lower bound, and the fringe builder (DF8), packing, upload and draw are outside the spike.
- **The record's noise.** The B0R remeasure's elevated P8 p95 samples were not identified; check 2 can fail again. INCONCLUSIVE goes to the user under B0-Q3; sampling is not tuned to avoid it.

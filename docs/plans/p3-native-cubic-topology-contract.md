No public API, ABI, P2 behavior, dependency, renderer or error-budget change; user-deferred stroke refinement stays deferred.

## Scope and mathematical ownership

Add an unexported Rust `simple_cubic_topology` module using existing `fill_exact::Signed` and multiplication. It certifies the same restricted exact-knot/monotone-projection/disjoint-hull condition as P3.1e, including implicit closure, exact orientation and nesting. Preserve all its proof obligations, not only absence of proper crossings. The result is a sufficient certificate for both fill rules, not a product rejection envelope or general cubic tessellator. Positional error is still separately certified; no tolerance parameter belongs to this helper.

Use exact restricted controls even when an interior control is not representable as Float64. An additional Float64-control round-trip restriction would unnecessarily narrow the already accepted condition, so it is not selected. General crossings, tangencies, close hull overlap and inexact returned knots remain unresolved under the existing sufficient condition. Production operation/source decoding, cache/transport and arbitrary-path fallback remain later work.

## Exact representation and finite work

All finite Float64 coordinates are integral multiples of 2^-1074. Decode using the existing integer decoder, then multiply by 2^60 to represent coordinates on 2^-1134. Restrict a provenance cell [(n-1)/2^d,n/2^d], d<=20, by following the high-to-low bits of n-1 through iterative midpoint de Casteljau subdivision. This differs from the reference oracle's arbitrary-rational start/local-end restriction. Do not use Float64 arithmetic to derive hull controls.

Initial controls have at least 60 trailing zero bits. Each subdivision consumes at most three, so every midpoint sum is exactly divisible by two through depth20. Coordinate magnitudes are below2^2158; midpoint pre-halving sums and coordinate differences below2^2159. `Signed<34>` supplies2176 magnitude bits. Difference products are below2^4318 and two-product determinant/dot sums below2^4319. A64-edge shoelace sum is below2^4323. `Signed<68>` supplies4352 bits. Reuse the existing checked-capacity arithmetic; no saturating/truncated product or external big-integer dependency.

Reconstruct all restrictions once for the all-knots preflight without retaining them, then again during hull construction. This keeps one leaf vector and preserves error precedence even when an earlier implicit closure exhausts capacity before a later source projection. At most2*64*20 midpoint splits, six point midpoints per split, occur. A leaf hull has at most four vertices; sorting, hull construction and projection have fixed finite loops. Unordered hull pairs are capped at2016, each with at most16 edge-pair, eight other-vertex containment and two allowed-knot membership checks; each such predicate has constant bounded arithmetic. Nesting has at most12 queries over64 edges. No recursion, adaptive subdivision, epsilon merging, retry or allocation during certification.

Exact convex hull intersection must include containment, endpoint contact, collinear overlap and proper crossings. Adjacent hulls may share exactly the canonical knot, including cyclic last/first; other pairs must be disjoint as closed sets. A two-leaf closed retrace remains unresolved. Exact horizontal half-open ray winding over the certified polygon supplies nesting labels; a boundary query is unresolved. A contour's orientation is its exact shoelace sign, with zero unresolved. Integer winding accumulation is bounded by64 edges.

## Private input, workspace and publication

Use flat, caller-owned input slices, with these crate-private types:

- `TopologyRange { start: usize, count: usize }`.
- `TopologyCubic { points: [Point;4], source_verb: u32, leaves: TopologyRange }`.
- `TopologyLeaf { end: Point, provenance: Provenance }`, reusing the existing geometry types.
- `TopologyInput<'a> { contours: &'a [TopologyRange], cubics: &'a [TopologyCubic], leaves: &'a [TopologyLeaf] }`.
- `TopologyLimits { max_contours, max_cubics, max_leaves, max_pairs, max_bytes }`, all usize. Defaults/absolute count ceilings are4/16/64/2016; the first three allow1..ceiling and pairs0..2016. Default/absolute heap byte ceiling is1 MiB. max_bytes allows0..=1 MiB: zero or less than requested produces ByteLimit, while values above1 MiB are InvalidLimits.

`SimpleCubicTopologyWorkspace::new(limits)` validates limits/checked requested bytes, reserves one Vec of exact leaf/hull records with capacity max_leaves, checks its actual capacity bytes, and returns InvalidLimits, ByteLimit or AllocationFailed on failure. Avoid a large stack `[ExactLeaf;64]` temporary. Store only small copied polygon[64], contour-range[4], orientation[4] and winding[4][4] arrays inline; fixed-size arithmetic scratch stays below32 KiB per active nonrecursive helper. Report heap capacity with `allocated_bytes()` and object inline size separately. No unaccounted retained allocation or copied input arena.

`certify(input)` returns `Result<(), TopologyError>`. Errors are InvalidLimits, AllocationFailed, ByteLimit, InvalidInput, InvalidProvenance, KnotMismatch, Unresolved and WorkLimit. Constructor-only errors remain distinguishable. `stats()` returns `{leaves,pairs}`. `output()` returns None unless the entire latest call succeeded, otherwise a borrowed `TopologyOutput` containing `points`, `contours`, `orientations` and row-major `winding` (one four-entry row per active contour; unused columns are zero). Polygon points and ranges are workspace-owned copies. No input borrow survives the call. A mutable call invalidates the previous borrow through Rust's lifetime rules.

Reset publication, logical vector length, output lengths and both counters at the start of every certify call. Validate before numeric work in this order:

1. Nonempty contour/cubic/leaf slices and count ceilings; excess declared counts return WorkLimit with zero counters before inspecting excess content.
2. Contour ranges must be a nonempty contiguous exact partition of cubics, and cubic leaf ranges a nonempty contiguous exact partition of leaves, with checked ends. Validate every finite source control/endpoint, unique source ordinal and mathematical consecutive-cubic connectivity. Invalid structure/content is InvalidInput. Signed zeros compare mathematically equal.
3. Validate every leaf source ordinal, depth0..20 and numerator1..2^depth; adjacent dyadic intervals must cover exactly[0,1] for each source. Any error is InvalidProvenance with zero counters.
4. Reconstruct every restriction and compare both canonical endpoints with the actual knot sequence. Any KnotMismatch has zero counters and precedes all projection/hull failures anywhere.
5. Reconstruct in source order, checking the leaf ceiling before each projection/hull append. Require nonzero chord and the three nonnegative derivative-control projections, at least one positive. Append any nonzero implicit closing segment immediately after its contour. Increment leaves only on append. Fewer than three leaves in a contour is Unresolved before pairs. Closure capacity is not precharged in input counts.
6. Enumerate i<j in append order. Before a candidate pair, if pairs equals max_pairs, return WorkLimit without incrementing or inspecting; otherwise increment then inspect. Failure at the cap reports exactly max_pairs, never max_pairs+1. Pair/projection/zero-area/nesting failures publish no partial certificate. Derive complete output only after every check passes.

Copied point convention matches P3.1e: the first leaf of each cubic uses that cubic's original p0 tuple; later leaves use the preceding actual endpoint; an implicit closing leaf uses the last actual endpoint. Preserve chosen signed-zero values. No dropped zero-chord leaf or fabricated cubic closure provenance. Limits/statuses are private helper semantics, not new final product support limits.

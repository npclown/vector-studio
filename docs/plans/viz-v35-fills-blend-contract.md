# V-35 contract: multiple fills and blend modes

Status: **ADOPTED 2026-11-12** (review round 2 READY WITH FOLLOW-UPS, follow-ups applied), Full tier. Visualization-track item [V-35](d9-visualization-track.md#status-index), with renderer units. Requested by the user on 2026-11-12 (item 5 of the Figma gap list, "1~10번까지 다 진행해줘"), which lifts the [requirements.md](../requirements.md) deferral of multiple fills and blend modes. The open choices in section 9 take the recommended option under the user's standing instruction of 2026-10-24 unless the user picks otherwise.

It changes shared surface:

- the document schema (the next schema version, see V35-S1): `fills` on every filled node, `blendMode` on every node;
- the editor commands `setStyle` and the create commands (new optional keys), and three new fill commands;
- the scene contract (`SceneNodeBase.blendMode`), scene validation, one renderer option and one new diagnostic code;
- a backdrop snapshot step and a blend composite pipeline in `renderer-core` and `renderer-webgpu`, shared with V-36's background blur;
- the property panel and the PNG and SVG export.

It adds no runtime dependency and changes no existing draw: a document whose nodes have at most one visible fill at opacity 1 with blend `normal`, and no node blend mode, projects to the same scene as before (V35-A06). Identifiers use the prefix **V35-**.

Owners: this file owns V-35's order, criteria and evidence. [graphics-engine-architecture.md](../graphics-engine-architecture.md) owns the compositing model (U4 amends it). The [E25 contract](d9-e25-isolated-opacity-contract.md) owns layers and the layer budget; the [E41 contract](d9-e41-boolean-effects-contract.md) owns effect roots. V-35 amends four earlier rules, each in its owning document when its unit lands: E25-K3 and E25-S2 (K3: a `normal` container at opacity 1 isolates), E10 section 3.2 (K4: the canvas usage under `blend: 'v0'`) and M4's `editor.isolation-depth` count (P6).

## 1. Scope

In scope:

- **Multiple fills.** A rectangle, ellipse, path, custom node, frame or symbol holds 0 to 16 fills, painted bottom first. Each fill is a paint (solid, gradient, or any later paint kind such as V-32's image paint) with its own visibility, opacity and blend mode. Instances draw with their source's fills, as they do with its fill today.
- **Blend modes.** The 16 modes of W3C Compositing Level 1 on every node and on every fill: `normal`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `colorDodge`, `colorBurn`, `hardLight`, `softLight`, `difference`, `exclusion`, `hue`, `saturation`, `color`, `luminosity`. Containers additionally take `passThrough` (the default).
- Commands, panel controls and PNG and SVG export for both.

Out of scope (backlog): multiple strokes, fills on text (text runs keep their colour) and on lines, Figma's `linearBurn`, `linearDodge`, `plusDarker`, `plusLighter`, blend modes on a mask group's source (ignored, P4-S2: the mask uses the fill area only), knockout groups.

## 2. Document model

- **V35-S1 version.** The v8 scaffold (#571, 2026-11-12) introduced v8 with v7's shape; under the coordinator's rule of that day, the gap-list items add to the unreleased v8 without a further bump. V-35 is the one recorded exception to "add optional fields": it **replaces** `fill` by `fills`. The v7 to v8 migration turns `fill: null` into `fills: []` and `fill: p` into `fills: [{ paint: p, visible: true, opacity: 1, blendMode: 'normal' }]`, and sets `blendMode` (`passThrough` on `group`, `maskGroup`, `frame`, `symbol` and `instance`; `normal` on leaves). Until v8 is released (V-23's alpha publish), the v8 reader also accepts a node carrying `fill` instead of `fills` (read as above) and a node without `blendMode` (its default), because v8 documents may have been autosaved by builds between the scaffold and V-35; a node carrying both `fill` and `fills` is invalid at `fill`. The writer writes only `fills` and `blendMode`. The legacy `fill` read is removed when v8 is released.
- **V35-S2 types.**

```ts
type BlendMode =
  | 'normal' | 'multiply' | 'screen' | 'overlay' | 'darken' | 'lighten'
  | 'colorDodge' | 'colorBurn' | 'hardLight' | 'softLight' | 'difference' | 'exclusion'
  | 'hue' | 'saturation' | 'color' | 'luminosity';
type Fill = { paint: Paint; visible: boolean; opacity: number; blendMode: BlendMode };
// rectangle, ellipse, path, custom, frame, symbol: `fill: Paint | null` becomes
fills: readonly Fill[];          // bottom first, 0 to 16 entries
// every node:
blendMode: BlendMode | 'passThrough'; // 'passThrough' only on group, maskGroup, frame, symbol, instance
```

- **V35-S3 limits.** At most 16 fills; `opacity` finite in `[0, 1]`; a paint per the model's existing paint rules. `passThrough` on a leaf, or an unknown mode, is invalid. Validation rejects anything else.
- **V35-S4 instances.** An instance has its own `blendMode`, which always applies (the symbol's mode applies to the symbol itself only; there is no unset value, unlike E41-S10), and no fills: it draws with its symbol's `fills` (M7 section 4.1). Detach copies the symbol's fills and keeps the instance's mode.
- **V35-S5 the old `fill` key in the API.** Create commands and `setStyle` keep `fill?: Paint | null`, which now means "replace all fills by this one fill (opacity 1, normal), or none". A new `fills?: readonly Fill[]` key replaces the list; passing both is invalid. Reading `fill` from a node in host code is replaced by `fills`; [host-api.md](../host-api.md) records the change. The default fill of new shapes is one fill of today's default paint.

## 3. Semantics

- **V35-R1 fills.** A node with fills `F₀ … Fₙ₋₁` (bottom first) draws, in its own paint slot, each visible fill with opacity above 0 in order, each covering the node's fill area with its paint, its alpha multiplied by the fill's opacity and composited with its blend mode; then its stroke on top with `normal`. Node opacity, node blend mode and effects apply to the result as a whole.
- **V35-R2 blend formula.** W3C Compositing and Blending Level 1 (blending, section 10: separable modes 10.1, non-separable 10.2) on **encoded sRGB, straight-alpha colour**, as `mix-blend-mode` in browsers and Figma do: with backdrop `Cb, αb` and source `Cs, αs`, the premultiplied result is `αs(1 − αb)Cs + αsαb B(Cb, Cs) + (1 − αs)αbCb`, `αo = αs + αb(1 − αs)`. `normal` is today's premultiplied source-over.
- **V35-R3 backdrop.** The backdrop of a blended node or fill is everything already drawn in its **parent target**: the canvas (page content below it in paint order), or the enclosing isolated layer (an E25 layer, an effect root's `L`, a blend root or an isolating container, K3). The canvas clear colour (opaque black) and the host's page background are not part of the document; over them a blend acts as on any opaque backdrop on the canvas, while PNG and SVG export are transparent there, so export matches the canvas only where the backdrop is document content. A blended fill of a node with opacity below 1, a node blend mode or effects therefore blends only with the node's lower fills (isolation, as `mix-blend-mode` and Figma).
- **V35-R4 containers.** `passThrough` keeps today's behaviour (no layer unless E25 or E41 make one). Any other mode isolates the container: its children blend only with each other, and the result is composited once with its opacity and mode (`normal`: source-over).
- **V35-R5 hidden and zero.** A fill with `visible: false` or opacity 0 draws nothing; a node whose fills draw nothing still draws its stroke and effects as today.

## 4. Projection (`editor-core`)

- **V35-P1 single draw.** A filled leaf with at most one drawing fill (V35-R5), whose fill blend mode is `normal`, projects exactly as today: one scene leaf whose `style.fill` is that fill's paint with its alpha multiplied by the fill's opacity (solid alpha, or every gradient stop's alpha), or null, carrying the node's own blend mode (K1). This is exact: one draw of `p` at opacity `o` equals one draw of `p` with alpha scaled by `o`.
- **V35-P2 expansion.** Any other filled leaf projects as a container with the node's ID, transform, visibility, opacity and effects, holding one leaf per drawing fill, ID `<id>\u0000fill<i>` (`i` the fill's index in `fills`), identity transform, the node's geometry, `style.fill` composed as in P1, the fill's blend mode, no stroke; then the stroke leaf `<id>\u0000stroke` (fill null) when there is a stroke. The node's own mode goes on the container: `normal` maps to `passThrough` (no key), so the fills blend through to the backdrop (R3); another mode makes the container a blend root. Its `unitIds` list all of them. Opacity below 1 or effects make the container a layer, which gives R1's "as a whole".
- **V35-P2b mask source.** A mask group's first child (P4-S2: its fill area only) always projects as one P1 leaf with no `blendMode`: its geometry with the first drawing fill's paint, or its first fill's paint when none draws, or null, exactly as the projector leaves out a mask source's effects (`emit = effects && id !== maskSource`, E41). P4-S2 rejects a container mask source, and both export painters read the source's geometry.
- **V35-P3 frames and symbols.** A frame unit's background becomes one background leaf per drawing fill in the content container, IDs `<id>\u0000background` for index 0 and `<id>\u0000background<i>` above it (`i` the index in `fills`, as in P2), each with its fill's blend mode. The frame's or symbol's mode goes on its outer container, with V35-P5's rule for `normal`.
- **V35-P4 gate.** Blend modes reach the scene only when the projector's `blend` option is on (off by default, as E41's `effects`). The projector never emits a default mode (`normal` on a leaf, `passThrough` on a container), gate on or off, so a scene without blending is the same value as before (A06). With the gate off, no `blendMode` key is emitted at all and every node and fill draws as `normal`.
- **V35-P5 isolating containers.** With the gate on, a container whose mode is `normal` always projects as `normal` (isolating, K3). It draws the same pixels as `passThrough` when nothing inside it blends (up to E25-K4's 1/255 rounding and E25-K2's clip-ramp difference, which any E25 layer has), at the cost of a layer; `passThrough` is the default, so the layer exists only where the user chose `normal`. (Amended 2026-11-12 during U3, recommended option auto-adopted: the earlier rule, `normal` only when the subtree projects a non-default mode, made a deep mode edit update every `normal` ancestor and instance unit, which scoped projection cannot do without a subtree walk.)
- **V35-P6 isolation depth.** `editor.isolation-depth` (M4) counts, on the document and conservatively: containers with opacity below 1 (as today), nodes with visible effects and opacity above 0 (E41's gap, closed here), any container or instance whose mode is not `passThrough`, any leaf whose mode is not `normal`, any leaf with a drawing fill whose mode is not `normal` (its fill leaf is a K3 blend root), any leaf with two or more drawing fills at opacity below 1, and an instance's inherited effects (E41-S10). A fill leaf with a mode is a leaf layer, so it must sit at 31 or less: a leaf's fill leaves sit one level below the leaf when its P2 container is a layer (opacity below 1, a mode or effects), and a frame's, symbol's or instance's background (an instance's is its source's fills) sits one level below the node when the unit isolates. (Amended 2026-11-12 in the U2/U3 review: fill leaves with a mode, backgrounds and inherited effects were missing.) `setStyle` (`blendMode`, `fills`, `opacity`), `addFill`, `setFill`, `moveFill`, `addEffect`, `setEffect`, group, paste and instance commands check it. A document past the depth now fails `loadDocument` with `editor.isolation-depth` where it used to load and draw partly; the renderer already refused such a tree (disclosed).

## 5. Scene contract and rendering

- **V35-K1 scene field.** `SceneNodeBase` gains optional `blendMode?: SceneBlendMode`, the 16 modes of V35-S2 plus `passThrough`. Absent means `normal` on a leaf and `passThrough` on a container. Scene validation adds the key; `passThrough` on a non-container is `invalid-value`. A mask source's `blendMode` is ignored by the renderer (the mask uses coverage only, P4-S2), since a reorder can make a node the source without touching it; P2b keeps the projector from emitting one.
- **V35-K2 gate.** Renderer option `blend: 'none' | 'v0'` (default `'none'`), as E41's `effects`; `'v0'` requires `groups: 'isolated'`. With `'none'`, any `blendMode` key other than the default is `unsupported-feature`.
- **V35-K3 blend roots and isolating containers.** A **blend root** is a visible node with opacity above 0 whose mode is outside {`normal`, `passThrough`}: a layer root (as an E41 effect root: a leaf root draws a layer of its own) whose `R` is composited into its parent target with its opacity and mode (K5). An **isolating container** is a visible container with opacity above 0 and mode `normal`: an E25 layer composited with E25's source-over composite, needing no snapshot. A node that is also an effect root or an E25 layer is one layer. Both count toward `SCENE_MAX_ISOLATION_DEPTH` as E41-S7's effect roots do. This amends E25-K3 (a container at opacity 1 is isolated when its mode is `normal`) and E25-S2's isolating set, and with it `isIsolating` in scene validation; U4 records both amendments in the E25 contract.
- **V35-K4 backdrop snapshot (shared with V-36).** Before a blend root's composite, the renderer copies the parent target's pixels under the root's output bound into a single-sample texture of the target format: it ends the parent pass (storing colour and stencil, which today's main pass discards, so the E17 stencil sequence survives), runs a resolve pass that reads that rectangle of the parent attachment with `textureLoad` (at 4x the average of the samples, as the hardware resolve; at 1x the texel), and resumes the parent pass with `loadOp: 'load'` for colour and stencil. Usages, only when `blend: 'v0'` (so A06's resource identity holds otherwise): the 4x MSAA attachment and the layer tile colour textures gain `TEXTURE_BINDING`; at 1x, where the main pass draws straight into the canvas texture, the canvas is configured with `TEXTURE_BINDING` added (an amendment of E10 section 3.2, which today adds `COPY_SRC` only for frame capture). One split is one end-and-resume of a pass around one snapshot. The step is one function, `snapshotBackdrop(encoder, parent, rect, margin, into, record)` in `renderer-webgpu/src/backdrop-pipeline.ts`, returning `into` (`{ texture, origin }`: the root's snapshot texture and its absolute device origin), or null when the rectangle is empty in this pass. The caller ends the parent pass (storing colour and stencil) before the call and resumes it after; `parent` is the pass's attachment with its device region, `into` is the root's snapshot, created once per frame and filled by each of its splits, and `record` is the dynamic offset of the split's snapshot record (`packBackdropSnapshotRecord`). `margin` grows `rect` by whole device pixels, clamped to the parent target, with clamp-to-edge sampling outside it; blend uses `margin = 0`, V-36's background blur `⌈3σ⌉`. In a tiled parent the caller passes, per tile pass, the root's rectangle already grown and clamped to that tile, with `margin = 0`. (Amended 2026-11-12 in the U4 review: the contract first named `snapshotBackdrop(encoder, parent, rect, margin)` returning a new texture; a root over several tile passes needs one texture filled by each.) The plan side is `renderer-core/src/backdrop-plan.ts`: the `LayerScope` fields `blend?: SceneBlendMode` and `backdrop?: { margin: number }`, and the per-frame split count. In an E25 layer or an effect root (a tiled parent) the snapshot is taken per tile pass, from that tile's attachment over the root's bound inside the tile, so blend roots work at any depth; in the shifted passes of an effect root's `L` (E41 U5b) the snapshot origin is the tile's device origin plus the pass shift. `margin > 0` is only offered when the parent is the main target (V-36 discloses the nested case).
- **V35-K5 blend composite.** A new pipeline `blend-composite-v0` draws `R` over the snapshot with V35-R2: its fragment reads `R` and the backdrop at the same device pixel and writes the blended, premultiplied result with blending off (`one, zero`). A clip or mask coverage `c` mixes in the shader, `c · blended + (1 − c) · backdrop`. Fragments where `αs · c = 0` are discarded, so pixels `R` does not cover keep their samples; a covered pixel gets one value in every sample, which flattens the parent's sub-sample edges under `R`'s antialiased edge only (disclosed). Variants: E41-K5's {plain, clip} × {main, layer} × {stencil, no stencil}, plus the shifted set for passes inside an effect root's `L` (E41 U5b). One shader holds all 15 non-normal modes, selected by a record field.
- **V35-K6 budget.** Per blend root, the snapshot costs `4 Oᵣ` bytes, counted with E25's 96 MiB layer budget and admitted per tree as E41's roots are. A blend root costs one split per tile pass it composites in (one in the main pass). A tree over the budget, or the blend roots past the first 64 of a frame in paint order (the pre-order of the layer scopes, a container before its descendants), drop the layers that only V-35 asked for: its blend roots draw as `normal` and its isolating containers as `passThrough`, keeping a layer only where E25's opacity or E41's effects need it, so nothing disappears. It raises one new diagnostic `render.blend-resource-limit` per transition and is re-admitted under E25's rule.
- **V35-K7 unavailable pipeline.** Without the blend pipeline, or when the platform refuses K4's `TEXTURE_BINDING` usage on the canvas or an attachment, blend roots draw as `normal`, isolating containers as `passThrough`, and `blendPipelineAvailable` is false, as E41's section 5.3.
- **V35-K8 invalidation.** A node blend-mode edit, a fill blend-mode edit inside P2, a fill opacity or visibility edit that keeps the node's projected form and leaf set, and a fill paint edit change records only: 0 geometry builds. An edit that switches a node between P1 and P2 is an update of `<id>` (leaf to container or back, with its `children`) plus inserts or removes of the fill and stroke leaves (never an insert and a remove of the same ID, which the scene mirror rejects), and builds the geometry of the new leaves once; so does an edit that makes a hidden fill draw.

## 6. Commands and UI

- **V35-C1 commands.** `addFill { ids }` appends a fill (the default paint, opacity 1, normal) to each listed node that takes fills, refusing with `editor.fill-limit` at 16; `setFill { ids, index, patch: { paint?, visible?, opacity?, blendMode? } }` patches the fill at `index` of each listed node that has one; `removeFill { ids, index }`; `moveFill { ids, from, to }`. `setStyle` gains `fills` (S5) and `blendMode` (applied to each node whose type allows the mode; `passThrough` skips leaves and applies to groups, mask groups, frames, symbols and instances). Each command is one undoable step; a change of no value records no step.
- **V35-C2 Fill section.** The property panel's Fill section lists the fills top first, as Figma does: per row a visibility toggle, the paint swatch and its editor (today's colour and gradient controls), an opacity field in percent, a blend-mode menu and a remove button; a `+` button adds a fill; up and down buttons reorder. A mixed selection shows "Mixed" with `+` replacing every selected node's fills by one fill (Figma).
- **V35-C3 Layer section.** A blend-mode menu next to the opacity field: `Pass through` (containers only), `Normal`, then the 15 modes in Figma's groups (darken, lighten, contrast, inversion, component).
- **V35-C4 paste and boolean.** Copy and paste keep fills and modes. A boolean result takes `A₀`'s fills and blend mode (E41-B2's rule, now over the list). Ungroup moves a group's `passThrough` children unchanged; a group with another mode warns `editor.ungroup-blend` and its children lose the group's mode (as M4-Q17 for opacity).

## 7. Export

- **V35-E1 export scene.** `exportScene` carries P2's expansion and each node's `blendMode`, always as if the projector's `blend` gate were on (export does not depend on the host's renderer).
- **V35-E2 SVG.** A node or fill leaf with a mode other than `normal` gets `style="mix-blend-mode: <css-name>"` (`colorDodge` → `color-dodge`, and so on); a container that is an isolated layer gets `style="isolation: isolate"`. SVG viewers that ignore `mix-blend-mode` show the unblended content (disclosed). A `<g>` with `clip-path` or `mask` is an isolated group in SVG, and V30's writer clips every frame content and mask group that way, so a blended child of a frame blends with the frame's content only in SVG while it blends through on the canvas (disclosed; moving the clip onto the children is backlog).
- **V35-E3 PNG.** The Canvas 2D painter draws a layer for every blend root, leaf or container, and for every isolating `normal` container, as it does for opacity below 1 (V30-P2), and composites a blend root's layer with `globalCompositeOperation` set to the CSS name.

## 9. Open choices (recommended option auto-adopted 2026-11-12 under the user's standing instruction)

- **V35-Q1 mode set.** (a) The 16 W3C modes plus `passThrough`, so the canvas, SVG and Canvas 2D export share one definition. (b) Figma's 19 (adds linear burn, linear dodge, plus darker, plus lighter): needs custom SVG filters. **(a)**.
- **V35-Q2 colour space.** (a) Encoded sRGB, straight alpha (CSS, Figma). (b) Linear light. **(a)**, matching E23's gradient rule.
- **V35-Q3 multiple fills via projection.** (a) Expand to sibling scene leaves (no scene-contract change for fills; geometry built once per fill). (b) A `fills` list in the scene contract and multi-paint draws. **(a)**: (b) is an optimisation for later if a benchmark shows the cost.
- **V35-Q4 nested blend roots.** (a) Support them in tile passes (V35-K4). (b) Only roots whose parent is the main target, others draw `normal`. **(a)**.
- **V35-Q5 scope of fills.** (a) Shapes, paths, custom nodes, frames and symbols; text and lines excluded. (b) Also text. **(a)**.

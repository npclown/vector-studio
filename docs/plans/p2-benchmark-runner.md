## Measurement implementation

- Build a separate benchmark composition page with Vite production output. Bundle the actual private geometry-wasm adapter; include the reproducibly built release WASM as an asset and verify its SHA-256 in each browser. Do not import geometry-reference or use an alternate flattening/ABI implementation.
- Generate the frozen workload once per page. Each variant has its own fresh kernel/session, with all cache limits set to zero. Compile/fetch once outside samples and report those costs; separately report instantiation, preparatory work, reserve calls/durations and arena sizes for each variant.
- Before warm-up, run one untimed preparation sample per variant to provision sufficient arenas and establish matching output checksums. Both variants then receive the plan's equal warm-up. Preparation is separately labeled and never substitutes for warm-up.
- Reuse already sufficient adapter arenas without calling reserve on steady batch execution. This general capacity check applies to every session, requires no new API, and preserves exact-size reserve/retry on exhaustion and all view/epoch checks. Primary owns this small adapter change and its regression fixtures. A measured reserve call, growth, retry or unexpected process count invalidates the repetition.
- A sample's monotonic clock starts before the actual GeometrySession.batch calls and ends after checksum publication. Every result's source/status/bounds, verb byte, Float64 coordinate and provenance scalar contributes to the checksum. Record copied-output byte totals and largest concurrently retained output payload; label JS/object/allocator/physical-memory exclusions.
- Observe process/reserve/growth calls through the existing private kernel injection seam. Use session work-counter deltas for logical cubics, paths, sizing/emission visits and emitted lines; also expose actual successful sizing/emission pass counts. All calls use the same production session/kernel code. Do not subtract timed work or switch to a benchmark-specific fast path.
- Retain all sample pairs in execution order, including warm-up and failed/partial repetitions. Reference repetition order/count and AB/BA scheduling follow the P2 plan. Functional mode uses one fresh page per browser, one untimed pair and two measured pairs, with the same 1,000-path workload; it has no performance disposition.
- Record positive performance.now increments before sampling; use their minimum as the observed clock quantum. Missing/nonfinite resolution or a reference sample shorter than 100 quanta yields UNVERIFIED. Do not change sample/repetition counts after observing results.

## Records and execution

- `pnpm benchmark:p2 --profile functional|reference` is explicit; reject unknown/duplicate flags and missing reference environment metadata before build/launch. Reference observations use the benchmark policy's provenance-bearing environment fields. Existing P1 environment-shape validation may be reused without changing P1 semantics.
- Reserve a new immediate child of ignored `artifacts/p2.5/`; never replace an existing run, record or result. Keep outputs outside Playwright cleanup. Persist invocation, source/build/environment manifests, every browser/repetition record and final aggregate, including failures. `completion.json` closes source/build capture before validation; `runner-status.json` records the final exit outcome after raw-record validation, including threshold failure.
- Capture git base/dirty state and SHA-256 manifest of the relevant adapter/kernel/runner/configuration/toolchain sources before and after execution. Persist file bytes or a manifest tied to subsequently committed sources for dirty runs. Include the production assets' manifest, exact Rust identity/profile and WASM hash. Source/build drift invalidates the run.
- Use stable installed Chrome then Edge with one worker, no retries. Reference uses headed fresh pages and no tracing/video/DevTools; functional uses headless pages. Record browser version/flags, OS/CPU/RAM, viewport/DPR/window/visibility, clock observations and available GPU metadata with explicit exclusions for this CPU/WASM workload. Never infer operator observations.
- Independently recompute results from raw samples: expected identities and pair order/counts; full output checksum agreement; one versus 1,000 process calls, 32,000 source cubics and 1,000 paths per sample; no failed paths/cache hits/reserve/growth; equal sizing/emission work per variant; disposed zero live session/cache counters. Reject malformed/incomplete/tampered records before threshold evaluation. Functional summaries are FUNCTIONAL_PASS/FAIL, never a speedup pass.
- Reference aggregates retain all five repetitions per browser and the plan's per-repetition median paired speedup and p95 condition, plus nearest-rank median/p95/p99/min/max. Missing/duplicate/source-incompatible repetitions or insufficient timer resolution prevent acceptance. A runner disposition is evidence for Primary review, not automatic full P2 acceptance.

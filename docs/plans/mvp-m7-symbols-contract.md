## 1. Scope

In scope: a symbol source node (`symbol`), a frame-like container that lives on a page and is edited with the existing commands; an instance node (`instance`) that refers to one source and has its own placement and size; the expansion of an instance from its source, derived for projection, hit testing and detach, never stored; propagation of every source change to its instances; `createSymbol`, `createInstance` and `detachInstances`; the source deletion rule; the nesting rule that rejects instances and sources inside a source; clipboard copy, paste and duplication of sources and instances, within a document and across documents; a schema bump with a migration; a persistence round trip; a next-host page and headed spec; a performance observation.

Out of scope (deferred by requirements or by this contract): nested instances (an instance inside a source), variants and general property overrides (requirements, Symbols); instance text override and text nodes inside sources until text exists (section 8); swapping an instance's source; "go to source" navigation; turning a source back into a frame; a command that moves nodes to another page; symbol libraries shared between documents; instance opacity other than 1 until the container opacity rule allows it (M7-S4); property-panel symbol controls (M8). M7 makes no performance claim (section 9).

## 2. Schema

The bump is from vN to vN+1, vN being the latest `schemaVersion` when M7-U1 starts: 2 today, higher if M4 or M6a bumps first (MVP-Q2 (a)).

```ts
type SymbolNode = NodeBaseV2 & { type: 'symbol'; children: string[]; fill: Color | null; stroke: RectStroke | null };
type InstanceNode = NodeBaseV2 & { type: 'instance'; symbol: string };   // no children, fill or stroke
```

- **M7-S1 source.** A `symbol` has the fields of a `frame` and is a container: its children are in its local space, it may be empty, and it clips to `{0, 0, width, height}`. It may be anywhere on any page except inside another `symbol` (M7-S3). The page that holds it owns it; instances on other pages refer to it across pages (M7-Q1 (a), M7-Q2 (a)).
- **M7-S2 instance.** An `instance` is a leaf in the document tree; `symbol` names a `symbol` node of the same document, on any page. Its `frame`, `rotation`, `constraints`, `opacity`, `visible` and `name` are its own (requirements: "independent placement and size"); its content is the expansion of section 3. A `symbol` that names no node is `document.dangling-reference` at `/nodes/<id>/symbol`; one that names a node of another type is `document.invalid-symbol` (new) at the same path.
- **M7-S3 nesting.** No `instance` and no `symbol` has a `symbol` ancestor (`document.invalid-symbol` at `/nodes/<id>/parent`). Because an instance's content comes only from a source and no source holds an instance, an instance can never contain itself, directly or through other instances, so no cycle check over `symbol` references is needed (M7-Q5 (a)).
- **M7-S4 opacity.** An instance projects as a container (section 4), so its `opacity` follows the container rule in force: the model gains an explicit check that an instance's opacity is 1 (`document.invalid-field` at `/nodes/<id>/opacity`, since `parse.ts:528` covers container types only), until M4 lifts the rule for containers and instances together.
- **M7-S5 depth through an expansion.** An expanded node's tree depth is the instance's tree depth plus one plus its depth below the source; its clip depth is the instance's clip depth plus one plus the clip levels that frames and mask groups add between the source and the node. The instance itself projects as a frame unit (section 4.1) whose background sits at its clip depth plus one, so, as a frame, an instance at clip depth 32 or more fails as well, even when its source is empty. **Tree depth** is checked by the model, after M7-S3, against `MAX_TREE_DEPTH` (256): `document.invalid-field` at `/nodes/<instance>/parent`. **Clip depth** is checked by `editor-core` on load after the extension checks, extending `documentClipViolation`: `editor.clip-depth` at `/nodes/<instance>/parent`. Commands check both as in section 5.3.
- Unknown fields stay rejected. Model check order: `readDocumentV2` as now, with M7-S2 after ownership, then the cycle walk, M7-S3, the M7-S5 tree depth, then the group and mask rules. Within each model rule the failure names the first failing node in node-map entry order, as the M1 rules do; the page pre-order of section 5.3 applies to commands and to the `editor-core` load checks.

### 2.1 Migration and versions

`migrate(vN -> vN+1)` rewrites `schemaVersion` only, since no existing node changes (M7-Q12 (a)); every committed vN fixture migrates byte for byte to its committed vN+1 text, and an older build fails a vN+1 document with `document.unsupported-version`. The P5 and M1 `malformed/unsupported-version.json` fixtures (`schemaVersion: 3` today) move to vN+2. `serializeDocument` writes `symbol` keys as a frame's and `instance` keys in the base order followed by `symbol`. The M5 envelope is unchanged: it embeds a document and `parseEnvelope` uses `validateAnyDocument`. No text override field is reserved now (M7-Q11 (a)).

## 3. Expansion and propagation

- **M7-X1 definition (M7-Q4 (c), recommended, user decision).** The expansion of instance `i` with source `s` maps the copies of `s`'s descendants by the scale `(sx, sy) = (i.width / s.width, i.height / s.height)` about the source's local origin `(0, 0)`, as a group resize does: `mapNode` on each child of `s` (an axis whose source size is 0 is not scaled), then groups refit innermost first. **Equal size:** when the scale is `(1, 1)` (the instance's width and height equal the source's, or an axis whose source size is 0 with the other axis equal), the descendants are copied unchanged and `mapNode` is not run, because at `sx = sy = 1` a rotated node would still take `approximateSize` (`resize.ts:69-90`), whose `hypot(cos θ, sin θ)` is not exactly 1, and be rebuilt from its centre. So content scales proportionally with the instance, transforms stay rigid (paths and lines map exactly, other rotated nodes take the MVP-Q3 approximation), stroke widths and corner radii are unchanged, and a frame inside the source maps like a leaf and applies its own children's constraints. The constraints of the source's direct children are not used. `s`'s own `x`, `y`, `rotation`, `constraints`, `opacity`, `visible` and `name` do not affect the expansion; `s`'s size, `fill`, `stroke` and every descendant do. **If the user picks (a):** this item instead reads "the copy of `s` takes the instance's size and its descendants follow `applyConstraints` exactly as `setFrames` on `s` would (M1 section 4.4), with the same equal-size rule"; the M7-X4 key (source node objects, source size, instance size) is unchanged, and the implementation's reuse key, which is the scale `(sx, sy)` under (c), must become the source and instance sizes, since `startEnd` and `end` margins depend on absolute sizes; M7-A02 then compares `expandInstance` with the source's descendants after `setFrames` on the source to the instance size.
- **M7-X2 derived, never stored.** The expansion is a pure function of the document in `editor-core` (`expandInstance(document, id)`). No expanded node is ever in `document.nodes`, a history entry or a saved file (ARCHITECTURE, state classification).
- **M7-X3 validity.** Every expanded node must pass `validateNode` and, for a custom node, its extension check (a large scale can overflow a frame to Infinity; a resized custom node can fail its `validate`). An expansion that fails is **invalid**, code `editor.invalid-expansion` with the instance's path and the failing source node. Every command (gesture updates included) checks the expansions it changes, those of an instance it resizes and those of every instance of a source it changes **on every page**, reporting the first failing instance in `pages` order, then page-tree pre-order, and fails with that code; `loadDocument` checks every expansion after the clip depth and fails the same way. So committed and live documents only hold valid expansions; consumers still treat a failure defensively: the projector excludes the instance with the diagnostic `editor.scene-rejected`, reason `invalid-value`, naming the instance, reported once until the instance projects again, hit testing hits only its background and border, `detachInstances`, a detached paste and the deletion rule's automatic detach fail the command with the code and change nothing.
- **M7-X4 cache.** One expansion cache per editor, keyed by node identity, serves the projector and hit testing: an instance's expansion is recomputed only when the instance node or a node object of its source subtree changed, checked once per symbol per document change. Within a recomputed expansion, each expanded subtree under a direct child of the source is reused when every node object of that child's source subtree, the source size and the instance size are unchanged.
- **M7-X5 propagation.** Any change to a source (its size, fill or stroke, or any descendant through any existing command, gesture, undo or redo) changes the expansion of every instance of it at the next projection; nothing is written to the instances. A gesture update inside a source is projected live into the instances on the active page.
- **M7-X6 determinism.** The expansion uses the resize code in binary64, so equal inputs give equal outputs; an instance whose size equals its source's has an expansion equal to the source's descendants field for field, by the equal-size rule of M7-X1.

## 4. Projection and hit testing

### 4.1 Scene shape and IDs

- An instance projects as a frame unit (M1 section 5) with the instance's ID, transform, visibility and opacity: outer container `i`, content `i + "\u0000content"` (rect clip `0, 0, w, h`), background `i + "\u0000background"` (the source's fill), the expanded children, then border `i + "\u0000border"` (the source's stroke). A `symbol` projects exactly as a frame.
- An expanded node with source node ID `n` gets the scene ID `i + "\u0000@" + n`; a frame inside the expansion gets its frame roles after that (`i + "\u0000@" + n + "\u0000content"`). Document IDs hold no U+0000 (M1-S4), so these IDs never collide, and `documentIdOf` already maps them to `i` (M7-Q6 (a)). Expanded scene IDs never appear in the public API; diagnostics, `touched` and hit results name the instance.
- **Cap.** The cap counts the scene nodes that instances add: each instance's own frame-role nodes (outer, content, and background and border when present) plus every expanded node and the frame-role nodes of expanded frames. At most `MAX_EXPANDED_NODES` = 100,000 per page and `MAX_EXPANDED_NODES_TOTAL` = 1,000,000 per document (both provisional, M7-Q13). A command or load that exceeds either fails with `editor.expansion-limit` at the path of the instance that crosses it, counting in `pages` order, then page-tree pre-order; nothing changes. M7-X3 validity is checked only for the instances up to and including the crossing one, so the checks never expand more than the caps allow: when a cap is crossed, an invalid expansion of a later instance is not reported (for example, with 102 instances of a 1,000-node expansion on one page, instance 101 crosses the page cap and the command fails with `editor.expansion-limit` at instance 101 even if instance 102's expansion is invalid); an invalid expansion at or before the crossing instance is still reported first (section 5.5). The total bounds the work of the M7-X3 and cap checks, which run across every page: a gesture inside a source repeats them on every pointer move, at a cost up to the expansions of every instance of that source (disclosed, M7-A10 times it).

### 4.2 Synchronization

- An instance and its whole expansion are **one unit** for isolation (M1 section 5): a rejected expansion excludes the instance.
- `change` re-projects the whole active page as now. The editor's `touched` stays the document IDs a change touched (M5's autosave and hosts read it); the projector maps a touched node that is a `symbol` or has a `symbol` ancestor to the instances of that symbol only to release them when excluded. The reverse index from symbol to instances is built in O(n), only for a change while the projector holds an exclusion and a touched node is a `symbol` or lies in one.
- Snapshot reuse follows M7-X4, and an expanded snapshot equal by value to its previous one keeps the previous object (as `keepEqual`), so one source edit sends updates only for the expanded nodes it changes.

### 4.3 Hit testing, selection and scope

- An instance is hit where any expanded node would be hit (the M1 section 6 rules in the instance's local space, inside its content clip), and on its background and border as a frame. The target is the instance itself (or its outermost ancestor below the scope, as for any leaf); expanded nodes are never targets, selected or snapped to. `boundsOf` and the `handles` query use the instance's rotated frame, which also bounds the clipped content.
- **Marquee.** An instance is a candidate as a leaf: selected when the marquee intersects its rotated frame (P5-Q5); a top-level `symbol` follows the top-level frame rule (contained entirely).
- `setScope` on an instance fails with `editor.invalid-scope`, and a double-click on it does nothing (M7-Q14 (a)). A `symbol` is entered as a frame (M2 section 5).
- Snapping (M2 section 4.2) uses an instance's frame edges and centre as for a leaf; a `symbol` counts as a frame for the candidates (section 1.2), and no expanded node is a candidate.

## 5. Commands

### 5.1 Creating sources and instances

- `createSymbol { ids }`: a non-empty list of sibling node IDs on the active page. If the list is one `frame`, that frame becomes a `symbol` in place (same ID, fields and children). Otherwise a new `symbol` wraps the nodes as `groupNodes` does (M1 section 4.3: placed at the topmost one's paint index, frame equal to their bounds in the parent space, rotation 0, `start` constraints, children keep page placement), with fill and stroke null and the name `Symbol`. Returns the symbol's ID (M7-Q3 (a)). Checks, in order: `ids` a list of distinct strings (`editor.invalid-command` at `/ids`), every node on the active page (else `editor.unknown-node`), one parent and a non-empty list (`editor.not-siblings`), then the wrap's checks as for `groupNodes` (a failure inside the new symbol has a path relative to it) and section 5.3; the conversion in place draws no ID, a wrap draws one after every other check. **Disclosed:** the wrap's frame is the nodes' geometric bounds, as `groupNodes` takes them, while a symbol clips to `{0, 0, width, height}`; so a horizontal or vertical line gives a symbol 0 high or 0 wide whose content is clipped away, and any stroke or arrow past the geometric bounds is cut off. 2026-10-29 추천안 자동 채택: geometric bounds kept; stroke-inclusive bounds deferred to the M7-U6 hands-on check (A11).
- `createInstance { symbol, frame?, rotation?, parent?, index? }`: `frame` in page space as other creating commands (M1 section 4.1); the default size is the source's own `width × height`, and the default top-left is the top-left of the source's page-aligned bounds (`boundsOf`) moved by `(bounds width + 40, 0)`, taken as coordinates on the active page even when the source is on another page; the default page rotation is 0. Name the source's name, `start` constraints, `opacity` 1. Returns the instance's ID. Checks follow the creating commands (M1 section 4.1), in order: `symbol` not a string (`editor.invalid-command` at `/symbol`); an unknown `parent` or `symbol` (`editor.unknown-node`); `symbol` not a source (`editor.not-a-symbol`); the index; the node's fields (a given `frame`, `null` included, by the model's rules; only `frame` is strict in this way: an omitted or `null` `rotation` or `index` falls back to its default through `??`, as for the other creating commands, and `parent`, when given, must be a string (`editor.invalid-command` at `/parent`)); the tree depth, the instance's own depth plus its source subtree's height (M7-S5); the parent a container; the mask source; a parent that is or lies in a `symbol` (`editor.nested-symbol`); the clip depth, as a frame and through its expansion (M7-S5); then, on a build with a placeholder ID, the expansion checks of every instance; `editor.duplicate-id` last. Failures at the new instance have paths relative to it (`/parent`, `/frame/width`), and its own `editor.invalid-expansion` or `editor.expansion-limit` carries no path.
- `setNodeProps` on an instance accepts `name`, `visible`, `opacity` (M7-S4) and `constraints`; other props are `editor.invalid-command` at `/props/<key>`, since general overrides are deferred. `setFrames` on an instance changes only its own frame.
- An instance inside a resized group or frame maps as a leaf (M1 section 4.4: centre exact, the approximation if rotated); its content then follows M7-X1, so under (c) it scales with the group.

### 5.2 Detach

`detachInstances { ids }` on instances of the active page at any depth (a listed ID that is not an instance is `editor.not-an-instance`). In one transaction each instance becomes a `frame` with the **same ID**, `name`, `frame`, `rotation`, `constraints`, `opacity` and `visible`, the source's `fill` and `stroke`, and as children copies of its expansion with fresh IDs. As in `duplicateNodes` (`packages/editor-core/src/arrange.ts:308`), every check runs on a build with placeholder IDs first, so a failed command draws no ID. **ID order** (here and for the deletion rule's detach): instances in page order (the document's `pages` order), within a page in page-tree pre-order, and each expansion in the source's pre-order. The selection is unchanged and the command returns empty `ids`. Checks, in order: `ids` a non-empty list of distinct strings (`editor.invalid-command` at `/ids`), every ID a node of the active page (`editor.unknown-node`), every node an instance (`editor.not-an-instance`, no path), each expansion (`editor.invalid-expansion` at the instance), the checks of the detached document, `editor.duplicate-id` last. The detached frame's projection equals the instance's projection with expanded scene IDs replaced by the new IDs (M7-Q7 (a)).

### 5.3 Nesting and depth

A command that would put an `instance` or a `symbol` inside a `symbol` (`moveNodes`, `groupNodes` inside a source, `createSymbol` over nodes that hold one, `createInstance` with such a parent, `paste` or `duplicateNodes` into one) fails with `editor.nested-symbol`. `duplicateNodes` and `groupNodes` keep each node in its parent's subtree and a valid source holds no `symbol` or `instance`, so neither reaches this code; a group inside a source still deepens its content and is checked by M7-S5. A command that would break M7-S5 for any instance (a frame moved into a source deepens every instance's content; an instance moved deeper) fails with `editor.clip-depth` or `document.invalid-field` (tree depth) at the first such instance in page pre-order; the check visits every instance of each changed source.

The checks run after a command's document is built, on the nodes the command **created, reparented or retyped** (a node whose `parent` or `type` differs from the document before the command, or which is new); a **changed source** is a `symbol` with such a node in its subtree. `editor.nested-symbol` names the first `symbol` or `instance` in those nodes' subtrees that has a `symbol` ancestor, in `pages` order then page-tree pre-order, at `/nodes/<id>/parent`; when that node is the one a creating command makes (`createInstance`, the symbol of a `createSymbol` wrap) the path is relative to it, `/parent`. The M7-S5 checks visit the instances in those subtrees and every instance, on every page, of each changed source, in `pages` order then page-tree pre-order: first the tree depth of each (`document.invalid-field` at `/nodes/<instance>/parent`, which the M1 order puts before every `editor.*` structural code), then, after the mask-source rule, `editor.nested-symbol` and the M1 clip depth of the moved and created subtrees, the clip depth through each (`editor.clip-depth` at `/nodes/<instance>/parent`). The depth and nesting checks visit no instance when a command creates, reparents and retypes nothing (a frame or prop edit, a path edit, a gesture update, a delete inside a source); a command that does pays one scan of the node map and one page walk on top of the instances it visits. The expansion validity and caps of sections 3 and 4.1 (`expansionFailure`) are separate: they still run over every instance on every command, as in M7-U2, the cache answering an unchanged instance by lookup. When `createSymbol` converts in place a frame that holds an instance, the node reported is that instance, not the converted frame.

### 5.4 Source deletion rule

Deleting a `symbol` by any route (`deleteNodes` of it or an ancestor, `cut`, `removePage` of its page) first detaches every remaining instance of it in the document, on every page, as `detachInstances` does, in the same transaction; then the source is removed. So no instance ever dangles, the delete is one undo step, and undo restores the source and the linked instances byte for byte (M7-Q8 (a)). An instance deleted in the same command is deleted, not detached. An automatic detach that fails (M7-X3) fails the delete. The delete's own checks come first: when an expansion to detach is invalid, the delete without the detach is checked and its failure, if any, is returned, else `editor.invalid-expansion` at the instance; then the delete with the detach is built with placeholder IDs (a failure inside a copy is reported at its source node, as `duplicateNodes` reports originals); IDs are drawn last (`editor.duplicate-id`), in the section 5.2 order. `cut` reaches this rule through its delete: the fragment is taken from the document before the delete (so a cut instance carries its source, section 6), the delete with its detach is one undo step, and the clipboard is replaced only when the delete succeeds; a failed delete, an automatic detach that fails or cannot draw its IDs included, leaves the document and the clipboard unchanged.

When several rules fail, the M1 section 4.3.1 order holds, with `editor.not-a-symbol` and `editor.not-an-instance` after the `unknown-*` codes and `editor.nested-symbol`, `editor.clip-depth`, `editor.invalid-expansion`, `editor.expansion-limit` in that order (with the one exception of section 4.1: an invalid expansion after the instance that crosses a cap is not checked, so `editor.expansion-limit` is reported), all before `editor.duplicate-id`, which stays last when a command draws IDs (M2 section 4.4, M1-U2 notes); on load, `editor.clip-depth`, `editor.invalid-expansion` and `editor.expansion-limit` follow the extension checks in that order.

## 6. Clipboard and duplication

- **Fragment v2.** `{ fragmentVersion: 2, schemaVersion: vN+1, roots, nodes, sources, sourceNodes }`, keys in that order, `sources` and `sourceNodes` always present (empty when nothing is carried). `copyFragment` carries, once each, the source of every copied instance whose source is not among the copied nodes: `sources` lists the carried source roots in page order then pre-order, and `sourceNodes` holds their subtrees, the root with parent `""` and its own local placement, in `serializeDocument` key order. A separate map lets a copied child of a source and the carried source both be present without a key collision.
- **Fragment parse order**, extending `parseFragment` (`clipboard.ts:122-135`): the marker; the JSON rules; the top-level keys: the six keys when `fragmentVersion` is the number 2, else the four keys (missing before unknown, `editor.invalid-clipboard` at `/<key>`); `fragmentVersion`: any value other than the numbers 1 and 2 (for example `3`, `"2"` or `null`) is `editor.invalid-clipboard` at `/fragmentVersion`; `roots`; `nodes`; then for version 2 `sources` (an array, else `editor.invalid-clipboard` at `/sources`; its entries distinct IDs, each a key of `sourceNodes`, which must then be an object, none a key of `nodes`, else `editor.invalid-clipboard` at `/sources/<k>`) and `sourceNodes` (an object, else at `/sourceNodes`; so a `sourceNodes` that is not an object fails at `/sources/0` when `sources` is not empty); `schemaVersion` (fragment version 1 at 2 to vN, version 2 only at vN+1, else `document.unsupported-version` at `/schemaVersion`); each node's field rules in `nodes` then `sourceNodes` (a repeated key in either map is `document.duplicate-id` at `/<map>/<id>` by the JSON rules; a fragment version 1 node of type `symbol` or `instance` is `document.invalid-field` at `/nodes/<id>/type`, before its other fields); the reference rules for `nodes` (as now) and then for `sourceNodes` (every carried root a `symbol`, else `editor.invalid-clipboard` at `/sourceNodes/<id>/type`, with parent `""`, every other node claimed once and reachable from one carried root, with the paths of the `nodes` rules under `/sourceNodes`); **M7-S3 nesting** in both maps (`document.invalid-symbol`; `nodes` then `sourceNodes`, each in map entry order); **instance references**: every instance in `nodes` names a `symbol` in the roots' subtrees or a carried source (a carried descendant or a copied node of another type does not count), else `editor.invalid-clipboard` at `/nodes/<id>/symbol`; the model's tree rules on **two holder documents**, first `nodes` on a holder page holding the roots (failures at `/nodes/...`), then `sourceNodes` on a second holder page holding the carried roots (failures at `/sourceNodes/...`), never one merged node map, so a node in both maps does not collide; both runs use a separately named model export, `validateFragmentTree(value)`, which returns a node map or a failure, never a document type, and is documented as skipping only M7-S2 and M7-S5 (M7-S3 nesting, the rejection of text inside sources and the base tree depth still run); `parseDocument`, `validateDocument`, `validateAnyDocument` and `parseEnvelope` take no such option. The two rules are skipped because the fragment rule above resolves instance references and the paste checks depth in the target (section 5.3); the extension checks in ID order, `nodes` then `sourceNodes`. Paths are into the fragment JSON.
- **Versions.** A fragment version 1 at schemaVersion 2 to vN is read by wrapping its nodes in a synthetic holder document and running the document migration chain to vN+1; when every bump between its version and vN+1 changed only the version, as M7's does, the nodes are read unchanged instead. Later bumps use the same wrapper, so no node-level migration API is added; M6-T5 in the M6 plan should follow the same rule. An older build rejects a v2 fragment with `editor.invalid-clipboard` (its key and `fragmentVersion` checks run first, `clipboard.ts:156-163`); disclosed.
- **Paste of an instance.** If its source is in the same fragment's roots' subtrees, the copy refers to the pasted source. Otherwise it is **linked** to the carried source's ID when the target document has a `symbol` with that ID and either (1) the paste comes from this editor's own clipboard (no `text`, or `text` equal to the in-memory clipboard) and the editor's **clipboard generation**, a session counter that `loadDocument` increments and `copy` and `cut` record with the text, is unchanged since the copy (`loadDocument` does not clear the clipboard today, M2 section 6), or (2) that symbol's size, `fill`, `stroke` and descendants serialize equal to the carried subtree (canonical `serializeDocument` text of the subtree with the root's `name`, `x`, `y`, `rotation`, `constraints`, `opacity` and `visible` left out; its `children` and every descendant field, IDs and names included, count); otherwise it is **pasted detached** (a frame, as section 5.2, from the carried subtree: the expansion of the instance's size against the carried source) (M7-Q9 (a)). Rule (1) holds for a paste without `text` and for one whose `text` equals the in-memory clipboard; the generation is 0 when the editor is constructed and only a successful `loadDocument` increments it. A detached paste is built like the rest of the paste: the trial with placeholder IDs first, with an instance whose expansion is invalid built as an empty frame, so the paste's own failures come first; then `editor.invalid-expansion` at the instance's fragment path `/nodes/<id>`; a failure inside a pasted copy is reported at its fragment path (`/nodes/<id>...`), inside an expansion copy at its carried node (`/sourceNodes/<id>...`). **Detached caps.** A detached instance becomes a frame, so the section 4.1 caps would not count it; to bound the work a hostile fragment can cause, each detached instance, in fragment order (each root in pre-order), adds the scene nodes it would add as an instance of its carried source (section 4.1 count) to the expanded nodes of the active page's instances and of the document's, and the first that takes either above `MAX_EXPANDED_NODES` or `MAX_EXPANDED_NODES_TOTAL` fails the paste with `editor.expansion-limit` at `/nodes/<id>` of the fragment, after the parse and before any expansion or build, so no later instance is expanded and no ID is drawn; linked and copied instances are counted by the section 4.1 check of the built document as for any command. The detached cap bounds each paste, not the document: the frames of earlier detached pastes are plain frames and are not counted. A carried source that no instance names is read and checked with the fragment and otherwise ignored. Rule (1) needs the carried ID to name the same node it named at the copy. The default `createCounterIdSource` (`packages/editor-core/src/ids.ts:4`) never returns an ID twice, but `drawIds` only skips IDs present at the time, so an ID freed by a delete (or a loaded `node-N`) can name an unrelated node later; so `copy` and `cut` record the fragment's carried source IDs, and an ID the editor's ID source returns after the copy to any command or gesture, and the draw accepts (an ID is accepted when the document it was drawn on does not hold it: a command's base, a gesture update's live document, or the document a replace step received; an ID that document holds is skipped and stays linkable), is no longer linkable by rule (1) and goes by rule (2); a gesture's drawn IDs include those of updates its commit discarded, which errs on the safe side. Each history step records the IDs its command or gesture drew; an undo or redo of the step removes them from the link set as well, since the nodes under them change (a step's created node returns or leaves under the same ID), so an undo or redo that restores another node under a carried ID falls back to rule (2); a step that drew none of the carried IDs (for example the delete of the source, which draws only its detach IDs) keeps the link. Rule (1) applies only with the default ID source; with a host-supplied ID source (`ids`, `packages/editor-core/src/editor.ts:97`) linking goes by rule (2) alone. A content match is needed across documents because document IDs repeat (section 1.1). **IDs** are drawn as in an M2 paste (fragment order, each root in pre-order), and a detached instance's expansion IDs follow the instance's own ID in the source's pre-order.
- **Paste or duplicate of a source** creates a new, independent `symbol` with fresh IDs; instances of the original are unchanged (M7-Q10 (a)). `duplicateNodes` and Alt-drag of an instance create a new instance of the same source. When a source and an instance of it are duplicated or pasted together, the copied instance refers to the copied source, as for paste.
- Paste or duplication of anything that would land inside a `symbol` follows section 5.3.
- **Disclosures.** (1) Copying an instance, editing its source and pasting the text into another tab of the same document, or after a reload, gives a detached frame (rule (1) covers only this editor's clipboard). (2) A source can only reach another page by cut and paste, since `moveNodes` stays on one page: the cut detaches every instance (section 5.4) and the pasted source has no instances.

## 7. Persistence round trip

`parse(serialize(d))` deep-equals `d` and re-serializes byte-identically for every vN+1 fixture with sources and instances on two pages, instances of a source on another page and a detached frame; the same holds through `serializeEnvelope` and `parseEnvelope` (M5). The headed spec of M7-A11 reloads such a document with `?persist=1`. Expansions are never written, so a saved file's size does not grow with instance content.

## 8. Text in symbols (deferred until M6a)

Requirements: "Instance text content may differ from the source." Schema v2 has no text node, and the [M6 text plan](https://github.com/npclown/vector-studio/pull/350) (draft, PR #350) puts the text node, its runs and its layout port in an M6a contract and says M7's override replaces `runs`. Until an M7 addendum (Full tier) is approved after the M6a contract merges, a text node inside a source, and an instance of a source holding one, are rejected (`document.invalid-symbol` on load, `editor.nested-symbol` in commands, as M7-S3), so the expansion stays a pure function of the document; whichever of M7-U1 and the M6a implementation merges second adds that rejection. The addendum fixes: (1) text nodes inside sources and their expansion, which needs the layout port because M6-T3 recomputes auto width and height through it (the expansion then depends on the port and its font generation, and the cache of M7-X4 adds that key); (2) how M7-X1 maps text (size, wrapping width) when an instance is scaled; (3) the override field on `instance`, keyed by the source's text node ID, its schema bump, its command, how detach and paste copy it, and what happens when the source's text node is removed. Unit M7-U7 implements it. Whether it waits for later M6 units is the user's M6-Q1 decision there. M7-U1 to M7-U6 do not depend on text.

Pointer, 2026-10-29: the addendum is [section 9 of the M6a contract](mvp-m6a-text-model-contract.md#9-m7-addendum-text-in-symbols) (M7-T1 to M7-T3), approved when that contract is approved; this section keeps ownership of its rules for M7.

## 9. Performance

M7 makes no performance claim; claims belong to M9 ([benchmarks README](../benchmarks/README.md)). An expansion adds scene nodes: a page with 100 instances of a 100-node source projects about 10,000 scene nodes from about 200 document nodes, and the renderer holds one copy of each expanded path mesh per instance. A source edit re-expands only the changed subtrees of each instance (M7-X4), on top of the projector's O(n) page walk and the O(n) reverse index. M7-A10 times this as an observation, as M1-A13 did. M7-Q13 (a) asks M9 to count scene nodes, so the 10,000-node target covers instance-heavy pages, and sets the provisional cap of section 4.1.

## 12. Risks

- **Propagation cost.** A source edit re-expands the changed subtree of every instance; a symbol used hundreds of times may slow typical edits before M9 measures it (M7-A10 is the early look). N instances mean N copies of each path mesh in the renderer.
- **Instance scaling** (M7-Q4): under (c) users cannot pin a child's size inside an instance; resizing the source (a frame) moves its children by their constraints, so with `start` constraints widening a source from 100 to 200 leaves its content in place and every 100-wide instance, now at `sx = 0.5`, halves its content; and a detached instance is a frame, so the same resize drag behaves differently before and after detach. Under (a) a default instance resize shows empty space.
- **Paste linking** (section 6) detaches a cross-tab or post-reload paste after the source changed, and could link to an unrelated source with the same ID and equal content (harmless: the content is equal).
- **Schema churn and ordering** with M4 and M6a, which may bump first; vN stays a variable until M7-U1 starts.
- **Disclosed P3 and P4 defects** (cracks, A04, large masks) repeat once per instance.

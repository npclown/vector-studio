## 1. Scope

In scope: a symbol source node (`symbol`), a frame-like container that lives on a page and is edited with the existing commands; an instance node (`instance`) that refers to one source and has its own placement and size; the expansion of an instance from its source, derived for projection, hit testing and detach, never stored; propagation of every source change to its instances; `createSymbol`, `createInstance` and `detachInstances`; the source deletion rule; the nesting rule that rejects instances and sources inside a source; clipboard copy, paste and duplication of sources and instances, within a document and across documents; a schema bump with a migration; a persistence round trip; a next-host page and headed spec; a performance observation.

Out of scope (deferred by requirements or by this contract): nested instances (an instance inside a source), variants and general property overrides (requirements, Symbols); instance text override and text nodes inside sources until text exists (section 8); swapping an instance's source; "go to source" navigation; turning a source back into a frame; a command that moves nodes to another page; symbol libraries shared between documents; instance opacity other than 1 until the container opacity rule allows it (M7-S4); property-panel symbol controls (M8). M7 makes no performance claim (section 9).

## 2. Schema

The bump is from vN to vN+1, vN being the latest `schemaVersion` when M7-U1 starts: 2 today, higher if M4 or M6a bumps first (MVP-Q2 (a)).

```ts
type SymbolNode = NodeBaseV2 & { type: 'symbol'; children: string[]; fill: Color | null; stroke: RectStroke | null };
type InstanceNode = NodeBaseV2 & { type: 'instance'; symbol: string };   // no children, fill or stroke
```

- **M7-S1 source.** A `symbol` has the fields of a `frame` and is a container: its children are in its local space, it may be empty, and it clips to `{0, 0, width, height}`. It may be anywhere on any page except inside another `symbol` (M7-S3). The page that holds it owns it; instances on other pages refer to it across pages (M7-Q1 (a), M7-Q2 (a)).
- **M7-S2 instance.** An `instance` is a leaf in the document tree; `symbol` names a `symbol` node of the same document, on any page. Its `frame`, `rotation`, `constraints`, `opacity`, `visible` and `name` are its own (requirements: "independent placement and size"); its content is the expansion of section 3. A `symbol` that names no node is `document.dangling-reference` at `/nodes/<id>/symbol`; one that names a node of another type is `document.invalid-symbol` (new) at the same path.
- **M7-S3 nesting.** No `instance` and no `symbol` has a `symbol` ancestor (`document.invalid-symbol` at `/nodes/<id>/parent`). Because an instance's content comes only from a source and no source holds an instance, an instance can never contain itself, directly or through other instances, so no cycle check over `symbol` references is needed (M7-Q5 (a)).
- **M7-S4 opacity.** An instance projects as a container (section 4), so its `opacity` follows the container rule in force: the model gains an explicit check that an instance's opacity is 1 (`document.invalid-field` at `/nodes/<id>/opacity`, since `parse.ts:528` covers container types only), until M4 lifts the rule for containers and instances together.
- **M7-S5 depth through an expansion.** An expanded node's tree depth is the instance's tree depth plus one plus its depth below the source; its clip depth is the instance's clip depth plus one plus the clip levels that frames and mask groups add between the source and the node. **Tree depth** is checked by the model, after M7-S3, against `MAX_TREE_DEPTH` (256): `document.invalid-field` at `/nodes/<instance>/parent`. **Clip depth** is checked by `editor-core` on load after the extension checks, extending `documentClipViolation`: `editor.clip-depth` at `/nodes/<instance>/parent`. Commands check both as in section 5.3.
- Unknown fields stay rejected. Model check order: `readDocumentV2` as now, with M7-S2 after ownership, then the cycle walk, M7-S3, the M7-S5 tree depth, then the group and mask rules.

### 2.1 Migration and versions

`migrate(vN -> vN+1)` rewrites `schemaVersion` only, since no existing node changes (M7-Q12 (a)); every committed vN fixture migrates byte for byte to its committed vN+1 text, and an older build fails a vN+1 document with `document.unsupported-version`. The P5 and M1 `malformed/unsupported-version.json` fixtures (`schemaVersion: 3` today) move to vN+2. `serializeDocument` writes `symbol` keys as a frame's and `instance` keys in the base order followed by `symbol`. The M5 envelope is unchanged: it embeds a document and `parseEnvelope` uses `validateAnyDocument`. No text override field is reserved now (M7-Q11 (a)).

## 3. Expansion and propagation

- **M7-X1 definition (M7-Q4 (c), recommended, user decision).** The expansion of instance `i` with source `s` maps the copies of `s`'s descendants by the scale `(sx, sy) = (i.width / s.width, i.height / s.height)` about the source's local origin `(0, 0)`, as a group resize does: `mapNode` on each child of `s` (an axis whose source size is 0 is not scaled), then groups refit innermost first. **Equal size:** when the instance's width and height equal the source's, the descendants are copied unchanged and `mapNode` is not run, because at `sx = sy = 1` a rotated node would still take `approximateSize` (`resize.ts:69-90`), whose `hypot(cos θ, sin θ)` is not exactly 1, and be rebuilt from its centre. So content scales proportionally with the instance, transforms stay rigid (paths and lines map exactly, other rotated nodes take the MVP-Q3 approximation), stroke widths and corner radii are unchanged, and a frame inside the source maps like a leaf and applies its own children's constraints. The constraints of the source's direct children are not used. `s`'s own `x`, `y`, `rotation`, `constraints`, `opacity`, `visible` and `name` do not affect the expansion; `s`'s size, `fill`, `stroke` and every descendant do. **If the user picks (a):** this item instead reads "the copy of `s` takes the instance's size and its descendants follow `applyConstraints` exactly as `setFrames` on `s` would (M1 section 4.4), with the same equal-size rule"; the M7-X4 key (source node objects, source size, instance size) is unchanged; M7-A02 then compares `expandInstance` with the source's descendants after `setFrames` on the source to the instance size.
- **M7-X2 derived, never stored.** The expansion is a pure function of the document in `editor-core` (`expandInstance(document, id)`). No expanded node is ever in `document.nodes`, a history entry or a saved file (ARCHITECTURE, state classification).
- **M7-X3 validity.** Every expanded node must pass `validateNode` and, for a custom node, its extension check (a large scale can overflow a frame to Infinity; a resized custom node can fail its `validate`). An expansion that fails is **invalid**, code `editor.invalid-expansion` with the instance's path and the failing source node. Every command (gesture updates included) checks the expansions it changes, those of an instance it resizes and those of every instance of a source it changes **on every page**, reporting the first failing instance in `pages` order, then page-tree pre-order, and fails with that code; `loadDocument` checks every expansion after the clip depth and fails the same way. So committed and live documents only hold valid expansions; consumers still treat a failure defensively: the projector excludes the instance with a diagnostic, hit testing hits only its background and border, `detachInstances`, a detached paste and the deletion rule's automatic detach fail the command with the code and change nothing.
- **M7-X4 cache.** One expansion cache per editor, keyed by node identity, serves the projector and hit testing: an instance's expansion is recomputed only when the instance node or a node object of its source subtree changed, checked once per symbol per document change. Within a recomputed expansion, each expanded subtree under a direct child of the source is reused when every node object of that child's source subtree, the source size and the instance size are unchanged.
- **M7-X5 propagation.** Any change to a source (its size, fill or stroke, or any descendant through any existing command, gesture, undo or redo) changes the expansion of every instance of it at the next projection; nothing is written to the instances. A gesture update inside a source is projected live into the instances on the active page.
- **M7-X6 determinism.** The expansion uses the resize code in binary64, so equal inputs give equal outputs; an instance whose size equals its source's has an expansion equal to the source's descendants field for field, by the equal-size rule of M7-X1.

## 4. Projection and hit testing

### 4.1 Scene shape and IDs

- An instance projects as a frame unit (M1 section 5) with the instance's ID, transform, visibility and opacity: outer container `i`, content `i + "\u0000content"` (rect clip `0, 0, w, h`), background `i + "\u0000background"` (the source's fill), the expanded children, then border `i + "\u0000border"` (the source's stroke). A `symbol` projects exactly as a frame.
- An expanded node with source node ID `n` gets the scene ID `i + "\u0000@" + n`; a frame inside the expansion gets its frame roles after that (`i + "\u0000@" + n + "\u0000content"`). Document IDs hold no U+0000 (M1-S4), so these IDs never collide, and `documentIdOf` already maps them to `i` (M7-Q6 (a)). Expanded scene IDs never appear in the public API; diagnostics, `touched` and hit results name the instance.
- **Cap.** The cap counts the scene nodes that instances add: each instance's own frame-role nodes (outer, content, and background and border when present) plus every expanded node and the frame-role nodes of expanded frames. At most `MAX_EXPANDED_NODES` = 100,000 per page and `MAX_EXPANDED_NODES_TOTAL` = 1,000,000 per document (both provisional, M7-Q13). A command or load that exceeds either fails with `editor.expansion-limit` at the path of the instance that crosses it, counting in `pages` order, then page-tree pre-order; nothing changes. The total bounds the work of the M7-X3 and cap checks, which run across every page: a gesture inside a source repeats them on every pointer move, at a cost up to the expansions of every instance of that source (disclosed, M7-A10 times it).

### 4.2 Synchronization

- An instance and its whole expansion are **one unit** for isolation (M1 section 5): a rejected expansion excludes the instance.
- `change` re-projects the whole active page as now. The editor's `touched` stays the document IDs a change touched (M5's autosave and hosts read it); the projector maps a touched node that is a `symbol` or has a `symbol` ancestor to the instances of that symbol only to release them when excluded. The reverse index from symbol to instances is rebuilt in O(n) per document change.
- Snapshot reuse follows M7-X4, and an expanded snapshot equal by value to its previous one keeps the previous object (as `keepEqual`), so one source edit sends updates only for the expanded nodes it changes.

### 4.3 Hit testing, selection and scope

- An instance is hit where any expanded node would be hit (the M1 section 6 rules in the instance's local space, inside its content clip), and on its background and border as a frame. The target is the instance itself (or its outermost ancestor below the scope, as for any leaf); expanded nodes are never targets, selected or snapped to. `boundsOf` and the `handles` query use the instance's rotated frame, which also bounds the clipped content.
- **Marquee.** An instance is a candidate as a leaf: selected when the marquee intersects its rotated frame (P5-Q5); a top-level `symbol` follows the top-level frame rule (contained entirely).
- `setScope` on an instance fails with `editor.invalid-scope`, and a double-click on it does nothing (M7-Q14 (a)). A `symbol` is entered as a frame (M2 section 5).
- Snapping (M2 section 4.2) uses an instance's frame edges and centre as for a leaf.

## 5. Commands

### 5.1 Creating sources and instances

- `createSymbol { ids }`: a non-empty list of sibling node IDs on the active page. If the list is one `frame`, that frame becomes a `symbol` in place (same ID, fields and children). Otherwise a new `symbol` wraps the nodes as `groupNodes` does (M1 section 4.3: placed at the topmost one's paint index, frame equal to their bounds in the parent space, rotation 0, `start` constraints, children keep page placement), with fill and stroke null and the name `Symbol`. Returns the symbol's ID (M7-Q3 (a)).
- `createInstance { symbol, frame?, rotation?, parent?, index? }`: `frame` in page space as other creating commands (M1 section 4.1); the default size is the source's own `width × height`, and the default top-left is the top-left of the source's page-aligned bounds (`boundsOf`) moved by `(bounds width + 40, 0)`, taken as coordinates on the active page even when the source is on another page; the default page rotation is 0. Name the source's name, `start` constraints, `opacity` 1. Returns the instance's ID.
- `setNodeProps` on an instance accepts `name`, `visible`, `opacity` (M7-S4) and `constraints`; other props are `editor.invalid-command` at `/props/<key>`, since general overrides are deferred. `setFrames` on an instance changes only its own frame.
- An instance inside a resized group or frame maps as a leaf (M1 section 4.4: centre exact, the approximation if rotated); its content then follows M7-X1, so under (c) it scales with the group.

### 5.2 Detach

`detachInstances { ids }` on instances of the active page at any depth (a listed ID that is not an instance is `editor.not-an-instance`). In one transaction each instance becomes a `frame` with the **same ID**, `name`, `frame`, `rotation`, `constraints`, `opacity` and `visible`, the source's `fill` and `stroke`, and as children copies of its expansion with fresh IDs. As in `duplicateNodes` (`packages/editor-core/src/arrange.ts:308`), every check runs on a build with placeholder IDs first, so a failed command draws no ID. **ID order** (here and for the deletion rule's detach): instances in page order (the document's `pages` order), within a page in page-tree pre-order, and each expansion in the source's pre-order. The selection is unchanged. The detached frame's projection equals the instance's projection with expanded scene IDs replaced by the new IDs (M7-Q7 (a)).

### 5.3 Nesting and depth

A command that would put an `instance` or a `symbol` inside a `symbol` (`moveNodes`, `groupNodes` inside a source, `createSymbol` over nodes that hold one, `createInstance` with such a parent, `paste` or `duplicateNodes` into one) fails with `editor.nested-symbol`. A command that would break M7-S5 for any instance (a frame moved into a source deepens every instance's content; an instance moved deeper) fails with `editor.clip-depth` or `document.invalid-field` (tree depth) at the first such instance in page pre-order; the check visits every instance of each changed source.

### 5.4 Source deletion rule

Deleting a `symbol` by any route (`deleteNodes` of it or an ancestor, `cut`, `removePage` of its page) first detaches every remaining instance of it in the document, on every page, as `detachInstances` does, in the same transaction; then the source is removed. So no instance ever dangles, the delete is one undo step, and undo restores the source and the linked instances byte for byte (M7-Q8 (a)). An instance deleted in the same command is deleted, not detached. An automatic detach that fails (M7-X3) fails the delete.

### 5.5 Failure codes

| Code | When |
| --- | --- |
| `document.invalid-symbol` | M7-S2 (a `symbol` reference to a non-source) or M7-S3 (nesting), on load |
| `editor.not-a-symbol` | `createInstance` whose `symbol` names a node that is not a `symbol` (an unknown ID is `editor.unknown-node`) |
| `editor.not-an-instance` | `detachInstances` with an ID that is not an instance |
| `editor.nested-symbol` | Section 5.3 |
| `editor.invalid-expansion` | M7-X3 |
| `editor.expansion-limit` | Section 4.1 cap |
| `editor.invalid-scope` | `setScope` on an instance (existing code) |

`createSymbol` reuses `editor.not-siblings` and the M1 grouping codes. When several rules fail, the M1 section 4.3.1 order holds, with `editor.not-a-symbol` and `editor.not-an-instance` after the `unknown-*` codes and `editor.nested-symbol`, `editor.clip-depth`, `editor.invalid-expansion`, `editor.expansion-limit` in that order, all before `editor.duplicate-id`, which stays last when a command draws IDs (M2 section 4.4, M1-U2 notes); on load, `editor.clip-depth`, `editor.invalid-expansion` and `editor.expansion-limit` follow the extension checks in that order.

## 6. Clipboard and duplication

- **Fragment v2.** `{ fragmentVersion: 2, schemaVersion: vN+1, roots, nodes, sources, sourceNodes }`, keys in that order, `sources` and `sourceNodes` always present (empty when nothing is carried). `copyFragment` carries, once each, the source of every copied instance whose source is not among the copied nodes: `sources` lists the carried source roots in page order then pre-order, and `sourceNodes` holds their subtrees, the root with parent `""` and its own local placement, in `serializeDocument` key order. A separate map lets a copied child of a source and the carried source both be present without a key collision.
- **Fragment parse order**, extending `parseFragment` (`clipboard.ts:122-135`): the marker; the JSON rules; the top-level keys: the six keys when `fragmentVersion` is the number 2, else the four keys (missing before unknown, `editor.invalid-clipboard` at `/<key>`); `fragmentVersion`: any value other than the numbers 1 and 2 (for example `3`, `"2"` or `null`) is `editor.invalid-clipboard` at `/fragmentVersion`; `roots`; `nodes`; then for version 2 `sources` (an array of distinct IDs, each a key of `sourceNodes`, none a key of `nodes`, else `editor.invalid-clipboard` at `/sources/<k>`) and `sourceNodes` (an object); `schemaVersion` (fragment version 1 at 2 to vN, version 2 only at vN+1, else `document.unsupported-version` at `/schemaVersion`); each node's field rules in `nodes` then `sourceNodes`; the reference rules for `nodes` (as now) and for `sourceNodes` (every carried root a `symbol` with parent `""`, every other node claimed once and reachable from one carried root); **M7-S3 nesting** in both maps (`document.invalid-symbol`); **instance references**: every instance in `nodes` names a `symbol` in the roots' subtrees or a carried source, else `editor.invalid-clipboard` at `/nodes/<id>/symbol`; the model's tree rules on **two holder documents**, first `nodes` on a holder page holding the roots (failures at `/nodes/...`), then `sourceNodes` on a second holder page holding the carried roots (failures at `/sourceNodes/...`), never one merged node map, so a node in both maps does not collide; both runs use a separately named model export, `validateFragmentTree(value)`, which returns a node map or a failure, never a document type, and is documented as skipping only M7-S2 and M7-S5 (M7-S3 nesting, the rejection of text inside sources and the base tree depth still run); `parseDocument`, `validateDocument`, `validateAnyDocument` and `parseEnvelope` take no such option. The two rules are skipped because the fragment rule above resolves instance references and the paste checks depth in the target (section 5.3); the extension checks in ID order, `nodes` then `sourceNodes`. Paths are into the fragment JSON.
- **Versions.** A fragment version 1 at schemaVersion 2 to vN is read by wrapping its nodes in a synthetic holder document and running the document migration chain to vN+1; when every bump between its version and vN+1 changed only the version, as M7's does, the nodes are read unchanged instead. Later bumps use the same wrapper, so no node-level migration API is added; M6-T5 in the M6 plan should follow the same rule. An older build rejects a v2 fragment with `editor.invalid-clipboard` (its key and `fragmentVersion` checks run first, `clipboard.ts:156-163`); disclosed.
- **Paste of an instance.** If its source is in the same fragment's roots' subtrees, the copy refers to the pasted source. Otherwise it is **linked** to the carried source's ID when the target document has a `symbol` with that ID and either (1) the paste comes from this editor's own clipboard (no `text`, or `text` equal to the in-memory clipboard) and the editor's **clipboard generation**, a session counter that `loadDocument` increments and `copy` and `cut` record with the text, is unchanged since the copy (`loadDocument` does not clear the clipboard today, M2 section 6), or (2) that symbol's size, `fill`, `stroke` and descendants serialize equal to the carried subtree; otherwise it is **pasted detached** (a frame, as section 5.2, from the carried subtree) (M7-Q9 (a)). Rule (1) assumes the editor's ID source never reuses an ID, which holds for the default `createCounterIdSource` (`packages/editor-core/src/ids.ts:4`), so it applies only with the default ID source; with a host-supplied ID source (`ids`, `packages/editor-core/src/editor.ts:97`) linking goes by rule (2) alone. A content match is needed across documents because document IDs repeat (section 1.1). **IDs** are drawn as in an M2 paste (fragment order, each root in pre-order), and a detached instance's expansion IDs follow the instance's own ID in the source's pre-order.
- **Paste or duplicate of a source** creates a new, independent `symbol` with fresh IDs; instances of the original are unchanged (M7-Q10 (a)). `duplicateNodes` and Alt-drag of an instance create a new instance of the same source. When a source and an instance of it are duplicated or pasted together, the copied instance refers to the copied source, as for paste.
- Paste or duplication of anything that would land inside a `symbol` follows section 5.3.
- **Disclosures.** (1) Copying an instance, editing its source and pasting the text into another tab of the same document, or after a reload, gives a detached frame (rule (1) covers only this editor's clipboard). (2) A source can only reach another page by cut and paste, since `moveNodes` stays on one page: the cut detaches every instance (section 5.4) and the pasted source has no instances.

## 7. Persistence round trip

`parse(serialize(d))` deep-equals `d` and re-serializes byte-identically for every vN+1 fixture with sources and instances on two pages, instances of a source on another page and a detached frame; the same holds through `serializeEnvelope` and `parseEnvelope` (M5). The headed spec of M7-A11 reloads such a document with `?persist=1`. Expansions are never written, so a saved file's size does not grow with instance content.

## 8. Text in symbols (deferred until M6a)

Requirements: "Instance text content may differ from the source." Schema v2 has no text node, and the [M6 text plan](https://github.com/npclown/vector-studio/pull/350) (draft, PR #350) puts the text node, its runs and its layout port in an M6a contract and says M7's override replaces `runs`. Until an M7 addendum (Full tier) is approved after the M6a contract merges, a text node inside a source, and an instance of a source holding one, are rejected (`document.invalid-symbol` on load, `editor.nested-symbol` in commands, as M7-S3), so the expansion stays a pure function of the document; whichever of M7-U1 and the M6a implementation merges second adds that rejection. The addendum fixes: (1) text nodes inside sources and their expansion, which needs the layout port because M6-T3 recomputes auto width and height through it (the expansion then depends on the port and its font generation, and the cache of M7-X4 adds that key); (2) how M7-X1 maps text (size, wrapping width) when an instance is scaled; (3) the override field on `instance`, keyed by the source's text node ID, its schema bump, its command, how detach and paste copy it, and what happens when the source's text node is removed. Unit M7-U7 implements it. Whether it waits for later M6 units is the user's M6-Q1 decision there. M7-U1 to M7-U6 do not depend on text.

## 9. Performance

M7 makes no performance claim; claims belong to M9 ([benchmarks README](../benchmarks/README.md)). An expansion adds scene nodes: a page with 100 instances of a 100-node source projects about 10,000 scene nodes from about 200 document nodes, and the renderer holds one copy of each expanded path mesh per instance. A source edit re-expands only the changed subtrees of each instance (M7-X4), on top of the projector's O(n) page walk and the O(n) reverse index. M7-A10 times this as an observation, as M1-A13 did. M7-Q13 (a) asks M9 to count scene nodes, so the 10,000-node target covers instance-heavy pages, and sets the provisional cap of section 4.1.

## 12. Risks

- **Propagation cost.** A source edit re-expands the changed subtree of every instance; a symbol used hundreds of times may slow typical edits before M9 measures it (M7-A10 is the early look). N instances mean N copies of each path mesh in the renderer.
- **Instance scaling** (M7-Q4): under (c) users cannot pin a child's size inside an instance; resizing the source (a frame) moves its children by their constraints, so with `start` constraints widening a source from 100 to 200 leaves its content in place and every 100-wide instance, now at `sx = 0.5`, halves its content; and a detached instance is a frame, so the same resize drag behaves differently before and after detach. Under (a) a default instance resize shows empty space.
- **Paste linking** (section 6) detaches a cross-tab or post-reload paste after the source changed, and could link to an unrelated source with the same ID and equal content (harmless: the content is equal).
- **Schema churn and ordering** with M4 and M6a, which may bump first; vN stays a variable until M7-U1 starts.
- **Disclosed P3 and P4 defects** (cracks, A04, large masks) repeat once per instance.

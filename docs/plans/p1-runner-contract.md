## Functional profile and records

The new root `pnpm benchmark:p1` command is deliberately functional-only in P1.6a. It requires `--profile functional`, rejects acceptance/reference profiles before build or browser launch, runs a production build and serial headless Chrome/Edge functional cases. Four scenarios run with the exact reference population, surface (1280x720, DPR 1) and required 4x sample count. No reduced object count or fallback is silently accepted.

Each case runs three warm-up callbacks followed by five observed callbacks, not the reference 5-second/10-second/five-repetition protocol. Start/end observations derive from those explicit frame boundaries. This short profile checks generator, instrumentation, record and cleanup behavior only. Its RAF numbers are diagnostic and cannot PASS A08. A05 upload observations do not establish unobserved CPU geometry rebuilds or complete A05 production acceptance. Complete reference windows are verified with synthetic numeric fixtures only; no reference benchmark is executed in this checkpoint.

Records contain the full configuration and hash, source revision and file hashes, exact command/profile, browser/OS/adapter/limits/flags, dimensions/sample count, every callback and native write range, diagnostics/visibility/error observations and disposal statistics. CPU memory, physical presentation and CPU rebuild observations use explicit unavailable reasons rather than zero. All records label P1 acceptance UNVERIFIED. Power/refresh/background/driver fields state unobserved where functional scope does not collect them. Writes use a fresh exclusive directory outside `test-results`; repeat paths fail without replacing artifacts. The result writer must reject inconsistent counts, evidence and source drift.

## 2. Schema (vN+1)

```ts
type TextRun = Readonly<{ text: string; family: string; size: number; color: Color }>;
type TextNode = NodeBaseV2 & Readonly<{
  type: 'text';
  runs: readonly TextRun[];
  sizing: 'autoWidth' | 'autoHeight' | 'fixed';
  align: 'left' | 'center' | 'right';
  letterSpacing: number;   // em of each run's size
  lineHeight: number;      // multiple of each run's size (CSS unitless)
}>;
```

- **M6a-S1 content (M6-T1).** The node text is the concatenation of the run texts, in UTF-16. LF (U+000A) separates paragraphs and is the only control character. Rejected at `/nodes/<id>/runs/<k>/text`, `document.invalid-field`: every other C0 and C1 control (CR, tab and U+0085 included; DEL U+007F is not a C0 or C1 control and is accepted, as E28-S2 allows); U+2028 and U+2029; the bidi controls U+200E, U+200F, U+061C, U+202A to U+202E and U+2066 to U+2069; a lone surrogate. A run boundary may not split a surrogate pair; each run's text is checked alone. U+00AD stays allowed and never hyphenates (section 4). Strong RTL characters and joining scripts are accepted but degraded in the MVP (laid out in logical order left to right by `bidi-override`, section 4, and rasterized per cluster; disclosed, plan section 1).
- **M6a-S2 runs (M6-T2).** At least one run (an empty array is at `/nodes/<id>/runs`); a run with empty `text` only when it is the only run (an empty node keeps one style); two adjacent runs never have equal `family`, `size` and `color` (equal by value): `document.invalid-field` at `/nodes/<id>/runs/<k>`, `k` the later run of the pair or the empty run.
- **M6a-S3 fields.** `family`: one family name, 1 to 128 UTF-16 units, no control character, no lone surrogate, never a CSS list (text-dom quotes and escapes it, section 4). Only C0 and C1 controls (U+0000 to U+001F and U+0080 to U+009F) and lone surrogates are excluded, so U+2028, U+2029 and the bidi controls are accepted in a family name; text-dom (M6a-U4) quotes the name and CSS-escapes every character of it, so none of them can break the font shorthand. `size`: finite, `0 < size ≤ 4096` page units in the document (E28-S2's range); commands that **author** a size accept only `0.5 ≤ size` (M6a-Q19, section 6.1), while sizes derived by group scale, the `scale` constraint, `map` handles or an expansion may go below 0.5. `color`: the model's `Color`, straight alpha in `[0, 1]` (M6a-Q9). `letterSpacing`: finite, `−1 ≤ v ≤ 10`. `lineHeight`: finite, `0.1 ≤ v ≤ 10`. `sizing` and `align` the enums above. Failures are `document.invalid-field` at the field.
- **M6a-S4 bounds (M6-Q22).** Per node at most `MAX_TEXT_LENGTH` = 16,384 UTF-16 units (at `/nodes/<id>/runs`), exported from `model`; since every run but a lone empty one holds at least one unit, this also bounds the run count (M6a-Q4). The values fit E28-S2 (section 3.1).
- **Order inside a text node.** The base fields, then `runs`: its array shape (empty at `/nodes/<id>/runs`), each run's fields in key order (types and M6a-S3, `text` only as a string), then M6a-S4 over the whole node, then the M6a-S1 scan run by run, then M6a-S2 run by run; then `sizing`, `align`, `letterSpacing`, `lineHeight`. So an over-long text fails at `/nodes/<id>/runs` before any control is scanned. "The run at offset `o`" means the run holding the character at `o`, and for `o` equal to the text length the last run.
- **M6a-S5 frame.** `frame` is stored for every sizing mode (M6-T3); the model checks it like any leaf frame and never compares it with a layout. `opacity` follows the leaf rule. Constraints work as for any leaf.
- **M6a-S6 no layout in the document (M6-T6).** Lines, positions, metrics, fonts used and `lang` are never stored (M6a-Q1).
- **M6a-S7 interim symbol rule.** A `text` node with a `symbol` ancestor is `document.invalid-symbol` at `/nodes/<id>/parent`, checked in the M7-S3 loop (`parse.ts:775-780`), also by `validateFragmentTree`. Section 9 lifts it in M7-U7.
- Model check order is unchanged otherwise: field rules (inside `readNodeV3`, in the order above), ownership, M7-S2, the cycle walk, M7-S3 with M6a-S7, M7-S5, group and mask rules. A `text` node is never a mask source (the M1 rule names `path`).
- **Key order.** `serializeDocument` writes the base keys, then `runs` (each `text`, `family`, `size`, `color` with `r, g, b, a`), `sizing`, `align`, `letterSpacing`, `lineHeight`.

## 3. `TextLayoutPort` (contracts)

New file `packages/contracts/src/text.ts`, exported from the index. Plain data only: no DOM, `FontFace` or element type; strings and numbers.

```ts
type TextLayoutRun = Readonly<{ text: string; family: string; size: number }>;
type TextLayoutRequest = Readonly<{
  runs: readonly TextLayoutRun[];   // canonical, as stored (M6a-S1 to S4)
  width: number | null;             // null: no wrapping (autoWidth); else the wrapping width
  align: 'left' | 'center' | 'right';
  letterSpacing: number;
  lineHeight: number;
}>;
type TextLayoutLine = Readonly<{ start: number; end: number; top: number; height: number; baseline: number; left: number; width: number }>;
type TextLayoutCluster = Readonly<{ start: number; end: number; line: number; run: number; x: number; y: number; advance: number }>;
type TextLayoutResult = Readonly<{
  generation: number;
  lang: string;                     // BCP 47, the port's (section 3.1)
  width: number; height: number;    // the box
  fontLists: readonly string[];     // per run index, the CSS font list (M6-F2)
  lines: readonly TextLayoutLine[];
  clusters: readonly TextLayoutCluster[];
}>;
interface TextLayoutPort {
  readonly portVersion: 0;
  readonly generation: number;
  layout(request: TextLayoutRequest): TextLayoutResult;
  subscribe(listener: () => void): () => void;
}
```

- **M6a-L1 coordinates.** Node-local page units, origin at the box's top-left, y down, no camera or DPR applied. `width` is the request width, or for `width: null` the widest line without hanging spaces; `height` is the sum of line heights. Offsets are UTF-16 into the node text; a line's `end` excludes its LF; lines tile the text. Clusters are the grapheme clusters (`Intl.Segmenter`, run boundaries are also cluster boundaries) except LF, in text order; `x` and `y` are the cluster's **baseline pen origin** with alignment applied (`y` equals its line's `baseline`); `advance` includes letter spacing. A line's `left` and `width` are the aligned start and the width of its content without hanging spaces, so an empty line has `width` 0 and `left` at its alignment point (M6b places a caret there). **Long clusters:** a grapheme longer than 32 UTF-16 units is cut, from its start, into pieces of 32 units, moving a cut one unit earlier when it would fall between a high and a low surrogate, so no piece ends in a lone surrogate; the first piece has the grapheme's `x` and its whole `advance`, later pieces the same `x` and `advance` 0; only the grapheme's start and end are caret stops. So every cluster fits E28-S2; such graphemes may draw degraded (disclosed). An empty node, or a text ending in LF, has a last line of height `lineHeight × size` of the run at that offset and no cluster on it.
- **M6a-L2 determinism.** `layout` is synchronous, never throws for a request built from a valid node, and returns deep-equal results for deep-equal requests at one generation (M6-L3 cache allowed, dropped on a generation change). The editor is the only caller that builds requests from documents (M6-L1).
- **M6a-L3 generation.** A non-negative safe integer that never decreases, so a larger value is newer. text-dom draws it from **one counter per JavaScript realm**, shared by every instance: a new instance starts at the counter's next value, and each event increments it, so a recreated port (HMR, a remount) never repeats a generation an earlier instance used (M6a-Q21). The renderer sees generations only through the scene nodes the editor projects; it holds no port. Events: a registered face settles (`loaded` or `error`), `document.fonts` `loadingdone` or `loadingerror`, a registry change, and a `devicePixelRatio` change (M6a-Q15). `loadingdone` also fires for fonts the host UI loads, so some bumps change no layout (one re-layout each; disclosed). `subscribe` listeners run synchronously after each increment, in registration order; a listener may call `layout`. `result.generation` is the generation it was computed at. Each increment also makes the renderer re-rasterize every visible cluster under E28 (E28-K10, E28-A04), spread over frames by its 256 rasters per frame budget, so a host-UI `loadingdone` costs rasters as well as one re-layout (disclosed).
- **M6a-L4 port version.** `portVersion: 0` until a breaking change; a port of another version is rejected by `createEditor` (it throws, as for an invalid keymap).

### 3.1 Answers to the rendering track (R-T, E28)

E28 (contract `docs/plans/d9-e28-text-glyph-atlas-contract.md`, PR #361, merged a9c8db2; its section 2) defines the scene kind `{ kind: 'text'; generation; lang; runs: { fontList; size; color: SceneColor; clusters: { text; x; y; advance }[] }[] }`. This contract matches it; M6c fills it from one `TextLayoutResult` (section 7):

1. **`lang` is per node** (one `lang` per result and per scene node), not per run. It is the port's configuration, `createTextDom({ lang })`, default `ko`, never stored, checked with E28-S1's syntax (section 4) (M6a-Q1). Per-run `lang` would need a stored field and a requirement for mixed Japanese and Chinese Han forms; the MVP has none.
2. **`generation` is a monotonic integer, larger is newer** (M6a-L3), owned by text-dom and increasing across its instances in a realm; the renderer gets it only from scene nodes, each carrying the `generation` of the result it was built from, so an atlas key with it never reuses a fallback raster after a load (M6-F4).
3. **`color` is the straight-alpha colour the other leaves use**: the run's model `Color` copied unchanged into `SceneColor`, as `projectNode` does for fills. **Text stays solid colour** in M6a and the MVP (M6a-Q9); gradient text would be a requirement change and a new `Paint` on runs with its own bump.
- **Limits (E28-S2, PR #361).** The M6a bounds fit inside E28's: `size` in `(0, 4096]`, the same range; 16,384 UTF-16 units per node give at most 16,384 clusters (LF and the sentinel are not clusters); clusters are at most 32 units with no control and no lone surrogate (M6a-S1 and the long-cluster rule of M6a-L1); font lists at most 512 characters (section 4); `lang` at most 35 characters. A scaled group or instance stays inside them because scaled sizes above 4096 fail (sections 6.3, 9). None of E28's limits needs to be larger for M6a.
- `fontList` is `fontLists[run]` exactly as the measurement element used it, so `ctx.font = "<px>px " + fontList` picks the same faces (M6-F2); `size` is the run's `size` in node-local units; `x`, `y` are M6a-L1's baseline pen origins; letter spacing, line height and alignment reach the renderer only through positions. A text node has no children, no clip and is not a mask source. **Scene runs (agreed with E28-S1):** M6c emits one scene run per maximal sequence of clusters with the same `run` index on one line, in text order, so a style run broken across lines gives several scene runs.

### 3.2 Measurement scale (M6-Q3)

Recommended (a): measure at page units, as the plan says. M6-S0 found line breaks and positions identical at DPR 1, 1.25, 1.5 and 2 under emulation on the main PC; browser zoom and monitor moves were NOT RUN. M6a-U6 takes over those manual cases (this contract records the hand-off M6-S0 asks for) and adds a size-linearity check (a fixture laid out at `s` and `4s` with width `4w`: same line breaks, and positions within 0.25 px after dividing by 4; a quarter pixel is E28's subpixel phase step, so smaller differences, hinting included, cannot change what the atlas draws). If either fails, M6-Q3 switches to (b), a fixed reference scale `R` (requests multiplied by `R`, results divided), by an amendment before M6c; the port's interface does not change. The generation bump on a DPR change stays in either case (M6a-Q15).

## 4. `@vector-studio/text-dom`

- **Package.** `packages/text-dom`, private, ESM, `tsc --build`, `lib: ["DOM", "ES2022"]`; manifest names `@vector-studio/contracts` only. Boundary policy: `boundaries` gains `['@vector-studio/text-dom', new Set(['@vector-studio/contracts'])]`, `externalDenied` gains it with `react`, `react-dom`, `next`; `packageDirectories` gains it; next-host's entry gains it. `ARCHITECTURE.md` gains `text-dom -> contracts` under dependency direction and a dated pointer naming the port; the host composition creates it and injects it into the editor; the renderer holds no layout port (it rasterizes through E28's `GlyphRasterPort`).
- **API.** `createTextDom({ document, lang = 'ko', fallbackFamilies = [] })` returns a `TextDom`: a `TextLayoutPort` plus `registerFont({ family, source })`, `dispose()` and a read-only `fallbacks` count (measurement method below). `source` is `{ url: string }`, which text-dom writes as `url("<escaped>")` (a CSS string with `"`, `\` and newlines escaped), so no `local()` or other `src` syntax can be injected, or `{ bytes: ArrayBuffer }`. `registerFont` adds a `FontFace` to `document.fonts`, loads it and resolves `'loaded'` or `'error'`, never rejecting (M6-F1). `lang` is 1 to 35 ASCII letters, digits and `-`, checked by syntax only, not through ICU, exactly E28-S1's rule. Invalid input (a family failing M6a-S3, a bad `lang`, a non-`Document`) throws `TypeError`. **After `dispose()`** listeners and the measurement host are removed, `generation` stays fixed, `layout` throws `Error`, `subscribe` returns a no-op and `registerFont` resolves `'error'`.
- **Font list (M6-F2).** Per run: `"<family>", <fallbackFamilies quoted>, "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`, each name a CSS string with `"` and `\` escaped. A family that names a CSS generic is still a quoted name (disclosed). **Length:** the quoted family is at most 258 characters (128 units, each escaped to at most 2, plus quotes) and the fixed tail 52 including its leading separator, so `createTextDom` throws `TypeError` when the quoted `fallbackFamilies` part with its separators exceeds 200 characters; every font list stays within E28-S2's 512 (258 + 200 + 52 = 510).
- **Measurement element (M6-L1, section 4.1 of the plan).** A hidden host (`position: fixed`, `visibility: hidden`, `contain: strict`, size 0, `pointer-events: none`) appended to `document.body`, with a shadow root holding a block styled `all: initial`, then `display: block`, `direction: ltr`, `unicode-bidi: isolate` on the block and `direction: ltr`, `unicode-bidi: bidi-override` on every run span (so RTL characters are laid out in logical order, left to right, with no reordering; A11's RTL fixture checks it), `white-space: pre-wrap`, `word-break: keep-all`, `overflow-wrap: anywhere` (M6-Q13), `hyphens: none`, `font-variant-ligatures: none` (M6-Q9), `text-spacing-trim: space-all` and `text-autospace: no-autospace` (so the browser adds no CJK spacing that per-cluster `fillText` would not; unverified in a browser, A11 checks it), `text-align`, `lang`, `width` (`max-content` for `width: null`) and **`font-size: 0`** (zero-size strut, M6a-Q2). Each run is a span with its `font-family`, `font-size`, and `letter-spacing` in em and unitless `line-height` set on the span (on the block they would resolve against size 0). A text that is empty or ends in LF gets a trailing sentinel span holding U+200B in the style of the run at that offset, excluded from clusters (M6a-L1). Main thread only.
- **Measurement method** (fixed here because E28's `y` depends on it). Pass 1: `Range.getClientRects` of each cluster gives its `x` (left edge minus the block's left) and `advance` (rect width); a cluster starts a new line after an LF, or when its rect's left is less than the previous cluster's left, or its top is at or below the previous cluster's bottom. Pass 2: **after the first cluster of each line** (never before it, where a soft-wrap point could put a probe at the end of the previous line), text-dom inserts two zero-width, zero-height `inline-block` probes, one with `vertical-align: top` (its top edge is the line box top) and one with `vertical-align: baseline` (its bottom edge is the baseline). A line's `top` and `baseline` come from them; its `height` is the next line's `top` minus its own, the last line's the block's bottom minus its top; `left` and `width` from its first and last non-hanging cluster. text-dom then re-reads the cluster rects; since atomic inlines add break opportunities, if any cluster's line changed it **falls back** for that request: lines keep their pass-1 assignment, a line's `top` is the previous line's bottom (0 first), its `height` the largest cluster rect height on it and its `baseline` `top + 0.8 × height` (an approximation, disclosed), and the instance's `fallbacks` counter increases (A11 asserts 0 on its fixtures). Probes and the sentinel are removed before the next request. A11's mixed-size fixture compares these with the M6-S0 `mixed-sizes` case (its 1.0 px offset is undiagnosed). Lines with `lineHeight` below 1, where glyph boxes overflow the line box, may misdetect lines (disclosed; A11 has a 0.5 case).
- **Generation sources (M6a-L3).** `FontFace` settle, `document.fonts` `loadingdone` and `loadingerror`, `registerFont`, and a `matchMedia('(resolution: <dpr>dppx)')` change listener re-armed after each change (browser zoom also changes `devicePixelRatio`).

## 5. Editor integration

- **Injection.** `EditorOptions` gains `textLayout?: TextLayoutPort`. The editor subscribes once at construction; there is no editor dispose (M6a-Q20 (a)), so the subscription lives with the editor (disclosed). **Composition rule:** an editor with a port is created on the client only, never during render or prerender, since `createTextDom` needs a `document`; the owner that creates the text-dom instance disposes it with the editor it fed. next-host therefore creates the port and editor in a client effect (not the `useState` initializer of `page.tsx:551-553`) and, under strict mode's double effect, disposes the first pair in the effect's cleanup.
- **Layout use.** Requests are built from a node: its runs without colour, `width` null for `autoWidth` else `frame.width`, `align`, `letterSpacing`, `lineHeight`. The editor's cache maps a node object to its request key in a `WeakMap`, and request keys to results in a least-recently-used map of 10,000 entries per generation, so nodes with equal requests (equal-scale instances among them) share one layout; a generation change drops the map and raises `session` event field `textLayout` (new), and no document event, history entry or frame change (M6-Q6 (a)).
- **Query.** `textLayout { id }` returns the `TextLayoutResult` of a text node, or null for no port or a non-text ID. It is for hosts, tests and M6b.
- **Without a port (M6-L4, M6a-Q8).** Load, undo, redo, move, delete, copy, paste, grouping and every command that needs no layout work with text nodes. A command or gesture edit that needs a layout (any section 6.1 command on a node in an auto mode, `createText` included unless `sizing` is `fixed`, and the uniform-scale refit of section 6.3) fails with `editor.no-text-layout` (new, no path) and changes nothing. `textLayout` returns null. Nothing is projected for text anyway in M6a (section 7).
- **Fake port (M6-L2).** `tests/support/fake-text-layout.ts`, test-only, implementing `TextLayoutPort` with `lang` `ko` and fixed advances per code point (in em of the run size): U+0020 0.25; `\p{M}`, U+200D, U+00AD and variation selectors 0; `\p{Script=Hangul}`, `\p{Script=Han}`, U+3000 to U+303F, U+FF00 to U+FFEF and `\p{Extended_Pictographic}` 1; any other 0.5. A cluster's advance is the sum plus `letterSpacing × size`. Breaks (only when `width` is not null): after a sequence of spaces, and inside a word only when the word alone overflows (before the first overflowing cluster, at least one cluster per line); trailing spaces hang. A line's `m` is the largest run size on it (an empty line: the run at its offset), `height = lineHeight × m`, `baseline = top + (height − m) / 2 + 0.8m`; the line's `x` offset is `(W − line width) × {0, 0.5, 1}` by `align`. Lines get `left` and `width` as M6a-L1 says, and graphemes over 32 units follow M6a-L1's long-cluster rule. `fontLists` are `"<family>", sans-serif`. `bump()` increases the generation for tests. Its own unit tests pin these rules.

## 6. Commands

### 6.1 Text commands

| Command | Effect |
| --- | --- |
| `createText { frame, runs, sizing?, align?, letterSpacing?, lineHeight?, rotation?, parent?, index? }` | New node at `frame` in page space (M1 section 4.1); `runs` must be canonical (M6a-S2; not canonicalized); defaults `autoWidth`, `left`, 0, 1.2, name `Text`, `start` constraints. Auto dimensions come from the layout, and the anchor of 6.2 is taken on the given frame: `(x + a·width, y)` of it stays put, so a zero-width frame at a click point grows from there by `align`. `fixed` needs no port. Returns the ID |
| `setText { id, start, end, text }` | Replaces `[start, end)` with `text`, in the style of the character before `start` (the first run's at 0); deleting everything leaves one empty run in that style; runs re-canonicalized; auto dimensions refit with the growth anchor |
| `setTextStyle { id, start, end, style }` | `style` a non-empty subset of `family`, `size`, `color` over `[start, end)`; `start < end`, or `0, 0` on an empty node; re-canonicalized and refit |
| `setTextProps { id, sizing?, align?, letterSpacing?, lineHeight? }` | At least one prop; refit; switching to `autoWidth` drops the stored width |
| `refitText { ids? }` | Refits the auto dimensions of the listed text nodes, default every text node of the document, as one step; a node whose frame does not change is skipped, and with no change no step is recorded (M6-Q6 (a)) |

`setNodeProps` on a text node takes `PROPS`' common props only (`edits.ts:112`). A size given by a command (`createText` runs, `setTextStyle`) below 0.5 is `editor.invalid-command` at that field (M6a-Q19), checked right after the model's rules below.
Checks in the M1 section 4.3.1 order: command shape (`editor.invalid-command` at the field); unknown node (`editor.unknown-node`); not a text node (`editor.not-a-text-node`, new, at the field naming the node, here `/id`); offsets not integers with `0 ≤ start ≤ end ≤ length`, or splitting a surrogate pair (`editor.invalid-text-range`, new, at `/start` or `/end`); the model's rules on the result (`document.invalid-field` and its path, as `setNodeProps` reports them; a new node's paths relative to it); the authored size floor (`editor.invalid-command` at the size field); `editor.no-text-layout`; the M7 nesting rule (M6a-S7: `editor.nested-symbol`); then the existing checks; `editor.duplicate-id` last. Each command is one transaction with byte-identical undo; M6b adds gestures and merging on top.

### 6.2 Auto sizing and the growth anchor (M6-T3)

`autoWidth`: width and height from the layout with `width: null`. `autoHeight`: stored width, height from the layout. `fixed`: nothing refits; overflow is drawn, not clipped. When the size changes from `(w, h)` to `(w', h')`, the **anchor** stays put on the page: the point at `(a·w, 0)` of the box in the node's own axes, `a` = 0, 0.5 or 1 for `left`, `center`, `right` (M6a-Q5). With `c` the old centre and `R` the node rotation, the new centre is `c + R(a·w − w/2, −h/2) − R(a·w' − w'/2, −h'/2)`, and `x' = cx' − w'/2`, `y' = cy' − h'/2`; at rotation 0 this is computed exactly as `x' = x + a·(w − w')`, `y' = y`.

### 6.3 Resize and scale (M6-T4, M6-T4a)

Each path that changes a text node's frame, named (M6a-Q18 is a user decision):

| Path | Code | Run sizes | Sizing mode |
| --- | --- | --- | --- |
| `setFrames` (hosts, `single` handle mode and frames mode, `tools.ts:997`, `1017`) | `edits.ts` | unchanged | width alone changes: `autoWidth` becomes `autoHeight`, `autoHeight` stays, height refit; height changes: auto modes become `fixed`; `x`, `y`, `rotation` alone: kept |
| Group resize (MVP-Q3, M6-T4a (a)) | `resizeContainer`, `mapNode` | `× s` | uniform: kept, auto dimensions refit; else auto modes become `fixed` with the mapped frame |
| Frame child, `scale` constraint on an axis | `applyConstraints` | `× s`, from the `scale` axes only | as group resize, uniform only when both axes are `scale` with equal factors |
| Frame child, `start`, `end`, `center`, `startEnd` on both axes | `applyConstraints` | unchanged | the `setFrames` rule on the mapped frame (a `startEnd` stretch is a frame change, never a size change) |
| `map` handle mode (several nodes, `tools.ts:1001-1005`, `edits.ts:448`) | `mapNodeInPageSpace` | (a) `× s`, as a group (recommended, M6a-Q18); (b) unchanged | (a) as group resize; (b) the `setFrames` rule |
| Instance expansion (section 9) | `expandInstance` | `× s` | as group resize, never refit |

- **Scale factor.** `s = √(kx · ky)`, `(kx, ky)` the node's own-axis scale: the map's `(sx, sy)` when the node's rotation relative to the map is 0 (swapped at ±π/2), else the ratios of `approximateSize`'s result to the old size; an axis of old size 0, or (for constraints) an axis that is not `scale`, counts 1. Uniform means `kx = ky`.
- **`mapNode` stays pure.** It gets the factor rule from its caller, multiplies sizes, sets the sizing mode and marks auto nodes that need a refit; it never calls the port. The refit is a separate step after the tree edit: in `applyEdit` for commands, and in `applyGestureEdit` and `refitGesture` for gesture updates and commits (so a live resize refits on every update, at one layout per text node). Without a port the step fails with `editor.no-text-layout`, and the command or update is not applied.
- **Bounds.** A derived size above 4096 fails the command or update with `document.invalid-field` at the size (disclosed); derived sizes may be below 0.5 (M6a-Q19). A factor `k = 0` (a `scale` constraint or a group resized to width or height 0) gives a derived size of 0, which also fails with `document.invalid-field` at the size; it is not clamped (disclosed). Handle resize in `single` and frames mode never changes `size`.

## 7. Projection and hit testing

- **M6a draws no text (M6a-Q6, user confirmation).** No `text` scene kind exists before E28; the projector keeps returning null for `text` (`projector.ts:295`), with no diagnostic, port or not. A text node is visible in next-host only through the selection overlay (its `handles` box) until M6c; next-host's headed spec reads layouts through the `?test=1` hook. No placeholder or DOM text layer is added (the plan rejects route (d)).
- **M6c (fixed here, implemented there).** A text node projects one leaf `{ kind: 'text', generation, lang, runs }` with the base fields of every leaf and the transform of its frame and rotation, filled from `textLayout` as section 3.1 says; a renderer created with E28's `text: 'none'` rejects it with `unsupported-feature`, which the projector isolates as any rejected leaf; without a port the node projects nothing, and M6c may add a text-specific diagnostic (a proposed `editor.text-unavailable`, once per load), never `editor.scene-rejected` or `unsupported-feature`, which the projector reports as `editor.renderer-unsupported`, a host capability (`projector.ts:1139`). A generation change re-projects every text node on the active page. Under M7, an expanded text node projects the same way. E28-S3 makes the renderer throw `TypeError` for `text: 'atlas'` without a `glyphRaster` port or with `clips: 'none'`, so next-host passes both (`createCanvasGlyphRaster()` from renderer-webgpu, E28-U3). Scene runs are non-empty, so runs ≤ clusters ≤ 16,384 fits E28-U1's per-node run cap, and an empty node projects `runs: []`, which E28 accepts.
- **Hit testing (M6a-Q7).** A visible text node is hit inside its rotated frame box (as a filled rectangle) or within the M1 stroke tolerance of its edge, with no layout call, so hit testing needs no port; the marquee takes it as a leaf (intersects its rotated frame); snapping uses its frame as a leaf's. Caret hit testing is M6b.

## 8. Persistence and clipboard

- **Envelope (M5).** Unchanged: `parseEnvelope` reads its document through `validateAnyDocument`, so older stored documents migrate on restore; since next-host subscribes autosave only after the restore (M5 section 5.3), the migrated document is written back at vN+1 by the next autosave, triggered by an edit or a page switch. `parse(serialize(d))` and the envelope round trip are byte-identical for every vN+1 text fixture.
- **Fragments.** No new fragment version (M6a-Q14). Copy writes the fragment version current on main at vN+1 (2 once M7-U5 merges, else 1). `parseFragment` accepts every (fragment version, schema version) pair it accepted before, plus the current fragment version at vN+1; nodes at an older schema version are read with that version's node types (a `text` node there fails at `/nodes/<id>/type`) and, since every bump since then changed only the version (or M4's migration runs first, if M4 landed), unchanged otherwise, by the M7 section 6 wrapper rule. Whichever of M7-U5 and M6a-U1 merges second applies this rule to the other's code. Text-node copies keep runs and props; a pasted text node is not refit (its frame is stored).
- **Plain text** in and out (M6-E7) stays M6b; a non-fragment paste still fails with `editor.unsupported-clipboard` in M6a.

## 9. M7 addendum: text in symbols

This section is the addendum M7 section 8 asks for, reviewed with this contract; M7-U7 implements it after M6a-U1 to U3 merge and defines M7-A12 below. Until then M6a-S7 holds.

- **M7-T1 allowed.** M6a-S7 is removed: a text node may be inside a `symbol` at any depth, and `createSymbol` may wrap text nodes.
- **M7-T2 expansion under scale (M6a-Q10, user confirmation).** Recommended (a): an expanded text node maps by M7-X1 exactly as section 6.3's group scale, sizes times `s`, a non-uniform scale switching auto modes to `fixed`, **but without the refit**: the mapped frame is kept. So the expansion stays a pure function of the document, needs no port and the M7-X4 cache keys do not change; the drawn layout of a uniformly scaled auto node may differ from its box by layout rounding (disclosed). At scale (1, 1) the source node object is copied unchanged (M7-X1 equal-size rule). Scaled sizes above 4096 make the expansion invalid (`editor.invalid-expansion`, M7-X3); sizes below 0.5 are valid (M6a-Q19). Alternatives: (b) frame only, sizes unchanged, which breaks M7-Q4 (c)'s proportional content; (c) as (a) with the refit through the port, which makes the expansion depend on the port and its generation (the cache gains the generation as a key, and a font load changes every instance).
- **M7-T3 override (M6a-Q11 (a), M6a-Q12).** `instance` gains `"textOverrides": { "<source text node ID>": { "runs": [ { "text", "family", "size", "color": { "r", "g", "b", "a" } } ] } }`, always present (`{}` when none), written after `symbol`, keys sorted by UTF-16 code units, each value exactly the one key `runs`, canonical (M6a-S1 to S4), sizes in the source's space. **Runs only:** the expanded node takes the override's runs and every other field from the source node as mapped by M7-T2, so a later change of the source's `align`, `lineHeight`, `letterSpacing`, `sizing` or width reaches the instance, and no box is stored to go stale; the box is the mapped source frame, never refit, so for an auto node it may not match the drawn override text (hit testing inside the instance uses that box; disclosed). Overriding freezes style too: a source style change does not reach an overridden node (disclosed, pinned in M7-A12).
  - **Load codes.** A key naming no text node of the instance's source subtree: `document.invalid-symbol` at `/nodes/<i>/textOverrides/<key>`; a value that is not `{ runs }`, or whose runs fail M6a-S1 to S4: `document.invalid-field` at its path (for example `/nodes/<i>/textOverrides/<key>/runs/0/size`).
  - **Commands.** `setInstanceText { id, node, runs }` (runs equal to the source node's remove the key) and `clearInstanceText { id, node? }` (all keys without `node`); no port is needed; one step each, byte-identical undo. Checks in order: shape (`editor.invalid-command` at the field); `editor.unknown-node`; `editor.not-an-instance` (no path); `node` not a text node of the source subtree (`editor.not-a-text-node` at the field naming the node, `/node`, as in section 6.1); the runs' model rules (`document.invalid-field` at `/runs/<k>/...`); the authored size floor (`editor.invalid-command` at `/runs/<k>/size`), in the section 6.1 position.
  - **Keeping keys valid.** Any command whose result leaves a key without its text node (delete, move out of the source, retype) drops that key in the same transaction. Detach copies the override runs into the detached text node; a paste remaps keys with a carried or co-pasted source's new IDs, keeps them when linked by ID, and applies them when pasted detached.
  - **Cost.** Each expanded text node is laid out for drawing (M6c) through the editor's request-keyed cache (section 5), so equal-scale instances without overrides share one layout; a generation change costs about 0.4 ms (M6-S0's mean) per distinct request on the active page.
  - **Schema.** Its own bump vN+2 in M7-U7, with a migration that adds `textOverrides: {}` to every instance (M7-Q11 (a)).
- **M7-A12 (defined here).** An instance's text differs from its source's while the source's other changes propagate, its props (`align`, `lineHeight`, `letterSpacing`, `sizing`, width) included; a source text or style edit leaves overridden nodes' runs unchanged and updates the others; one undo step each, byte-identical undo; the override survives a round trip, detach and every paste case; removing the source text node drops the key; each load and command code above.

## 12. Risks

- **Browser layout is not ours** (plan section 11): breaks and fallback change with browser updates; structural fixtures only. The zero-size strut and the sentinel rely on Chrome's line-box rules; A11 checks them, and a failure moves M6a-Q2 to (b).
- **Main-thread layout**: about 0.4 ms per node in M6-S0; `refitText` over a large document and generation changes re-lay out every text node; no budget is claimed (M9).
- **Invisible text until M6c** (M6a-Q6): M6a and M6b work with boxes only.
- **Machine-dependent frames** (M6-Q6): frames follow the fonts of the machine that last edited.
- **Live refit cost**: a uniform group or `map` resize refits every auto text node on each gesture update.
- **Schema churn** with M4 and M7-U7 (two more bumps possible) and fragment versions with M7-U5.
- **Bounds** (M6a-S3) refuse scaling text above 4096; derived sizes far below 0.5 lay out poorly (browser minimum font size, rounding).

## What changed

- `cubic_fill.rs` (E14-K1): rung 0's S1 prefix runs at its own caps `FAST_CAPS`: E0 = `MAX_FAST_EDGE_OWNERS` = 8,192 flat edges, `MAX_FAST_FLAT_COMMANDS` = E0 + 2·contours, `MAX_FAST_CONTOUR_POINTS` = E0 + contours. The exact rung keeps `B1_CAPS` (E = 256), and the pre-B1 cap mode passes `PRE_B1_CAPS` for both. The prefix caps are chosen per call (`prefix_caps`), and `certify_topology` keeps the exact caps. The prefix buffers (commands, contour points, edge owners) moved to the heap, sized for E0 and reserved fallibly; `combined_bytes()` counts them (590,208 B).
- `fill_ladder.rs` (E14-K2, E14-K3): every rung-0 array (`FastRung`, and the FR5, FR7 and AL-FR9 stage arrays now in `RungScratch`) is a heap buffer reserved once by `FillLadder::reserve`, which refuses scratch smaller than rung 0's AL-FR9 records at E0 (`BATCH_INTERNAL_ERROR`). The FR5 candidate bitset exists only in debug builds. A work counter `Work` with cap W0 = 2^22 is charged per FR5 sweep candidate, per FR7 status visit and `remove_edge` shift, and per candidate in `next_half`; over W0 rung 0 returns the new reason `WORK`, appended last. `next_half` uses a per-vertex diagonal index (counting sort that keeps half-edge order) instead of the linear scan.
- `fill_export.rs`: `FILL_V0_REVISION` = 3. The fill scratch is sized for rung 0's records at E0 (24,606 records, 885,816 B), while the exact rung's checks stay bounded by its own sizes (`exact_slots`). `stroke_outline.rs` reserves the stroke scratch as before.
- Identity: `geometry-wasm/fill-v0+r3` in `fill-adapter.ts`, its tests, the analysis harnesses (revision literals and the three AL-S1/AL-S2/AL-OB5 configuration hashes, which hash the operation id), and the five GPU specs. `tests/geometry/p3-fill-ladder/dump.ts` and `oracle.ts` know `WORK` (no condition, after FR3).
- Size pins: the bridge workspace's heap grows by the prefix buffers (2,908,672 → 3,498,880 B) and its inline size drops (42,952 → 24,304 B), in `native_cubic_fill_tests.rs` and the native mixed and triangle-free verifiers.
- `tooling/compare-p3-fill-identity.mjs`: `--failure-to-success` combines with `--revision-change` (E14-G1); the two size records are printed as recorded changes; the self-test covers the combination.

**E14-F5 departure.** The contract names the lowest-index looping path with E + 1 to E0 flat edges whose rung-0 reason at `r3` is `CROSSING`. There is none: all 190 such scene paths stop at `MONOTONE`, because FR4 (monotone pairs) runs before FR5's crossing test. E14-F5 is therefore the lowest-index such path (scene path 3) with its actual reason. The E14-Q1 class does not depend on the rung-0 reason (its test is the exact crossing of the S1 polygon), and scene path 3 is in it: `proper_crossing` finds two edges of its S1 polygon that cross properly by exact `orient2d` (`e14_f5_f6_scene_paths_stay_work_limit`).

**E14-F8.** No simple path within E0 and 64 sources reaches W0 in FR5 before another reason. FR5's candidates are pairs whose x ranges, widened by the clearance, overlap. Intervals that overlap pairwise share a common x (Helly's theorem in one dimension), and a cubic crosses a vertical line at most 3 times, so 64 sources give at most 192 edges whose widened ranges all overlap at one x, plus the few within the widening of it: a few hundred, far below the 2,897 edges a pairwise-overlapping set needs to charge W0. A path whose x ranges overlap in many smaller groups charges far less than W0. As the contract allows, E14-D2 runs with W0 lowered in a `cfg(test)` build (`with_work_cap`).

## Seeded defects (E14-A5)

- **E14-D1**: with the exact rung on the fast caps, E14-F7's exact attempt no longer returns `CommandLimit` (`e14_d1_exact_rung_with_fast_caps_is_caught`), and E14-G1's combined mode fails on any changed entry record (AL-I1) or any cascade change other than `work-limit` → `ok`; its self-test seeds an entry change, an `unsupported-geometry` → `ok` change and a `work-limit` → `unsupported-geometry` change and detects each.
- **E14-D2** (`e14_work_cap_is_inclusive_and_d2_is_caught`): W0 is inclusive (cap = work meshes, cap = work − 1 is `WORK`); with the cap disabled, the lowered cap is not observed and the test fails.
- **E14-D3** (`fill_ladder_tests::e14_d3_scratch_sized_from_the_exact_limits_only_is_refused`): scratch sized from `FILL_V0_LIMITS` only (9,216 records) is refused with `BATCH_INTERNAL_ERROR`; 24,606 records and the pre-B1 2,304 are accepted.
- **E14-D4**: on a synthetic face-tracing graph with a tie, today's order gives `TRIANGLE` and the reversed index succeeds (`e14_d4_diagonal_order_is_observable_on_a_tie`). The differential compares the indexed scan with today's linear scan on every `next_half` call and counts the calls whose vertex has a diagonal (only those can differ): over the full AL-I3 corpus (B0 framed and `p3-b0r-random/v1`, 13,270 paths, at the pre-B1 and the production caps) 411,087 calls, 36,020 with diagonals, all equal (`fill_ladder_tests::e14_d4_next_half_differential_on_the_full_corpus`, release); the debug test runs the AL-I3 debug sample plus a nonconvex smooth path (`e14_d4_next_half_differential_on_the_debug_sample`). The E14 circles are convex, so on them every call compares only w → next(w).

## Departures from the contract

- **E14-F5** and **E14-F8**: see the fixture table.
- **E14-A3, `triangle-mesh` oracle.** `inspectTriangleMesh` (`packages/geometry-reference/src/triangle-mesh.ts`) refuses input above 256 vertices or 256 triangles, so it cannot run on any mesh over E (all 433 are above its cap; the A3 check counts that one issue as `overInspectorCap` and fails on any other). Its checks are implied by SL-O2 on the same mesh: degenerate and reversed triangles by item 1 (every triangle strictly positive); overlap by items 1 and 3 together (the cancelled chain of positively oriented triangles equals the oriented boundary of R(P), so the sum of their indicator functions is the winding number of ∂R(P), which is 1 on R(P) and 0 elsewhere, and positive triangles summing to at most 1 have disjoint interiors); bounds hold trivially (SL-O2 passes the bounds of the mesh's own vertices); area by item 4 (exact area equal to A(R(P))). The oracle still runs on E14-F1 (`e14-fill-rung0.test.ts`).
- **E14-A3, SL-O1** is not part of A3 and is not run over E: its exact certificate costs about three times SL-O2 per mesh (17.4 s against 5.8 s at 597 edges), which would put the run past a day on the container. Rung 0's own FR checks and AL-FR9 run on every mesh.
- **E14-G1, identity harness.** The contract sets aside the workspace-size identity (`allocated_bytes()`, inline sizes) by recording the two META size records as changes. The harness (`p3_b0r_identity.rs`) also hashed the absolute `allocated_bytes()` into every entry record, so the first combined run failed every one of the 61,080 entry records on that line alone (`OK -> OK`, and every path failure to the same failure). The harness now hashes `allocated_bytes()` as its growth over the workspace's value after construction: the absolute value stays in `meta/cubic-workspace-sizes`, any growth inside an attempt still changes the digest, and the tool copies the harness into the merge-base tree, so both sides hash the same way. With that change the native layer of the same run regenerated on both trees compares identical (82,475 records, FAIL 0, both size records recorded); G1 above is the full re-run.
- **O5 inline test module.** `native_cubic_fill_tests.rs`'s inline module changes its `allocated_bytes` and inline-size pins (3,498,880 and 24,304), which the identity tool's O5 check reports as an inline-module difference; this is the accepted case (as in [E8-U2](e8-u2-2026-10-24.md)): the pins follow the size change E14-G1 sets aside. The other changed test files are passed with `--allow-test-change`.
- **Identity tool host.** See G1: the container run used an uncommitted copy with the host string changed ([identity-linux-host.diff](e14-u1-2026-10-25/identity-linux-host.diff)).

# E2 evidence: cause of stroke `work-limit` on the E11-U2 scene, 2026-10-24

Rendering-track item E2 ([status index](../plans/d9-rendering-track.md#status-index), [contract](../plans/d9-e2-stroke-fast-rung-contract.md)). This record is diagnostic input to the E2 contract. It is not A01, A02 or A04 evidence, and it makes no performance claim.

## Setup

- `main` at 93630a2, kernel `stroke-v0+r4`, natively in `packages/geometry-wasm/kernel`, release profile, container (Linux, no GPU).
- Input: the 1,000 stroke requests of scene `p3-exit-stress/v1` (seed `0x5eede111`), generated by `tests/geometry/p3-exit-sweep/scene.ts` from the E11-U2 branch (`claude/eng-e11-u2-exit-sweep`, commit e35b3c1). Every fourth path loops (self-intersects).
- Probe: a `cfg(test)` module, kept as text beside this record ([`scene_probe.rs.txt`](e2-stroke-work-limit-cause-2026-10-24/scene_probe.rs.txt), registered by [`scene_probe_lib.rs.patch.txt`](e2-stroke-work-limit-cause-2026-10-24/scene_probe_lib.rs.patch.txt); not compiled in the repo), that runs `StrokeWorkspace::build` on each request at `STROKE_V0_LIMITS` and reads `last_error()`, the emitted piece count and the emitted vertex total. A second run used a scratch copy with `MAX_PIECES` and `MAX_PIECE_RECORDS` raised (`1 << 16`, `1 << 18`) so that the front end finishes and reports its full piece demand; that copy changes no committed file.
- Projection: a Python model of B2 §4.5's leaf subdivision (Float64, no guards) counting leaves per stroke under the current rule and under candidate rules ([`leaves.py`](e2-stroke-work-limit-cause-2026-10-24/leaves.py), [`ruleD.py`](e2-stroke-work-limit-cause-2026-10-24/ruleD.py), [`ceiling.py`](e2-stroke-work-limit-cause-2026-10-24/ceiling.py); input is the scene dumped to JSON by [`dump_scene.test.ts.txt`](e2-stroke-work-limit-cause-2026-10-24/dump_scene.test.ts.txt); the circle counts below come from [`circles.py`](e2-stroke-work-limit-cause-2026-10-24/circles.py); and `ruleD.py` and `ceiling.py` take `leaves.py`'s output as their second argument). The model uses the full cone set on every leaf and `KO · lO ≤ π`, so it ignores stationary-end leaves and the contract's `π/2`. Its rule-A counts equal the kernel's on four-cubic circles (128, 256 and 408 leaves for the three circles checked below).

The probe reproduces E11-U2's stroke totals: 121 `ok` and 879 `work-limit`.

- No stroke wider than 0.16 device px meshes. The widest `ok` stroke is 0.158 px and the largest `ok` path radius 18 px.
- Demand grows about linearly with the device width: about 800 pieces per device px for these rings, at about 5.9 hull vertices per piece. The radius split in the E11-U2 table is mostly this width effect, because a path's width and radius both scale with zoom × DPR.
- Cause: B2 §4.5 accepts a cubic leaf only when `deltaUp + 4·r·sinUp + gCtrl + gOff ≤ 2^e`. The term `4·r·sinUp` is linear in the half width `r` and in the leaf's normal turn, so for a fixed path the leaf count is proportional to `r / 2^e`. The curve-flattening term `deltaUp` alone grows only like the square root of the radius, as E14 finds for fill.
- Arrangement cost is not the limit on this scene. The `ok` strokes took 45 ms median and 179 ms at most per path natively (a functional observation, not evidence).

## Deviations

- **Schema versions.** The contract left vN open. M7-U1 took v3 (main had no M4 or M6a bump); M6a-U1 then took v4 and M7-U7 v5 for `textOverrides` (M7-U7 note 1); M4-U1 has since taken v6. Each bump committed its migration and moved the unsupported-version fixtures.
- **No new fragment version for overrides** (#375): `readFields` adds `textOverrides: {}` to instances below schema 5 instead of running the migration chain on a holder document. The reviewer judged this sound, since v5 touches only instance nodes. One residual difference is disclosed: when another unknown key comes before `textOverrides` in the object, a v4 document reports that key while the fragment reports `/textOverrides` (M7-U7 note 9).
- **Visual-bounds wrap** (contract section 5.1, M7-U6 wrap bounds): `createSymbol` wraps by visual bounds, so a stroked line is not clipped by its new source. `visualBounds` repeats the renderer's stroke rule in editor-core, because editor-core may not import renderer-core. Placement is kept up to rounding (one ulp), and only the geometric stroke is covered: the anti-aliasing fringe at the clip edge may be cut.
- **Headed diagnostics tolerance** (M7-U6 headed run): the A11 spec tolerates exactly the `render.path-mesh-failure` warning with `fringe-work-cap`, from the fixture's round-joined stroked paths exceeding the V4 fringe builder cap at zoom 2 and instance scale 2, a disclosed P3 renderer class, and fails on any other diagnostic.
- **The addendum's approval record.** M7-A12's method names the addendum as approved when the M6a contract is approved. The M6a contract merged via #364 after review round 2 READY WITH FOLLOW-UPS was applied, and its questions were adopted as recommended, but its status line still reads DRAFT and records no APPROVED; this record does not change it.

## Known limits and disclosed findings

- **Instance scaling** (M7-Q4 (c), contract section 12): an instance maps its source as a group resize, so a child cannot keep its size inside an instance and the source's child constraints are ignored. Resizing the source (a frame) moves its children by their constraints, so with `start` constraints widening a source from 100 to 200 halves the content of every 100-wide instance. A detached instance is a frame, so the same resize drag behaves differently before and after detach. Text under the instance scale follows the same rule without a refit (M6a-Q10 (a)): the drawn layout of a scaled auto-size text node may differ from its box by layout rounding.
- **Clipboard** (contract section 6 disclosures, M7-Q9 (a), M7-Q10 (a)): (1) copying an instance, editing its source and pasting the text into another tab of the same document, or after a reload, gives a detached frame, since rule (1) covers only this editor's clipboard; (2) a source can reach another page only by cut and paste, since `moveNodes` stays on one page; the cut detaches every instance and the pasted source has none. A paste could link to an unrelated source with the same ID and equal content (harmless: the content is equal). An older build rejects a fragment version 2 with `editor.invalid-clipboard`.
- **Overrides** (M7-U7 note 10): an overridden node's box is the mapped source frame, never refit, so for an auto-size node it may not match the override text, and hit testing inside the instance uses that box. An override freezes the style of its runs too. next-host has no override control, so A12 is unit-tested only.
- **Expansion cap** (M7-Q13 (a)): 100,000 expanded scene nodes per page is provisional; M9 reads the 10,000-node target as projected scene nodes.
- **Performance, observed only** (M7-A10): on 10,302 scene nodes in the container, a gesture inside a source cost about 169 ms per pointer update (about 75 % in the renderer-core mirror), a source edit commit 187 ms and an instance move 115 ms, well above a 16.7 ms frame; projecting instances is about 8.6 times dearer per scene node than plain nodes, since subtree work is not shared between instances of one source at one scale (M7-U2 review). The mirror cost bears on [E26](../plans/d9-rendering-track.md#items), whose U2 (incremental scene mirror, #384) merged after the observation; A10 was not re-run on it. The WebGPU upload and draw cost (one copy of each expanded path mesh per instance) is not measured. No claim.
- **Disclosed P3 and P4 defects repeat once per instance** (contract section 12): cracks, the A04 class and large masks.
- **Headed evidence is from the main PC only** (Chrome and Edge 156) at `d628caa`. Main has moved to `f3e44a8` since, with M4-U2 (#385, projector paints, outlines, dashed lines and opacity, which also touches `visual-bounds.ts`) and E26-U2 (#384, the incremental scene mirror); the headed specs at `f3e44a8` are NOT RUN, while the M7 unit tests pass there. Pointer and key events are sent by Playwright. The headless `chromium-smoke` project of `playwright.m7-next-host.config.ts` (under `M7_NEXT_HOST_CHROMIUM`) is a spec check, not evidence; it does not check propagation.
- **Exit order** ([MVP plan section 7](../plans/mvp-editor-plan.md#7-order-and-parallelism)): the plan has `M6 -> M7 (text-override criterion and exit)`. M7-U7 started after the M6a contract and M6a-U3 merged, as contract section 15 requires, but no M6 exit is recorded yet (the M6a exit record, M6a-U7, has not started). Whether the M7 exit is accepted ahead of the M6 exit is the user's call. The M6a headed spec at `d628caa` had 2 M6a-owned failures (M6a-A11, M6a-A12), which the M6a exit has to settle.
- **Deferred scope** (contract section 1, out of scope): nested instances (an instance inside a source); variants and general property overrides; swapping an instance's source; "go to source" navigation; turning a source back into a frame; a command that moves nodes to another page; symbol libraries shared between documents; instance opacity other than 1 (M7-S4); property-panel symbol controls (M8). Text override and text in sources, deferred there until text existed (section 8), landed in M7-U7.

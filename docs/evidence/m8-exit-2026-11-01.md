## Disclosures

- **M8-T2 amendment** (2026-11-01, M8-U3): `ui` re-exports `react` through explicit named value and type-only lists (16 values, 147 types), not `export *`: Next.js's flight loader rejects `export *` in a `'use client'` module imported by a Server Component, which M8-H5 requires. A02 keeps the lists equal to `react`'s exports and A06 fails on any `export *`. `react` likewise re-exports editor-core's 142 type exports as an explicit type-only list, since `export type *` would also expose editor-core's values as type names (M8-U2 notes).
- **Two public names the contract does not list** (M8-U1): `ExtensionSummary` and `ExtensionCommandBuilder<Args>`; both reach `react` and `ui` and are in the A02 fixtures.
- **M8-H1 and M8-A04 semantics** (M8-U2): `useHistory` returns a value equal to `snapshot.history`, kept while the undo and redo depths are equal, not always the same object. A selector now runs once per snapshot object, so an impure selector that reads `editor.query` goes stale on events that keep the snapshot (such as `textLayout`); the TSDoc says selectors must be pure and points to `useEditorQuery`. A store whose shared memo another store wrote re-runs its selector, which can cost one extra synchronous render in a concurrent render, never a wrong value or a loop (review r2). `extensionCommand` comes through the `'use client'` entry, so Server Component code imports it from `editor-core`.
- **Panel error order** (M8-U3): `resolvePanels` gives a rejected panel one error, the first of `ui.unknown-extension`, `ui.unowned-panel`, `ui.duplicate-panel`; `onPanelError` gets each error once by code and panel, rejections first. Effects, a real error-boundary catch, panel collapse, the refusal outputs and click wiring are browser-only and covered by A14.
- **UI choices inside the contract** (M8-U4, U5): a blank page or node name is invalid in the UI (`aria-invalid`, nothing sent) although editor-core accepts it; remove page is disabled on the last page; add page then activates the new page as a session command (one undo step). Layer rows are a plain list of buttons, not an ARIA tree, collapsed by default. Property fields parse locally only what cannot be a value and leave the rest to the editor's refusal, which shows only while its selection stays selected; the moved M4 panel keeps its M4 behavior (its `appearance-error` persists across selection changes).
- **M8-Q7 to M8-Q10, user-visible choices adopted as (a) on 2026-11-01** (contract status line, #438): Q7 reorder by forward, backward, front and back buttons, not drag and drop; Q8 transform fields in the stored parent-local frame (X and Y relative to the parent) with the rotation in degrees; Q9 text run fields disabled at a collapsed caret (no typing style); Q10 two fixed toolbar rows within the canvas row's width, the canvas origin kept.

## Known limits

- **No performance claim.** M9 owns every performance claim. Re-rendering `LayerTree` (whose `layerRows` walks the whole active page on each document change) and the property panel on a 10,000-node page is unmeasured; `?bench=1` excludes them (M8-N5).
- **E26 and E30 judge against the bench page** as it is now (M8-N5 disclosure); the E26 and M6c-U5 records stay valid for their own commits. E30 is paused by the user's decision of 2026-11-01 (#440).
- **One-node fields** (contract section 7): with several nodes selected, the fields of `setFrames`, `setNodeProps`, `setTextProps` and `setTextStyle` are read-only ("mixed" or the common value); several nodes cannot be renamed, transformed, constrained or restyled as text at once until a multi-node command exists.
- **No DOM unit tests** (M8-Q5 (a)): event wiring, the error boundary's real catch and panel collapse are checked only by the headed specs.
- **One editor per page** for the text run fields (`data-text-edit-focus`, M6b-H2 amendment above).

Unversioned aliases are backlog. A later milestone that adds a `model` type to the API must re-export it; A01 and A02 fail until it does.

## What changed

- `cubic_fill.rs`, X-K1:
  - Two tiers, `FillTier::Small` and `FillTier::Large`. The small tier is the `r4` limits, unchanged. The large tier (`LARGE_CAPS`, `LargeTierLimits`) has EX = 1,024 edge owners (`MAX_LARGE_EDGE_OWNERS`), EX + 8 flat commands and EX + 4 contour points; the source caps (4 contours, 64 segments) are B1's.
  - The workspace reserves storage for the large tier once (`new_two_tier`), and `activate_tier` sets the active limits per attempt on the rounded arrangement, the three topology workspaces and the fill scratch (`set_limits`).
  - The tier is chosen in `attempt_body`: the prefix runs at the small caps first. When the workspace has a large tier, the caller allows it, and the small prefix stops with `CommandLimit`, `PointLimit` or `OwnerLimit`, the prefix runs again at the large caps and the attempt continues in the large tier. `ExactOutcome` and `BuiltPath` carry the tier.
- `simple_cubic_topology.rs`:
  - `ABSOLUTE_MAX_LEAVES` = 1,024, `LEAF_WORDS` = 16, `MAX_CROSSINGS` = 256 (the small tier keeps 32). `TopologyLimits::LARGE` has 1,024 leaves, 523,776 pairs and 8 MiB.
  - The leaf points, pair rows, order, boxes, partners and crossings moved from inline arrays to heap buffers reserved once (stack inventory below). Rows and prefixes are cleared only up to the used length.
  - The crossing-triangle scan has its own counter, `crossing_scan`, charged c² before each `closes_crossing_triangle` (X-K3). In the large tier it is capped at `MAX_CROSSING_SCAN` = 2^24 and stops with the new `TopologyError::ScanLimit`; in the small tier it runs uncapped and is not read.
- `rounded_line_fill.rs`: `set_limits` swaps the active limits within the reserved storage.
- `fill_export.rs`:
  - `FILL_V0_REVISION` = 5. `FILL_V0_LARGE_LIMITS` derives from EX as `FILL_V0_LIMITS` derives from E, with `max_sections` fixed at 131,584 (X-K2), `max_work` = 2^26 (X-K3, measured below) and 32 MiB.
  - `exact_rung` allows the large tier only for the cascade at e. A large request gets no E16-K2 retries. `map_attempt_error` maps `ScanLimit` to `work-limit`.
  - `FillScratch` reserves for the large tier and checks against the active tier (`set_exact_tier`), so a small path's overflow stays a self-check failure.
- Identity: `geometry-wasm/fill-v0+r5` in `fill-adapter.ts`, its tests, the analysis harnesses and the five GPU specs. The three configuration hashes are pinned anew, as the P3 plan's AL-S1/AL-S2/AL-OB5 note records.
- Size pins: the bridge workspace's heap grows from 4,514,304 to 4,662,016 B and its inline size drops from 16,928 to 2,824 B; the rounded topology workspace is 942,592 B and the transverse workspace 945,408 B (inline 440 B, was 7,120). These apply in the native tests and in the native mixed, triangle-free and depth-positive verifiers.
- Diagnostics: `e14_fill_limit_diag` also runs each request through a two-tier engine and prints `engine`, `tier`, `engineError`, `work` and `engineUs`. `pnpm e16:fill-diag` writes `transitions.tsv` (each stratum's rows by their `r4` and `r5` class) and prints the large tier's largest charged work.
- `tooling/compare-p3-fill-identity.mjs`: `--large-tier` (combined mode only) allows `work-limit` → `unsupported-geometry` on cascade and WASM records, which X-Q4 (a) admits. The self-test covers it. The records carry the path status, not the tier or kernel error, so the rule cannot check that the path is large or that the error is in X-Q4's set; the run lists every allowed change, and X-G1 below had none. `Topology(ScanLimit)` is added to the tool's path-failure codes.

### Departures from the contract

- **X-F1 and X-F7 stop at the event cap.** At exactly E (or EX) flat edges the rounded arrangement's endpoint events fill `max_events` = 2E (or 2EX), so a self-crossing path at the cap has no room for a crossing event and stops at `Rounded(EventLimit)`, as E16-F3 (a) found on `r4`. The contract allows a listed stop for X-F7 at EX; X-F1 is identical to `r4`. X-A6 therefore checks X-F7 through the WASM as `work-limit`, and meshes X-F1b, X-F2, X-F3 and X-F5 instead.
- **X-F7b stops at `OwnerLimit`, not `CommandLimit`.** EX + 1 edges fit the large tier's EX + 8 flat commands, so the owner cap stops it first. It is still `work-limit` in the cap-stop class.
- **`MAX_EDGE_OWNERS` stays E.** The contract's item 1 makes it EX; the implementation keeps it at E for the small tier and adds `MAX_LARGE_EDGE_OWNERS` = EX, which every large-tier array is sized from. The effect is the same, and the small-tier constant keeps its readers unchanged.
- **How the tier is chosen.** The contract runs the prefix at the large command capacity and calls the request small when it has at most E edges. The implementation runs the small prefix first and switches only when it stops at a prefix cap (`CommandLimit`, `PointLimit`, `OwnerLimit`). For a small path the first run is exactly `r4`'s, so identity holds without a second prefix run; a large path pays one extra prefix run.
- **Identity entry rule.** Entries run the small-only workspace, so AL-I1 holds strictly and the entry set-aside was not needed.

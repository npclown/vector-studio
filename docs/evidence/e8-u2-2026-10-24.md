## E8-P1, discharged

**Setting.** A source cubic has represented controls P0..P3 (binary64), o = P0. The flattener subdivides the relative cubic with controls r_i = fl(P_i − o) and emits each leaf endpoint as fl(o + c), where c is the leaf's computed relative end control. A right child keeps its parent's last control, so the final leaf has c = r_3 and its emitted endpoint is q′ = fl(o + fl(p3 − o)), with p3 = P3. Let T be the exact sub-curve of the represented source on the final leaf's dyadic interval; T(1) = p3 exactly. The flattener accepted the leaf because `flatness + guard ≤ 2^e`, with the guard of the [P2 private contract](../plans/p2-private-contract.md#cubic-bounds-and-flattening): 128ε(max(1, A) + (depth + 1)R), where A is the largest absolute original control coordinate, R the largest absolute relative one, and the guard budgets the rounding in splits, chord evaluation, norm computation and the one-time origin subtraction and output addition.

**Claim 1 (the tolerance relation holds with the snapped chord).** For a chord from s to e parametrized linearly, write L_T for the chord from T(0) to T(1). For every t in [0, 1]:

|T(t) − ((1 − t)s + te)| ≤ |T(t) − L_T(t)| + (1 − t)|T(0) − s| + t|T(1) − e|.

The first term is the continuous flatness that the Bernstein controls 0, q1, q2, 0 bound. The other two are the endpoint errors of the emitted chord. The snap replaces e = q′ with e = p3 = T(1), so the last term becomes 0, and the right-hand side is at most its value for the unsnapped chord, for every t. The guard is the declared allowance for the unsnapped chord's rounding, including its endpoint errors. A pointwise smaller bound therefore stays inside the same accepted inequality, and the snapped chord keeps the tolerance relation of [V2 section d](../plans/p3-v2-fill-mesh-transport-contract.md#d-tolerance). The same argument covers the first chord of the next source: its start moves from q′ to p3, which is that source's represented P0, so its start error also becomes 0. A closing edge is a straight segment between represented points and has no flattening error. If the snap makes the last point equal the contour's first point, collection drops the duplicate, so no chord is added.

**Claim 2 (the size of the move, checked by E8-K11).** Per coordinate, with u = 2^−53, |q′ − p3| ≤ u|p3 − o| + u|q′|. Since |p3 − o| ≤ R/(1 − u) and |q′| ≤ A + |q′ − p3|, it follows that |q′ − p3| ≤ u(A + R)/(1 − u)². The Euclidean move is at most √2·u(A + R)(1 + 3u) < ε(A + R) ≤ guard/128, because the guard at any depth is at least 128ε(A + R). This tightens the E8.4 sketch (at least 64 times) to 128 times.

**Test (E8-K11).** `e8_final_knot_tests::e8_k11_snapped_final_knot_moves_less_than_the_guard_at_the_largest_admitted_magnitudes` flattens 2,564 single-cubic paths with non-dyadic coordinates at scales 2^0 to 2^1023 and tolerance exponents up to 1023, plus four paths with A = 0.2·f64::MAX and |p3 − o| = 0.4·f64::MAX at tolerance 2^1023. For every final leaf it checks the per-coordinate bound u(A + R)(1 + 8u), the exactness of q′ − p3 (Sterbenz), and |q′ − p3| ≤ guard/128. Result: 2,011 final leaves, 1,107 of them inexact (57 at A ≥ 2^1020), maximum depth 6, worst |q′ − p3|/guard 2.48·10^−3 (about 1/404).

**Bounds note.** `flat_bounds` stays the emission pass's bounds. They are a diagnostic, they are expanded by the guard, and the snapped point lies within the guard of the emitted one.

## Alt-A1 frozen oracles (not foreseen by the addendum; user decision requested 2026-10-24)

The first full geometry run found that E8-U2 changes the exact rung on the B0 corpus, which E8.10 did not list. On 757 of the 1,270 B0 paths, all in the O1 (closure) cells, the exact rung changes from a recorded failure to OK: 741 from `Topology(KnotMismatch)` (M2) and 16 from `OwnerLimit`. The 16 `OwnerLimit` paths, among them `b0/O1/P4/s=16#0`, are in the O1/P4/s=16 cell. The likely cause, not traced path by path, is that the snapped last knot equals the first point, so the closing duplicate and its closing owner are dropped and the owner cap is no longer exceeded. No recorded OK outcome changes, and the fast rung, which publishes these paths in production, is unchanged. Three frozen oracles read the exact rung on every path and fail as a result:

- **SL-O4** (exact rung equals the 2026-10-17 B0 record): 757 mismatches, all failure-to-success.
- **SL-O3** (on paths that both rungs admit, the exact polygon equals the fast rung's S1 view): 22 mismatches on the AL-S1 subset and 120 on the AL-U2 entries. The newly admitted exact rung has snapped final knots, and the S1 view does not. The area band still holds on every path.
- **SL-A7 S1 accessor**: a published exact attempt is compared with the frozen spike accessor, which matches the unsnapped prefix.

**Decision, 2026-10-24:** the user chose to amend the oracles to allow failure-to-success (the recommended option). Applied, all in test code:

- SL-O4 (`p3-b0-spike/analysis.ts`, `p3-fill-ladder/analysis.ts`): a recorded failure may become OK (`e8U2FailureToSuccess`). A recorded OK, and a failure that stays a failure, must still match. The decision-cell checksums are unchanged.
- SL-O3 (`verifyAgreement` in `p3-b0-spike/oracle.ts`): the polygon matches if it equals the S1 view, or the S1 view after `snapViewFinalKnots`. That function is a TypeScript mirror of E8.4 written from the contract text, with a unit test that includes the closing-duplicate case.
- The S1 accessor check (`p3_b0_spike_bench::accessor_matches`): a published attempt that equals the production exact prefix passes only if the spike accessor equals the production fast prefix.
- Re-baselined values: published exact attempts 453 → 1,210 (`p3-b0-spike-analysis.test.ts`), and `b0/O1/P4/s=16#0` exact `OwnerLimit` → `OK` (`p3-fill-ladder-oracle.test.ts`).

**Cause of the 876 FAIL.** All are F6-sliver attempt records that stay `ok` but change digest. Their cubic sources end at a −0 coordinate; the flattener emits fl(o + fl(p3 − o)) = +0, which equals p3 in value, so the certificate was already valid, but the snap wrote the −0 bits back. The fix skips the snap when the emitted point equals p3 in value (`e8_final_knot_tests::an_endpoint_equal_in_value_keeps_its_emitted_bits`, which fails without the fix); the TS mirror `snapViewFinalKnots` compares by value the same way.

**Independent review (2026-10-24).** No defect in the snap itself. Four oracle and edge findings, addressed in the PR:

- The zero-length skip now compares with the previous command's point as emitted, before any snap, as E8.4 states. A residual case remains: when the previous cubic's final knot is snapped, a following leaf that was zero-length against the emitted point is no longer zero-length against the snapped one. The outcome is either a certified path (valid geometry, failure-to-success) or the earlier failure; it never reaches `Mapped::Internal`. No such path is in the corpora.
- The S1 accessor check for a published exact attempt now also requires that the exact prefix's commands equal the fast prefix's commands as emitted, except at cubic source-final knots, which must equal the source's p3 bit for bit.
- The SL-O4 exemption is limited to recorded `Topology(KnotMismatch)` and `OwnerLimit` statuses turning `OK`.
- The TS mirror's closure rule compares points by value, as the kernel's `same_point` does.

**O5 (inline test module).** The identity tool's O5 check flags `native_cubic_fill_tests.rs`, whose control is rewritten in place (above); this is the accepted inline-module case. `e8_final_knot_tests.rs` is a new file and is not passed to `--allow-test-change`.

## Implementation and integration seam

`PrimitiveSceneSource` implements `PrimitiveFrameSource` over an injected `RetainedSceneMirror`. Accepted replacing snapshots renew the private scene epoch; incremental changes, replay and camera changes retain it. The editor-facing scene contract is unchanged.

The source reuses cached world transforms and stroke-aware bounds, traverses authoritative order iteratively, excludes hidden/degenerate primitives and culls conservatively with the two-physical-pixel guard. Stable logical slots include hidden primitives, preserve holes, reuse the lowest hole and grow power-of-two capacity without automatic shrink. Native allocation lifetime remains the existing backend's responsibility.

Transform, geometry and style values have independent dirty identity tokens. Writes coalesce only adjacent dirty records; order is separate. Every ready `prepare` provides a fresh frame envelope, including zero-write continuous frames and the empty draw list needed to clear a removed last primitive. Uninitialized/disposed sources return null. This introduces no scheduler or extra public flag.

Only one pending packet is retained because the consumer is synchronous. Receipt identity and complete, duplicate-free record coverage are checked before acknowledgment; later edits remain dirty. Generation/epoch/backing changes reconstruct all occupied records. Failed preparation retains accepted CPU truth and retryable work. Source disposal releases its five typed views and caches, leaving the injected mirror's lifecycle to its owner.

P1.4 supplies current surface/generation metadata, consumes bytes synchronously, returns submitted receipts, and connects the existing backend invalidation/lifecycle/accounting owner. The source does not create GPU resources or assign native completion serials.

## Precision model and its limits

The first worker draft incorrectly treated arbitrary-point f32 rounding error as affine. Primary replaced it with a fixed-vertex model in `primitive-packing.ts`:

1. Construct the actual four ordered-f32 quad endpoints from stored geometry, half stroke and inverse-linear guard. Reject nonfinite/collapsed arithmetic and f32-singular transforms without changing CPU scene acceptance.
2. Evaluate the frozen shader's scalar transform, camera-relative offset, separate zoom/DPR and NDC/viewport round trip at those fixed vertices. Stored-value and subsequent arithmetic errors are separate fields.
3. Once the vertex outputs are fixed, their error interpolants are affine over each of the two triangles. Clip those triangles against the guarded physical viewport and bound the absolute error at every resulting polygon vertex. Each convex polygon encloses its continuous contour intervals, including partly visible large shapes. This is not a claim that fround of arbitrary points is affine.
4. Charge geometry/stroke/radius storage displacement separately and include a Float64 bookkeeping roundoff envelope. Guard rounding reparameterizes the shared local-position/clip-position quad; guard construction is evaluated explicitly. Native compiler/interpolation behavior still requires P1.5 evidence.

The full N02 input product includes both large-origin signs, 16x8/16x16/4096x4096 sizes, null/width-4 strokes, seven affine variants, three zooms, three DPRs and two camera placements. Each potentially visible variant checks the separate 0.125px budgets and independent scalar f32 samples. The 0.25px total, visual thresholds and corpus are unchanged. No hardware precision or performance claim follows from this CPU model.

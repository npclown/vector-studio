## Known limits and disclosed findings

- **First frame of 10,000 miter-joined rectangles** (M4-A13, headed): about 20 s (Chrome 20,272 ms, Edge 19,796 ms) against about 0.5 to 0.7 s for `round` primitives, while re-presented frames are 300 to 331 ms for `miter` and 252 to 261 ms for `round`. The likely cause is the WebGPU renderer's path-mesh build for 10,000 outline paths (contract section 11, "Path projection cost"); it is not profiled here. Since M4-Q4 (a) keeps `round` as the default join, a new stroked rectangle stays a primitive; only an explicit `miter` or `bevel` join or a dash takes the path. Follow-up below. No claim.
- **Section 3 disclosures:** a composed gradient transform that overflows (a frame near `1e160`) or underflows (a `1e-170` box) the determinant is rejected as `invalid-value` and isolated (`editor.scene-rejected`, M4-P1); a rounded rectangle with every radius above 0 still becomes a path under a `miter` or `bevel` join, and the four-cubic ellipse deviates by about 0.027 % of the radius (M4-P3); at exactly 4,096 or 4,097 dashes the editor's and the renderer's counts can disagree under rounding (M4-P5).
- **Section 5 disclosures:** each instance below opacity 1 is one offscreen layer, so many translucent full-screen instances can exceed E25's 96 MiB layer budget and report `render.layer-resource-limit`; under M4-Q15 (a) a translucent source makes every instance a layer.
- **Section 11 risks, as they stand at exit:** path meshes carry P3's disclosed defects (A01 cracks, A04) and the fringe cap (region-only with a notice, seen on H3 and H6); a dashed stroke over a region-only fill at `0 < opacity < 1` can take O3 and not draw (E27, E24 D6), not worked around; each translucent container or instance is a layer re-rendered every frame within 96 MiB, a layer edge at 4x blends per pixel with content under or over it, and a failed layer pipeline draws nothing of the isolated content with no diagnostic (E25 U3 departure); box-relative gradients stretch on a path edit or resize that changes the frame (M4-Q2 (a)).
- **API change** (section 11): old `{ color, width }` strokes are no longer command input (`document.invalid-field` at `/stroke/cap`); `serializeDocument` writes v6 documents only; `migrateV4toV5` returns `ParseResultV5`; `validateNode` takes an optional `{ olderInput }`; `setStyle` and `editor.isolation-depth` are new public surface.
- **Panel** (section 8): the linear angle is measured in the unit box, so on a non-square node the drawn ramp's direction differs from the angle, as in Figma; colours are entered as hex at 8 bits per channel with alpha separate.
- **Headed coverage** (M4-U4 note 5): no edge probe on H2, H3, H4, H6, H8 or H9; H6 never cuts a dash at the triangle base, so that branch is unit-tested only (M4-A07). Headed evidence is from the main PC only (Chrome and Edge 156), with pointer and key events sent by Playwright. The headless `chromium-smoke` project (SwiftShader, device lost after `ready`) is a spec check, not evidence.
- **A13 observation scope:** the main PC observation records medians only (no ranges, run count or Node version in the report); the container observation is the detailed one. Neither is a benchmark.
- **Deferred scope:** on-canvas gradient handles (M4-Q9 (a), backlog); a live preview during slider drags (M4-Q13 (a)); the panel moves to the UI package in M8; text has no node-level paint (M4-Q16 withdrawn, M6a's).
- The M4 exit does not establish MVP completion; M6, M8 and M9 remain, and the M7 exit is still awaiting acceptance.

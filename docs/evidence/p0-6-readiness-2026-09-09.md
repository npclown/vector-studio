## Decisions and preparation before acceptance

1. **Presentation measurement:** startup and recovery deliberately export `observedPresentation` as unavailable with reason `browser-webgpu-no-presentation-timestamp`. Submission counters, queue completion and screenshots prove different events. The [measurement policy](../benchmarks/README.md#measurement-semantics) prohibits substituting them for physical presentation. Keep the current criterion unless the user approves a prospective change; otherwise define a real observation method and its clock correlation, overhead, environment and reproducible acceptance procedure. A different measured endpoint requires an owning-plan decision and successor scenario identity before code/run changes.
2. **Native OOM:** [backend unit fixtures](../../tests/unit/webgpu-backend.test.ts) cover injected OOM mapping; [headed recovery tests](../../tests/gpu/webgpu-recovery.spec.ts) cover native validation errors and deliberate device destruction. Neither reproduces native OOM delivery. P0-A07 remains UNVERIFIED for that requirement under the [validation evidence limits](../validation.md#evidence-limits-and-gate-status). Do not add uncontrolled allocation pressure on the development machine. Define a bounded procedure on a suitable environment, or obtain approval for a prospective split/change of the owning acceptance criterion.
3. **Reference environment:** do not infer 60 Hz from RAF samples or older records. Establish the actual display used by the benchmark window, refresh rate, power mode, visible/unobscured state and relevant background load before capture. The current runner records power mode as unavailable and background load as not audited; its screen-recording flag describes runner configuration, not a host-wide inspection. Add a factual run-environment record or appropriate capture inputs without inventing missing metadata.
4. **Immutable output and provenance:** capture from a clean feature source using a fresh directory. Review each repetition and the raw samples, including failures, before accepting any baseline. Keep source/evidence commits distinct and preserve measured source if squash merge would otherwise make it unreachable. No historical record is edited by this checkpoint.
